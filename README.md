# 話者分離文字起こし Web UI

フォルダー構成とバックアップ対象は [フォルダー構成](docs/PROJECT_LAYOUT.md) を参照してください。起動は最上位の `run.bat`、初回セットアップは `setup_gui.bat` だけで行えます。

動画・音声を Whisper / WhisperX で文字起こしし、pyannote で話者分離する Windows / Google Colab 対応 Web UI です。Windows版のサーバーはこの PC の `127.0.0.1` だけで待ち受けます。Colab版はノートブック内の認証付きポート表示を使用します。

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/krokharu/gurumoji/blob/main/notebooks/Gurumoji_Colab.ipynb)

現在のバージョン: **1.8.0**

## 主な機能

- MP4 / MOV / MKV / WAV / MP3 / M4A / FLAC を文字起こし
- Windowsローカル実行とGoogle Colab GPU実行に対応
- Windows のファイル選択画面またはフルパス入力に対応し、選択したパスのファイルを直接処理
- 上部バーで「新規作成」「処理済みデータ」「話者管理」を切り替え。「処理済みデータ」内でデータ一覧と分析・可視化を切り替え。画面ごとにURL（`#/data` など）を持ち、再読み込み・戻る操作・ブックマークに対応
- 新規作成は「ファイル → 設定 → 開始」の3ステップ。詳細設定は閉じた状態で要約を表示し、「変更」を押した項目だけを開く。スマホでは1ステップずつ表示
- 処理前に選択した動画のサムネイルを表示
- 発話ごとの話者分離とタイムスタンプ
- TXT / JSON を常時出力し、SRT を任意で出力
- 動画では、話者名と話者別テーマカラーを付けた字幕焼き込み MP4 を任意で出力
- OpenAI / Google Gemini / LM Studio による任意の文字ノイズ除去・明白な誤変換修正
- TypeSafe Jevによる「修正が必要／修正不要」の独立判定と、現行AI結果との4区分比較・可視化
- LM Studio（Windows）またはOllama（Google Colab）のローカルLLMによる、外部API送信なしの文字ノイズ除去・話者特定・アウトライン作成
- 会話冒頭の明示的な自己紹介から、任意で話者名を抽出
- OpenAI / Google Gemini / LM Studio による任意の議題・アウトライン作成
- 文字起こし前の音声加工（ノイズ除去、音量調整、明瞭化、16kHz/mono 化）
- 小さい声を拾いやすくする高感度 VAD 設定
- 通常結果の長い空白だけを軽め/強めで再処理する詳細処理で、取りこぼし区間を補完
- 起動時にCPU・RAM・CUDA GPU・VRAMを診断し、推奨モデルと処理装置を自動設定
- デスクトップ表とスマホ専用カードを備えた話者管理、会話別の話者連携（司会、観察者、記録者、議長、役職、同意、条件）
- Google Forms回答CSVの話者管理への取込、スプレッドシート型編集、CSV書出し
- 話者ごとの発話回数・発話時間・文字数と、グループインタビュー運営上の確認表示
- データの作業画面（「発話の確認・編集」「会話・話者」「議事録・アウトライン」「ファイル・管理」）で話者名と全発話を手動編集し、出力ファイルを再保存
- 概要・固定フィルター・スマホ専用カードを備えた処理済みデータ管理と、SQLiteへの永続保存
- 処理済みデータの頻出語からワードクラウドを生成し、サムネイルと出力ファイルに使用
- データグループの作成・割り当て・名称変更・削除と、グループ、話者、感情、キーワードによる絞り込み・並べ替え
- 「分析・可視化」で、発話量、参加バランス、司会進行、話者遷移、無音・重なり候補、時間推移、頻出語、感情推定を可視化
- GiNZA / SudachiPyによる日本語の形態素解析（表層形・原形・正規形・読み・品詞）とUniversal Dependencies係り受け解析
- 発話単位のTF・DF、Jaccard係数による共起ネットワークをWeb上で可視化
- multilingual-e5-smallによる発話の意味クラスタリング、テーマ候補、代表発話、話者別分布、時間推移、例外候補、意味検索
- SPSS系の度数分布、記述統計、クロス集計、カイ二乗検定＋Cramér's V、ANOVA＋η²、Kruskal–Wallis＋ε²、Pearson／Spearman相関
- 研究質問、比較属性、判定しきい値、ストップワード、コードブックを設定し、発話ごとの複数コード、相互作用タグ、重要引用、分析メモを手動保存
- 発話・形態素・構文・語彙・共起・統計・既存分析を複数シートにまとめたExcelを標準出力とし、全分析JSONと個別CSVも出力
- 発話を選択して、該当箇所の前後3～15秒を元の音声・動画で再生
- 本文・話者・時刻・くしなだ感情ラベルの修正差分を、音声クリップ付き学習データとして蓄積
- API キーは画面へ入力せず、`config/tokens.json` からだけ読込

分析内容用の `runtime/data/obsidian/ResearchVault` と、プログラム資料用の `docs/program-vault` を独立したObsidian Vaultとして用意しています。「分析・可視化」の「分析結果をObsidianに保存」で、見解・根拠・分析表を登録できます。AI仕上げの校正前後・根拠付き議題と、AI見解は自動で履歴に残します。全件JSON／CSVは `runtime/data/analysis_store`、実行台帳はSQLiteで保持します。[2つのVaultの開き方](docs/OBSIDIAN_VAULTS.md)と[保存仕様・手法登録ルール](docs/program-vault/30-Data/analysis-storage-v1.md)を参照してください。研究メモ・解釈・コード案の差分取り込みは今後実装します。

Obsidian がインストール済みの場合は、`run.bat` と同じフォルダーに **「可視化用Obsidianを開く」** ショートカットが自動作成されます。クリックすると `runtime/data/obsidian/VisualizationVault` を開きます。

## 1. 事前準備

### Windows: GUI セットアップ（推奨）

別のPCやPython未導入のWindows環境では、フォルダー内の **`setup_gui.bat`** をダブルクリックしてください。組み込みのセットアップ画面で、次を順番に行えます。

1. Python 3.10〜3.13（64 bit）の有無を確認し、必要なら確認画面で承認後、公式の python.org から Python 3.13.15 を自動導入します。FFmpeg はアプリ環境内へ自動導入されます。
2. Hugging Face token、任意のOpenAI / Google / TypeSafe API key、LM Studio接続先を安全な伏せ字入力で `config/tokens.json` に保存します。秘密鍵はセットアップログに出力しません。
3. 「アプリ環境を作成」で、このフォルダー内の `.venv`、必要なPythonパッケージ、FFmpeg を作成します。
4. 「Gurumoji を起動」で通常のWeb UIを開きます。

Python をGUIから新規導入した直後だけは、PATHを読み直すためセットアップ画面を一度閉じて開き直してください。自動導入では、ダウンロードしたインストーラーのSHA-256とPython Software FoundationのWindows署名を確認します。Google ColabではこのGUIではなく、付属ノートブックを使用します。

### 手動セットアップ

1. 64 bit 版 Python 3.10～3.13 をインストールします（Python 3.12 推奨）。
2. Hugging Face で read token を作成し、次のモデルの利用条件へ同意します。
   - <https://huggingface.co/pyannote/speaker-diarization-community-1>
   - <https://huggingface.co/pyannote/speaker-diarization-3.1>
   - <https://huggingface.co/pyannote/segmentation-3.0>
4. `config/tokens.json` をテキストエディターで開き、少なくとも `huggingface_token` を設定します。

## 2. config/tokens.json

```json
{
  "huggingface_token": "hf_...",
  "openai_api_key": "sk-...",
  "google_api_key": "AIza...",
  "openai_model": "gpt-5.6-luna",
  "google_model": "gemini-3.5-flash",
  "typesafe_api_key": "your_typesafe_api_key",
  "typesafe_model": "jev-latest",
  "lmstudio_base_url": "http://127.0.0.1:1234/v1",
  "lmstudio_model": "",
  "lmstudio_api_key": ""
}
```

- `huggingface_token` は話者分離に必須です。
- `openai_api_key` は OpenAI の AI 仕上げを使う場合だけ必要です。
- `google_api_key` は Google Gemini の AI 仕上げを使う場合だけ必要です。
- `typesafe_api_key` は、Jevで各発話を「修正が必要／修正不要」の二択判定にかけ、現行AIの結果と比較する場合だけ必要です。`typesafe_model` の既定値は `jev-latest` です。Jevには音声・動画ではなく文字起こしテキストだけを送信します。
- `lmstudio_base_url` はループバック上のOpenAI互換ローカルLLMサーバーです。WindowsではLM Studio、ColabノートブックではOllamaを使用します。省略時は `http://127.0.0.1:1234/v1` です。
- `lmstudio_model` は画面上部のローカルLLM接続ライトをクリックして選択すると保存されます。`lmstudio_api_key` は、ローカルサーバー側でAPI認証を有効にした場合だけ設定します。キー名は従来版との互換性のため維持しています。
- モデル ID は必要に応じて同じファイル内で変更できます。
- `config/tokens.json` は Git の除外対象です。第三者へ渡したり、画面共有へ映したりしないでください。
- ファイルを編集した後、Web UI の再起動は不要です。文字起こし開始時に読み直します。

### LM Studio の接続方法（ローカルLLM）

1. LM Studio で指示追従モデルを読み込みます。JSON Schema 出力に対応する、7B以上の Instruct 系モデルを推奨します。
2. LM Studio の **Developer** 画面で **Start server** をオンにします。既定の接続先は `http://127.0.0.1:1234/v1` です。
3. Gurumoji を開き、右上の **LM Studio** ライトが緑になることを確認します。ライトをクリックして、`/v1/models` から取得したモデルを選びます。
4. 接続済みでモデルを選択済みの場合、新規文字起こしでは **LM Studio（このPCのローカルLLM）** とAI仕上げの3項目（校正・話者特定・アウトライン）が最初から有効になります。不要な項目だけ外して開始します。

ライトが赤い場合は、LM Studioのサーバー起動・ポート番号・モデル読込を確認してください。ポートを変更した場合は `tokens.json` の `lmstudio_base_url` を `http://127.0.0.1:ポート番号/v1` に合わせます。このアプリは安全のため `127.0.0.1` または `::1` だけを許可し、LANアドレスや外部URLには接続しません。

## 3. 起動

`run.bat` をダブルクリックします。起動時にGitの追跡先リモート（未設定なら `origin` の同名ブランチ）を確認し、現在のブランチに新しいコミットがあればfast-forwardで更新します。更新後の起動処理でそのまま起動します。ローカル変更やブランチの分岐がある場合はファイル保護のためソース更新をスキップし、ネットワークへ接続できない場合もインストール済みの版で起動します。また、既存の仮想環境では `requirements.txt` の範囲内でPythonライブラリの更新を確認します。環境の作成は `setup_gui.bat` の「アプリ環境を作成」で先に済ませておくことを推奨します。`.venv` が未作成の場合は `run.bat` も同じ処理で必要なパッケージと CUDA 対応 PyTorch をセットアップするため、初回は時間がかかります。

起動時の更新・セットアップ・アプリの出力とエラー詳細は、画面と `runtime/logs` フォルダー内の `startup-日時-プロセスID.log` に記録します。`runtime/logs` フォルダーは起動時に自動作成されます。起動に失敗した場合はウィンドウを閉じずに停止するので、表示されたエラーとログを確認してください。

起動時の先頭に、大きなアスキーアートと色付きの枠で `GURUMOJI` と `MADE BY KUROKAWA` を0.6秒間表示してから起動処理へ進みます。更新確認後に起動する版のバージョンと最終更新日時を表示します。最終更新日時は現在のGitコミット日時（PCのローカル時刻）で、Git情報を取得できない場合は `app.py` のファイル更新日時です。

開発・オフライン確認などで更新処理を省略する場合は、起動前に `MOJIOKOSI_SKIP_UPDATE_CHECK=1`（Git）または `MOJIOKOSI_SKIP_LIBRARY_UPDATE=1`（ライブラリ）を設定できます。

セットアップ後、ブラウザーで次が自動的に開きます。

```text
http://127.0.0.1:7860
```

自動で開かない場合は、この URL をブラウザーへ貼り付けてください。終了するには `run.bat` の黒いウィンドウで `Ctrl+C` を押します。

## 4. 使い方

1. 上部バーの「＋ 新規作成」を開き、「ファイルを選択」で動画または音声を選びます。ドラッグ＆ドロップもできます。フルパスを使う場合は「パスと保存先を指定」を開いて貼り付けます。動画の場合はサムネイルが表示されます。
2. 「設定を確認する」で録音の種類（会議／グループインタビュー／雑談）を選びます。話者数と音声前処理がまとめて調整されます。
3. 「現在の設定」の要約を確認し、変えたい項目の「変更」を押します。押した項目の設定だけが開きます。認識モデル、言語、音声前処理、CPU / GPU、話者数、無音判定は「認識・話者分離」にあります。人数が分かっている場合は「話者数を固定する」を押して指定します。
4. 小さい声が抜ける場合は「認識・話者分離」の「小さい声を拾いやすくする」を有効にします。既定で有効です。通常結果の長い空白だけを軽め/強めで再処理し、取りこぼしを追加したい場合は「詳細処理」を有効にします。AI仕上げを使わない設定でも実行できます。
5. AI仕上げが必要なら「AI仕上げ」の「変更」を開き、OpenAI / Google / LM Studio を選びます。プロバイダー選択時は3つの処理がすべて選択され、不要な処理だけ外せます。
   「Obsidianに保存して仕上げ（標準）」は既定で有効です。Whisper原文と録音1件の全文を研究Vaultに保存し、データの作業画面の「Obsidianで仕上げ」から操作ノートを開けます。標準のプロパティ・内部リンク・発話のブロック参照を使い、会話・全体アウトラインを編集して、チェック欄でアウトライン作成 → AI仕上げ → 結果の反映と進めます。[操作手順と保存形式](docs/OBSIDIAN_FINISHING.md)を参照してください。全文・分析・操作をインタビュー単位にまとめ、ブックマークから[研究全体とインタビュー別のグラフ](docs/OBSIDIAN_GRAPH.md)を切り替えられます。
6. 動画へ字幕を直接入れたい場合は、「出力形式」の「字幕付き動画」を有効にします。
7. 「内容を確認して開始する」で設定を確認し、「文字起こしを開始」を押します。処理中は同じ画面に進捗が表示されます。ほかの画面へ移っても、上部バーの表示で状況を確認できます。
8. 完了すると、そのデータの作業画面が開きます。発話の再生ボタンで前後の音声・動画を確認し、時刻、本文、感情を編集して「編集内容を保存」を押します。話者名、テーマカラー、会話プロファイルは「会話・話者」タブで編集します。
9. 「処理済みデータ」では、過去の結果を話者・感情・キーワードで絞り込み、カードを押して作業画面を開きます。
10. 作業画面の「ファイル・管理」タブ、または `runtime/output` フォルダーから結果を取得します。
11. 論文用の分析では上部バーの「分析・可視化」を開き、対象データを選んで「Excel（標準出力）」をダウンロードします。作業画面の「分析・可視化 →」からも同じデータの分析へ進めます。個別の表は各パネルのCSVから取得できます。

AI仕上げの再校正は、原文から会話全体の参照用アウトラインを作成した後、その全体像と前後の発話を照合して行います。長い会話は前後の文脈を重ねて分割し、アウトラインが長い場合は全議題を対象に段階的に圧縮します。発話順・話者・時刻を保持し、意味・否定・迷い・話し方を変えずに明白な認識ミスだけを修正します。仮のアウトラインに合わせて発言を作り変える指示はしません。

雑音の誤認識が疑われる発話は自動削除せず、ノイズ候補として原文と判定理由を残します。作業画面の各発話にある「AI仕上げ」欄で理由・原文を確認し、前後を再生して編集・削除できます。修正した本文を校正前に戻すこともできます。話者特定は引き続き校正前の自己紹介を根拠に行い、「根拠付きのアウトラインを出力」が有効なら仕上げ後の会話から出力用アウトラインを再作成します。出力をオフにしても、再校正の参照用アウトラインは作成するためAI呼び出しが増えます。参照用アウトラインの作成に失敗した場合は再校正を省略し、原文を保存します。参照用アウトラインと修正・判定の履歴はAI仕上げの保存記録に残ります。

分析画面へ直接開く場合は `http://127.0.0.1:7860/#/analysis` を使用できます。従来の `?view=analysis` も引き続き使えます。

### 見解から会話の内容を読み解く

「分析・可視化」→「自動分析」→「会話全体」の冒頭に、保存済みの語彙・手動コード・重要引用から作成した「分析結果の見解」を最大5項目表示します。基本の見解と文脈検索はAPIキーなしで利用できます。

- **根拠の発話**：見解の「根拠の発話を確認」を開くと原文・話者・時刻を表示します。「音声で確認」で文字起こし画面へ進み、「見解・文脈検索に戻る」で検索条件と表示位置を復元します。
- **文脈検索（KWIC）**：自由入力は文字列検索、頻出語・特徴語のボタンは正規化語検索です。各出現箇所の前後40文字と前後の対象発話を確認でき、50件ずつ表示します。CSVは現在の検索条件に一致する全件を出力します。
- **話者別特徴語比較**：本文のある対象発話を分母に、本人の語の発話出現率と他の話者の出現率の差を表示します。同じ発話内で何度使っても1発話として数え、話者ごとに差の大きい上位10語を表示します。
- **任意のAI見解**：設定済みのAIを選び「AIで見解を作成」を押すと、研究質問（未入力なら会話目的）に沿って、総合見解・主要テーマ・共通意見・異なる意見や少数意見・追加確認点を根拠付きの下書きとして保存します。長い会話も対象全文を分割して処理します。進捗、トークン使用量、中止操作に対応します。

基礎分析の実行設定では、計画担当O01に分析目的を入力し、「計画候補を生成」を押せます。既定はローカルTransformerで、設定済みのLM Studioモデルや明示選択したクラウドLLMも選べます。候補は優先して確認する手法と確認事項を示し、開始時に実行記録へ含めます。基礎分析の実行手順は既存の2手法です。LLMへ送るのは分析目的、集計件数、手法カードであり、発話本文は送りません。

AI生成には保存済みデータを使います。本文・話者情報・分析条件・注釈の更新後は「更新が必要」と表示し、再生成は手動で行います。生成中の更新や失敗・中止では前回の成功結果を保持し、アプリ再起動後の中断処理も自動では再実行しません。AI見解が手動コードや研究者メモを上書きすることはありません。

### アウトライン（予定と結果）

処理済みデータを開くと、見出しのすぐ下に「アウトライン（予定と結果）」が出ます。折りたたみできます。

- **予定**: 「会話・話者」タブの調査設計で登録した質問ガイド・議題を、1行1項目として読みます。Transformerテーマ分析を「手動で定義する」で実行し、テーマ名が予定項目と一致している場合だけ、項目ごとに「話された（N発話・M人）」を表示します。一致していない項目は「未照合」とし、推測で消化済みにはしません。
- **結果**: 実際の内容を時間順に1本で並べます。見出しはAI仕上げが作った議題を使い、議題がない時間帯はTransformerのテーマ名で埋めます。各行には「AI議題」「テーマ」の別と、その区間に含まれるテーマ候補と発話数を付けます。
- **予定がない場合**: 予定が未登録であることを明示し、結果と自動アウトラインだけを表示します。
- テーマは保存済みの実行結果です。実行後に本文・話者・除外を変えた場合は「実行時点の結果です」と表示します。自動では再実行しません。

議題の要点（箇条書き本文）は従来どおり「議事録・アウトライン」タブにあります。

### Transformerでグループインタビューを分析する

「分析・可視化」→「自動分析」→「会話全体」の「Transformerテーマ分析」で、文字起こし本文をローカルの `intfloat/multilingual-e5-small` により384次元の意味ベクトルへ変換します。「テーマ分析を実行」を押したときだけ処理し、OpenAIやGoogle等の外部AI APIへ会話本文を送信しません。初回実行時はHugging Faceからモデル（約500MB）を取得し、以降はローカルキャッシュを使います。既定はCPU実行です。明示的にGPUを使う場合は起動前に `MOJIOKOSI_TRANSFORMER_DEVICE=cuda`、自動選択は `auto` を設定できます。

- **前処理と相づち**: 句読点だけの発話と認識時に生じた反復フィラーを除外します。「はい」「そうですね」「なるほど」などの相づちは捨てずにテーマ本文とは別集計し、直前の別話者の有意味発話を優先して対象テーマ・応答先発話・時間差を保持します。短い有意味発話は、3秒以内に続く同一話者の前後発話を埋め込み時だけ補い、保存本文は変更しません。
- **テーマの決め方**: 「自動でまとめる」「候補から選ぶ」「手動で定義する」から選べます。
    - **自動**: コサイン類似度に基づく文脈付き発話埋め込みをK-meansでクラスタリングし、silhouette係数が最も高いテーマ数を選びます。テーマ名は汎用フィラーと会話全体で頻出しすぎる語を除いた特徴語による仮ラベルです。
    - **候補から選ぶ**: テーマ数2〜12件ごとのsilhouetteを一覧で示し、研究者が選んだ件数で作り直します。本文が変わっていなければ保存済みの意味ベクトルを再利用するため、モデルの再実行は不要です。
    - **手動で定義する**: 研究者がテーマの見出しと、手がかり語またはシード発話IDを定義し（「設定とコードを保存」で保存）、意味が最も近いテーマへ各発話を割り当てます。しきい値を設けると、どのテーマにも近くない発話を未割当にできます。上位2テーマの差が小さい境界例の件数も表示します。テーマの妥当性を確かめた結果ではないため、未割当と境界例は原文で確認してください。
- **代表発話と話者比較**: 発話量の多い一人に結果が偏らないよう話者別の重みを補正します。各テーマでは短い断片を避け、可能な範囲で異なる話者から最大3発話を根拠として表示します。話者別に加え、参加者と進行役候補の発話数も分けて集計します。
- **時間推移**: 各発話の開始時刻に基づき、テーマ候補の出現を時間帯別に集計します。
- **例外候補**: 他の発話との最大類似度が低い発話を確認候補として表示します。少数意見や重要発話であるとは自動判定しません。
- **意味検索**: 単語の完全一致ではなく、検索文と意味が近い有意味発話をコサイン類似度順に表示します。旧形式の保存結果でも句読点・相づちだけの発話は検索結果から除外します。
- **相づち集計**: 相づちの種類、発話者、対象テーマ、応答先の話者・発話IDを明細で保存し、話者×テーマ別の件数・話者内割合と時間帯別件数をCSV・Excelへ出力します。時系列上の推定であり、相づちを賛成とは断定しません。
- **相づちの統計分析**: 話者別・話題別に、他者の有意味発話数を反応機会の代理分母として、応答した対象発話数、応答率、100機会あたりの相づち数、種類別件数を算出します。話者×応答有無、話者×相づち種類、話題×相づち種類のPearsonカイ二乗検定とCramér's Vを探索的に出力し、期待度数5未満のセルが多い場合は警告します。同一話者の反復は独立観測とは限らず、参加時間も完全には測れないため、p値だけで結論を出さないでください。
- **話者別の会議リザルト**: 話者ごとに「意見・認識が変わった」「意見・認識が変わらなかった」「新しい見解・気づきを得た」「支持・選好が明確になった」を、対象テーマと根拠発話付きで表示し、CSV・Excelへ出力します。本人の明示表現がない話者も省略せず「未判定」とします。会議前調査との比較や、Transformer類似度だけからの心理推定は行いません。

結果はSQLiteへ保存され、本文・話者・除外設定が変わると「更新が必要」になります。テーマ・発話分類・話者比較・時間推移・例外候補はCSVおよびExcelへ出力できます。モデル名、取得revision、実行装置、埋め込み次元、クラスタリング条件、テーマの決め方と手動テーマの定義もJSONに記録し、画面にも表示します。Transformerの類似度だけでは、賛否、合意、因果関係、重要性を判定できません。テーマ名と例外候補は必ず原文・音声・研究質問と照合してください。

ExcelはREADMEの直後に「分析の見解」と「話者別特徴語比較」を出力し、JSONにも見解・根拠・生成情報を含めます。語の頻度や出現率の差だけでは、意見の一致や重要性は判断できません。原文と合わせて確認してください。

AI 仕上げやアウトライン作成を有効にした場合、文字起こしテキストだけが選択した処理先へ送られます。音声・動画そのものは送信しません。LM Studio を選んだ場合は、テキストもこのPCのループバック通信だけで処理され、外部へ送信されません。OpenAI へのリクエストでは `store: false` を指定しています。機密情報を含む会議では、組織の規程と各APIのデータ利用条件も確認してください。

## 音声前処理

文字起こしの前に、FFmpeg で一時的な 16kHz / mono / WAV を作成します。前処理は音声認識だけに使います。ノイズ除去や音量正規化で声質や音量の起伏を変えると、話者の区別や感情推定の手がかりが失われるためです。話者分離には、元音声のうち小さすぎる声だけを最大4倍（+12 dB）まで持ち上げた音声を使います。普通以上の大きさの声と背景の静かな部分はそのままです（前処理を「加工なし」にした場合は元音声をそのまま使います）。音声感情分析には元音声をそのまま使います。前処理は時刻を変えないため、どの工程の結果も同じ時刻で対応します。前処理済み WAV は処理後に削除します。元メディアは発話確認用としてローカルの `runtime/data/media` に保存します。

| モード | 内容 | 使いどころ |
| --- | --- | --- |
| 加工なし | 元ファイルをそのまま使用 | 既に音声がきれいな録音 |
| 軽め | 低域カット、音量正規化 | 声は明瞭だが音量が小さい録音 |
| おすすめ | 低域カット、軽い定常ノイズ除去、音量正規化、弱い声の持ち上げ | 既定。会議、面談、講義 |
| 強め | 強めのノイズ除去と明瞭化 | 空調音、環境音、距離がある録音 |

日本語では短い母音や子音が抜けると誤変換が増えるため、前処理では高域を強く削りすぎない設定にしています。強めで声が不自然になる場合は「おすすめ」または「軽め」に戻してください。

## 小さい声が抜ける場合

既定では「小さい声を拾いやすくする」が有効です。WhisperX の VAD onset / offset を低めにして、弱い声が無音として捨てられにくくします。

- `VAD onset`: 声として扱い始めるしきい値です。小さいほど拾いやすくなります。
- `VAD offset`: 声が終わったと判断するしきい値です。小さいほど短い声や語尾が残りやすくなります。
- 雑音や空調音まで文字起こしされる場合はチェックを外すか、値を少し上げてください。

### 詳細処理

詳細処理を有効にすると、複数回処理やエフェクトを加えて精度を上げるため、次の3パスを順番に実行します。処理時間が増える点に注意してください。

1. 通常モード: 画面で選んだ音声前処理 + 標準VADで文字起こし
2. 空白補完（軽め）: 通常結果に残った3秒以上の空白だけを元音声から切り出し、前後0.75秒の文脈を付けて軽めの音量正規化・帯域調整 + 高感度VADで再文字起こし
3. 空白補完（強め）: 2回目を統合しても残った3秒以上の空白だけを切り出し、強めのノイズ除去・明瞭化 + 高感度VADで再文字起こし

各補完後に空白を再計算するため、2回目で埋まった場所は3回目の対象になりません。統合時は通常モードを主結果として保持し、補完で見つかった区間のうち、既存結果と重なりが少なく品質条件を満たす発話だけを追加します。全編を毎回処理せず長い空白だけを再処理するため、処理時間の増加を抑えています。AI仕上げを別途有効にした場合だけ OpenAI / Google / LM Studio で文字ノイズと誤変換を整理します。

## 起動時のマシン診断

起動時に論理CPU数、総RAM、PyTorchからCUDAを利用できるか、GPU名、VRAM、CUDAバージョン、Compute Capabilityを確認します。GUIの「マシン診断」にはCPU利用可・GPU利用可の状態ランプを表示します。

診断結果から認識モデル、文字起こし装置、話者分離装置を自動設定します。GPUを利用できない場合はCUDAの選択肢を無効化してCPUへ切り替えます。設定は自動選択後も手動で変更できます。

## 話者管理と会話別の話者連携

上部の「話者管理」では、参加者コード、氏名、分析用の仮名、既定役割、組織、部署、役職、守秘同意、タグ、事前アンケート回答、備考を管理できます。デスクトップでは表、スマホでは話者カードで編集でき、登録した人物は複数の文字起こしで再利用できます。分析時に実名を表示したくない場合は仮名を設定してください。

Google Formsの「回答をダウンロード（.csv）」で取得したCSVは「CSVを読み込む」から取り込めます。`参加者コード`、`氏名`、`仮名`、`役割`、`組織`、`部署`、`役職`、`守秘同意`などの見出しを自動認識し、それ以外の質問列を事前アンケート回答として保持します。「CSVを書き出す」でGoogle Sheetsへ再取込できるUTF-8 CSVを作成します。

「事前アンケート分析」では、質問別の回答分布・回答率・未回答数・数値回答の平均／中央値／最小／最大、2項目クロス集計、数値項目間の相関、回答に該当する参加者を確認できます。話者を文字起こし内の音声話者とリンクすると、「分析・可視化」の比較軸に任意のアンケート質問を選び、回答群ごとの発話時間・発話回数・参加割合を比較できます。相関や群差は記述的な値であり、因果関係や回答の意味を自動確定するものではありません。

文字起こし結果の「会話プロファイルと話者連携」では、次を会話ごとに保存できます。

- 会話種別: グループインタビュー、会議、個別インタビュー、ワークショップ、その他
- 目的、実施日、場所、質問ガイド／議題、対象者条件、観察・フィールドノート
- 動画に撮影日時が埋め込まれている場合は実施日へ自動入力し、取得できない場合や修正が必要な場合は手動編集
- AI仕上げで作成したアウトラインを処理済みデータに表示
- 音声話者とグローバル話者の対応
- 話者ごとの表示名とテーマカラー（JSON、カラー字幕、字幕付き動画へ反映）
- 会話役割: 参加者、司会、進行、副司会、観察者、記録者、インタビュアー、議長、発表者、意思決定者、出席者、ゲスト
- 会話固有の組織、部署、役職、条件、同意状態、参加状態、メモ

グループインタビューモードでは、参加者数、司会／進行、観察／記録担当、同意未確認、参加者内で発話時間が50%以上を占める話者を確認表示します。会議モードでは議長／進行と意思決定者を表示します。「会話話者CSV」には属性に加えて発話回数、発話秒数、文字数を出力します。

話者属性と同意情報は `runtime/data/library.sqlite3` にローカル保存されます。CSVやデータベースには個人情報が含まれる可能性があるため、組織の規程に従って取り扱ってください。

## グループインタビュー分析・可視化

上部の「分析・可視化」では、処理済みデータを1件選び、グループインタビューや会議の発話構造を確認できます。画面は分析の性質を次の3区分で表示します。

- **自動集計**: 発話時間・比率・回数、参加者内バランス、司会発話比率と質問候補、話者遷移、長い無音候補、発話重なり候補、時間帯別発話、簡易頻出語、音声感情モデルの推定分布、データ充足状況
- **要設定**: 司会・運営役の除外、比較する話者属性、無音・重なり・低参加のしきい値、時間帯の幅、ストップワード、コードブック
- **要確認・解釈**: 発話へのコード適用、テーマ構築、同意・不一致など相互作用の意味、重要引用、司会の影響、少数意見や反例、研究上の解釈

手動分析では、コード名、定義、含める例、除外する例、カテゴリー、テーマ、テーマカラーを持つコードブックを作成できます。コードブックを変更した場合は理由と変更履歴を保存します。各発話へ複数コード、発話のきっかけ（自発／司会・参加者の働きかけ）、相互作用タグ、対象発話への根拠リンク、重要引用、除外、メモを保存すると、内容分析と相互作用分析を別表で照合できます。設定と注釈は処理済みデータと同じSQLiteへ保存されます。

分析画面の「対象データの確認と分析方針」は、研究目的・研究質問・質問ガイド・グループID・参加者属性・話者順・時刻・司会役・逐語録／音声／動画の利用可否を、未入力時は**不明**として表示します。研究目的と質問が十分でないときは、質的内容分析＋相互作用分析を暫定案として表示するだけで、結果を作成しません。分析レポート（Markdown）、発言と分析結果の対応表CSV、コードブックCSV、相互作用の根拠発話CSVを出力できます。

初回取込時の文字起こしは、編集用本文とは別の原文スナップショットとして保存します。既存データをこの版へ移行した場合は、移行時点の本文を保存し、その来歴を`migrated_current_snapshot`と明示します。移行前の真の原文は復元できないため、原文として断定しません。

文字起こし編集で注釈先の発話IDがなくなった場合も、注釈は孤立データとして分析JSON内に保持します。手動分析画面に件数を表示するため、元発話の統合・削除後も復旧や監査ができます。

各可視化には対応するCSV出力があり、画面上部の「全分析JSON」には計算条件、元データrevision、自動集計、手動設定・注釈、根拠発話を含めます。生のJSONは画面には表示せず、ダウンロード時に必ず生成します。

### 形態素・構文・計量テキスト分析

- **形態素解析**: GiNZAが読み込める場合は、そのSudachi情報から表層形、原形、正規形、読み、Universal POS、詳細品詞、活用を形態素単位で保存します。GiNZAが利用できない場合はSudachiPy単独へ切り替えます。
- **構文解析**: GiNZAのUniversal Dependencies形式から、語、依存関係ラベル、係り先トークン、係り先表層形を保存します。GiNZAモデルが利用できない場合は構文解析を「利用不可」と明示し、推測値は作りません。
- **語彙頻度**: 内容語（名詞・固有名詞・動詞・形容詞・副詞）のTF（総出現回数）、DF（語を含む発話数）、話者数、TF-IDFを計算します。
- **共起**: 1発話を1文書として、同じ発話に現れた内容語ペアの共起発話数、Jaccard係数、Dice係数を計算します。画面の設定で最小共起発話数と対象上位語数を変更できます。

KH Coder 3 Reference Manualの抽出語、TF・DF、品詞選択、共起ネットワークの考え方を分析設計の参考にしています。ただし、このアプリのトークン化、文書単位、語の選択、しきい値は独自仕様であり、**KH Coderとの数値互換性はありません**。論文ではソフトウェア名・バージョン、解析器、分析単位、除外語、しきい値を記載してください。

### SPSS系の統計分析

分析単位は発話で、画面設定から比較軸を「話者」または「会話役割」に変更できます。

| 出力 | 内容 |
| --- | --- |
| 度数分布 | 話者、役割、質問候補の件数と割合 |
| 記述統計 | N、欠損、平均、標準偏差、中央値、最小、四分位、最大 |
| クロス集計 | 比較軸×質問候補、比較軸×手動コードの度数、行%、列%、全体% |
| Pearsonのカイ二乗検定 | 統計量、自由度、p値、Cramér's V、期待度数5未満のセル数 |
| 一元配置分散分析 | F、自由度、p値、η² |
| Kruskal–Wallis検定 | H、自由度、p値、ε² |
| 相関 | Pearson／Spearmanの係数、N、p値 |

同一会話内の発話は、同じ話者や直前の発話の影響を受けるため、独立観測とは限りません。この画面の推測統計は探索用です。p値だけで結論を出さず、効果量、標本数、期待度数、研究デザインを確認してください。多重比較補正は自動では行いません。複数会話・反復測定を一般化する場合は、話者・会話を階層として扱う混合モデル等を統計専門家と検討してください。

### Excel標準出力とCSV

「Excel（標準出力）」は1ファイルに、README、発話データ、話者別集計、形態素、構文・係り受け、品詞頻度、語彙頻度、共起、記述統計、度数分布、クロス集計、統計検定、相関、既存の会話分析、手動コード、重要引用、分析手法を別シートで保存します。各表には対象ID、元ファイル名、文字起こしrevision、分析revision、生成日時、アルゴリズム版を付けます。Excel数式として解釈される文字列は無害化しています。

CSVはUTF-8 BOM付きで、ExcelまたはGoogle Sheetsへ取り込めます。形態素と構文は行数が多くなるため、必要な表だけCSVで取得することもできます。

### 分析手法の主な出典

- 樋口耕一「KH Coder」および [KH Coder 3 Reference Manual](https://khcoder.net/en/manual_en_v3.pdf)
- Works Applications [SudachiPy official documentation](https://worksapplications.github.io/sudachi.rs/python/)
- Megagon Labs [GiNZA — Universal Dependenciesに基づく日本語NLPライブラリ](https://megagonlabs.github.io/ginza/)
- [Universal Dependencies: Japanese](https://universaldependencies.org/ja/)
- SciPy [Statistical functions](https://docs.scipy.org/doc/scipy/reference/stats.html) と [chi2_contingency](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.contingency.chi2_contingency.html)

数値だけで発言の意味を確定しないでください。発話時間の多さは重要性や影響力、話者遷移は影響関係、頻出語は重要テーマ、無音は同意、発話重なりは遮りを意味しません。音声感情モデルの結果も本人の感情を確定するものではありません。COREQは研究品質の得点ではなく、報告項目の入力状況を確認するために扱います。

## モデルと GPU の目安

| Whisper モデル | 特徴 | 目安 |
| --- | --- | --- |
| `tiny` | 最速・低精度 | 動作確認、短いメモ |
| `base` | 標準 | VRAM 4 GB の旧世代 GPU |
| `small` | 高精度 | CPU または VRAM 6 GB 以上 |
| `medium` | さらに高精度 | CPU または VRAM 8 GB 以上 |
| `large-v3` | 最高精度 | RAM 16 GB 以上の CPU または VRAM 12 GB 以上 |

GeForce GTX 970 など Compute Capability 7.0 未満の GPU では、文字起こしに PyTorch 版 OpenAI Whisper を使用します。`tiny` / `base` だけを選んでください。話者分離は CPU を推奨します。

文字起こしを CPU で行う場合も OpenAI Whisper を使用します。OpenAI Whisper には VAD（音声区間検出）がないため、「小さい声を拾いやすくする」の VAD onset / offset は適用されず、無音判定しきい値だけが効きます。

## 出力

既定ではこのフォルダーの `runtime/output` に、実行ごとの専用フォルダーを作成します（`MOJIOKOSI_OUTPUT_DIR` で変更可）。

```text
runtime/output/
└─ YYYYMMDD_HHMMSS_元ファイル名_実行ID/
   ├─ 元ファイル名_話者分離.txt
   ├─ 元ファイル名_話者分離.srt
   ├─ 元ファイル名_話者分離.json
   ├─ 元ファイル名_話者カラー字幕.ass
   ├─ 元ファイル名_字幕付き.mp4
   └─ 元ファイル名_アウトライン.txt
```

JSON は画面設定にかかわらず必ず生成され、話者ラベル、自己紹介から特定した名前、話者別テーマカラー、全発話を含みます。ASS と字幕付き MP4 は「字幕付き動画」を有効にした動画ジョブで生成します。話者名やテーマカラーを作業画面で変更して保存すると、JSON と字幕付き動画も更新されます。

研究分析のExcel、分析全体JSON、個別CSVは「分析・可視化」で選択中の処理済みデータからダウンロード時に生成します。これらは保存済みrevisionを記録しますが、`runtime/output` フォルダーへ自動複製はしません。

選択した元ファイルは変更・削除しません。開始時にアプリ内のジョブ専用フォルダーへスナップショットコピーし、そのコピーを処理するため、実行中に元ファイルが置換されても処理内容は変わりません。前処理用ファイルを含む一時コピーは処理終了後に削除します。確認再生用のコピーは `runtime/data/media`、ライブラリのメタデータは `runtime/data/library.sqlite3` に保存されます（`MOJIOKOSI_DATA_DIR` で変更可）。

## くしなだ学習用データ

編集を保存すると、変更があった発話について修正前後、時刻、話者、くしなだ感情ラベルを、本文のrevision更新と同じSQLiteトランザクションへ保存します。元メディアがある場合は発話区間を16kHz/mono WAVに切り出し、`runtime/data/kushinada_training/corrections.jsonl` と学習マニフェスト `manifest.csv` をSQLiteの正本から原子的に再生成します。強制終了後も次回起動時に両ファイルと孤立音声を修復します。ダウンロード時もSQLite正本から生成するため、派生ファイルが未生成または一時的にロック中でも履歴を取得できます。

この機能は再学習に使える教師データを蓄積するもので、モデルの再学習や重みの更新そのものは自動実行しません。データを削除しても監査・学習履歴としてこの修正データと通常の出力ファイルは保持されます。保持した出力は削除後の起動時自動インポート対象から除外されるため、削除したライブラリ項目が意図せず復活することはありません。

学習用JSONLとCSVにはサーバー内の音声パスが含まれるため、リモートアクセスを有効にした場合はWeb UIからの生データダウンロードを無効化します。必要な場合はサーバーの `runtime/data/kushinada_training` を管理者が直接取得してください。

## セキュリティとリモート公開

既定では `127.0.0.1` だけで待ち受けるため、このPC以外からは接続できません。通常の個人利用では、この既定設定のまま使用してください。

外部から接続できる構成は明示的なオプトインです。`MOJIOKOSI_ALLOW_REMOTE=1` を設定したうえで、少なくとも次を設定します。環境変数はアプリを起動する前に指定してください。

| 環境変数 | 内容 |
| --- | --- |
| `MOJIOKOSI_ALLOW_REMOTE` | `1` の場合だけリモートアクセスを有効化 |
| `MOJIOKOSI_HOST` | 待受アドレス。既定は `127.0.0.1`。TLSリバースプロキシを同じPCで動かす場合は通常このまま使用 |
| `MOJIOKOSI_ACCESS_TOKEN` | 20文字以上の十分にランダムな秘密文字列。リモート有効時は必須 |
| `MOJIOKOSI_TRUSTED_HOSTS` | 許可するホスト名をカンマ区切りで指定（例: `transcribe.example.jp`） |
| `MOJIOKOSI_ALLOWED_ORIGINS` | 許可する完全なOriginをカンマ区切りで指定（例: `https://transcribe.example.jp`） |

ブラウザーの認証ダイアログでは、ユーザー名は任意、パスワードには `MOJIOKOSI_ACCESS_TOKEN` の値を入力します。APIクライアントは同じ値をBearer tokenとして送信できます。

```powershell
$env:MOJIOKOSI_ALLOW_REMOTE="1"
$env:MOJIOKOSI_HOST="127.0.0.1"
$env:MOJIOKOSI_ACCESS_TOKEN="十分に長いランダムな秘密文字列をここへ設定"
$env:MOJIOKOSI_TRUSTED_HOSTS="transcribe.example.jp"
$env:MOJIOKOSI_ALLOWED_ORIGINS="https://transcribe.example.jp"
$env:PYTHONPATH="$PWD\src"
.\.venv\Scripts\python.exe -m gurumoji.app
```

FlaskのHTTPサーバーを `0.0.0.0` などへbindし、`http://PCのIPアドレス:7860` をLANやインターネットへ直接公開しないでください。認証情報と文字起こしデータを平文HTTPで流さないよう、TLSを終端する信頼済みリバースプロキシ、またはアクセス制御されたVPNを使用してください。可能ならアプリ自体は `127.0.0.1` のままにし、同じPCのTLSリバースプロキシから接続します。

リモートアクセス時、サーバー上の任意のローカルパスを指定する機能は既定で無効です。必要なファイルはブラウザーからアップロードしてください。この状態ではAPIのエラー、警告、ログに含まれる絶対ローカルパスも伏せて返します。例外として `MOJIOKOSI_ENABLE_REMOTE_LOCAL_PATHS=1` を設定すると、認証済みのリモート利用者にもサーバー内パスの指定と診断上のパス表示を許可できます。これは直結接続とリバースプロキシ経由の両方で、サーバー内ファイルへアクセスできる範囲を広げる高リスクな設定です。隔離された専用環境以外では有効にしないでください。

アプリは `runtime/data` ディレクトリに対して単一インスタンスで動作します。同じデータディレクトリを使う複数プロセスは起動できず、1インスタンス内で同時に実行できる文字起こしジョブも1件です。削除中に強制終了した場合は、次回起動時にSQLiteの有無を正本として隔離中メディアを復元するか、ゴミ箱（`runtime/data/trash`）へ移して削除を完了します。並列処理のために同じ `runtime/data` や `runtime/output` を複数プロセスで共有しないでください。

文字起こしの編集保存では、出力を置換する前に `.edit-transaction.json` と旧ファイルのバックアップを同じ出力先へ記録します。保存中にプロセスが強制終了した場合、次回起動時にSQLiteのrevisionを正本として、未確定の出力は旧版へ戻し、確定済みの出力は新版のまま後片付けします。journalの改ざん、別データベースのjournal、外部変更などで安全に判定できない場合は、出力を推測で変更したり自動取り込みしたりせず起動を停止します。

## 容量・ジョブ保持の設定

大きすぎる入力によるメモリーやディスクの消費を抑えるため、次の上限があります。値の単位はMBで、変更する場合はアプリの起動前に環境変数を設定します。

| 制限名 | 環境変数 | 既定値 | 対象 |
| --- | --- | ---: | --- |
| `MAX_MEDIA_MB` | `MOJIOKOSI_MAX_MEDIA_MB` | 4096 MB | メディアのアップロードとローカルパス入力 |
| `MAX_CSV_MB` | `MOJIOKOSI_MAX_CSV_MB` | 10 MB | 話者管理CSVの取込 |
| `MAX_JSON_MB` | `MOJIOKOSI_MAX_JSON_MB` | 32 MB | JSON形式のAPIリクエスト |
| `MAX_RETAINED_JOBS` | `MOJIOKOSI_MAX_RETAINED_JOBS` | 50件 | メモリー内に保持するジョブ状態 |
| `JOB_TTL_SECONDS` | `MOJIOKOSI_JOB_TTL_SECONDS` | 86400秒（24時間） | 完了・失敗・キャンセル済みジョブ状態の保持時間 |
| `BACKUP_DIR` | `MOJIOKOSI_BACKUP_DIR` | `runtime/backups` | 「バックアップを作成」と `scripts/backup_data.py` の保存先 |
| `TRASH_RETENTION_DAYS` | `MOJIOKOSI_TRASH_RETENTION_DAYS` | 30日 | 削除した会話の元音声・動画を `runtime/data/trash` に保管する日数。過ぎた分は起動時に完全削除します。0で削除時にすぐ消去 |

ジョブ保持上限とTTLは、進捗表示や再接続に使うメモリー内の状態を整理する設定です。処理済みライブラリや `runtime/output` の成果物を自動削除する設定ではありません。送信直後に接続が切れたりページを再読み込みした場合は、ブラウザーが同じ送信IDで受付中・実行中・保存済み結果を照会し、未受付を確認した再送でも同じIDを再利用して二重実行を防ぎます。

「中止」はFFmpeg、感情分析、AI API通信などの子プロセスを停止し、生成途中の成果物を片付けます。Whisper・WhisperX・pyannoteのモデル読込や推論はライブラリ内処理を安全に強制終了できないため、その工程の終了直後に停止します。長い音声をCPUで処理している場合は、中止要求から実際の停止まで時間がかかることがあります。

## API 実装について

- OpenAI は Responses API の Structured Outputs を使用します。
- Google は Gemini `generateContent` の JSON Schema 出力を使用します。
- LM Studio / Ollama はループバック上のOpenAI互換 `POST /v1/chat/completions` と JSON Schema 出力を使用します。モデル一覧と接続ライトは `GET /v1/models` で確認します。
- API が発話 ID や発話数を変えた場合は、不整合を防ぐため AI 校正結果を採用しません。
- 話者名は明示的な自己紹介がある場合だけ自動入力し、最終判断は作業画面で手動修正できます。
- アウトラインは文字起こし済みテキストから作成し、音声・動画ファイルは API に送信しません。
- 音声前処理はローカルの FFmpeg だけで実行します。音声・動画ファイルは OpenAI / Google / LM Studio / Ollama へ送信しません。
