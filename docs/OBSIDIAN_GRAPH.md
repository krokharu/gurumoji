# 全体とインタビュー別のグラフを使う

研究用の保管庫は `runtime/data/obsidian/ResearchVault` です。`00-ホーム.md` または左のブックマークを入口にします。

## 表示を切り替える

左のブックマーク → **Gurumoji** から次を選びます。

| 項目 | 表示 |
| --- | --- |
| 研究全体のグラフ | インタビューの概要と、関連付けた共通テーマ |
| インタビュー別 → I001など | その1件の概要・全文・アウトライン・分析まとめ・研究メモ・関連テーマ |
| インタビュー一覧 | 日付・状態などを一覧表示するBases |
| ホーム | インタビューを選ぶ入口 |
| 分析結果 | 保存済みの分析まとめをインタビュー別に開く一覧 |
| 分析手法別 | KH Coder系、Transformer系、生成AI、統計、会話構造、質的分析から選ぶ |

ホームの「分析結果」には保存済みの分析まとめへの直接リンクも表示します。各インタビューの概要では、先頭の「分析結果」から見解・根拠・分析条件・保存履歴へ進めます。結果が未保存の場合は未保存と表示します。アプリで分析結果をObsidianに保存すると、一覧とホームも自動で更新します。

「分析手法別」では、同じ分類の結果をインタビュー別に確認できます。KH Coder系はKH Coderの考え方を参照した独自の計量テキスト分析です。Transformer系は既存のHuBERT・wav2vec 2.0による音声感情分析をまとめます。KH Coder本体の実行や新しいモデルの追加は行いません。

各インタビューの分析まとめにも同じ6分類を表示し、手法ごとの最新の保存日時（UTC）・状態・結果へのリンクを掲載します。文脈検索だけを後から保存しても、他の手法の保存結果は一覧に残ります。未実行・データなし・利用不可・簡易解析・入力変更後の結果を区別します。分類ページは `40-研究/分析手法/` に保存し、通常のグラフからは除外します。

グラフ内のノートをクリックして開きます。操作・状態・原文・分析の履歴・手法説明は通常のグラフから除外しています。仕上げノートのタグは作成時点のまま保持するため、過去の全文やアウトラインも表示される場合があります。現在の作業版は概要・状態ノートから開きます。インタビューごとの分析結果や全文は別のインタビューのグラフには入りません。

色は概要が青、テーマが緑、分析が橙、メモが紫、全文が灰色、アウトラインが水色です。選択中のノートの強調色はObsidianの表示設定に従います。

Workspacesの **Gurumoji・研究全体** と **Gurumoji・インタビュー作業** は画面配置の切り替えです。グラフの表示対象は上記ブックマークで選びます。作業画面の右側にあるローカルグラフは、現在のノートに追従します。共有テーマから他のインタビューへ広がる場合があるため、1件限定で見るときはブックマークのインタビュー別グラフを使います。

## テーマでインタビューをつなぐ

1. インタビューの「研究メモ」に `[[20-テーマ/働き方]]` のようなリンクを書きます。
2. リンク先を開いて、テーマノートを作成し、その意味・解釈・根拠を記録します。
3. 関係する別のインタビューの研究メモにも、同じテーマへのリンクを書きます。

Gurumojiを起動している間は、約10秒間隔で明示的なリンクを確認し、`40-研究/テーマ関連/`に関連インタビューの一覧を生成します。グラフから関連一覧を開き、そこからテーマ本文へ進めます。AIは呼びません。実際に書かれたリンクを使い、語が似ていることだけで関係を確定しません。

テーマノートの本文・プロパティは書き換えません。グラフ用タグと関連一覧は別の生成ノートに置きます。以前の版がテーマ本文に作った`gurumoji:interviews`区間はそのまま残り、今後は更新されません。研究メモに書いたコード例のリンクは関連付けに使いません。本文の根拠には、全文ノートの `#^s-...` ブロックリンクを利用できます。

テーマをまだ付けていないインタビューも、全体グラフと一覧に表示します。全文内の発話を1つずつ独立ノートにする必要はありません。

## 保存場所

```text
ResearchVault/
  00-ホーム.md
  01-分析結果.md
  インタビュー一覧.base
  10-インタビュー/I001-録音名/
    I001-概要.md
    I001-全文.md
    I001-アウトライン.md
    I001-分析まとめ.md          分析保存済みの場合
    I001-研究メモ.md
    I001-操作.md
    I001-状態.md
    I001-保存原文.md
    履歴/                      仕上げ版・分析・引用スナップショット
  20-テーマ/
  30-人物/
  40-研究/
  80-添付/
  90-運用/
```

同じ録音ファイル名でも、アプリに別々の保存データとして登録されている場合は別のインタビューIDを付けます。既存の本文や保存結果を名前の一致だけで統合しません。

全文の編集とAI仕上げは[仕上げ操作の手順](OBSIDIAN_FINISHING.md)を参照してください。管理用プロパティの表示は、生成ノート用のCSSで整理しています。操作ノートでは `provider` を表示します。ID・タグなどはプロパティのサイドバーやソースモードから確認できます。

## 移行・設定の保存

2026-09-13に旧階層の63ノートをバックアップ付きで移行し、保存済み3件の入口を作成しました。バックアップ先と旧→新パスの対応は `runtime/data/obsidian_layout/migration-v1.json` に記録しています。移行前の研究Vault・DB・仕上げ状態・分析成果物は同じフォルダー内の `backup-...` に残っています。

アプリの初回起動時にも旧階層を検出し、移行を行います。中断した移行は `migration-pending.json` とバックアップを使って再開します。移行先や移行元が手動編集されていた場合は、その内容を保護して中断します。移行・再保存でAIを再実行しません。

表示設定は研究Vaultの `.obsidian`、インタビューのID対応と生成ノートの管理情報は `runtime/data/obsidian_layout` にあります。バックアップにはこのフォルダーも含めてください。既存の分析成果物のJSON／CSVは移動・再計算しません。

生成した概要を直接書き換えた場合、その概要は自動上書きしません。考察は「研究メモ」に記載すると、概要のリンクや状態を自動更新したまま使えます。ブックマークのGurumojiグループはアプリが更新するため、自分用の項目は別グループに保存してください。保存済みのWorkspacesは自動で上書きしません。

## プラグインと確認

Graph view・Bookmarks・Workspaces・Bases・Backlinks・Properties・Canvasという標準機能を使用します。コミュニティプラグインは追加していません。必要になった場合は、ExcaliBrainと、その依存先のExcalidraw・Dataviewを比較できます。

Obsidian 1.13.7で全体グラフ3ノード、インタビュー別グラフ5・4・4ノード、Basesの3件表示、未解決リンク0件を確認しました。追加のAI通信は行っていません。CLIを有効にした環境では `python scripts/check_obsidian_graph.py` で実機の表示対象を再確認できます。

公式資料：[Graph view](https://help.obsidian.md/plugins/graph)、[Bookmarks](https://help.obsidian.md/plugins/bookmarks)、[Workspaces](https://help.obsidian.md/plugins/workspaces)、[Bases](https://help.obsidian.md/bases)。設計の背景は[再設計の計画書](program-vault/40-Design/obsidian-graph-plan.md)にあります。
