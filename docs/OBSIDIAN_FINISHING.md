# Obsidianで文字起こしを仕上げる

新しい文字起こしでは「Obsidianに保存して仕上げ（標準）」が既定で有効です。画面・API・内部の処理設定ともObsidianでの保存と操作を標準にしています。Whisperの出力に話者ラベルを付けた時点で、AI校正前の原文と作業ノートを保存し、文字起こしは一旦完了します。本文のAI校正・アウトライン作成などは、Obsidianの操作ノートで実行操作を選んだときに呼び出します。

文字起こし開始時に「自己紹介から話者を特定・登録」を有効にし、AIプロバイダーを設定した場合だけ、本文を変えずに自己紹介を確認します。確認できた未登録の話者は話者管理へ登録され、アプリ・出力・新規の作業ノートでは話者番号の代わりに名前を表示します。名前や発話の割り当ては、アプリの「会話・話者」でいつでも修正できます。

## 使い方

1. アプリでAPIキー・モデルを設定し、文字起こしを実行します。APIキーはObsidianに記載しません。
2. データの作業画面（処理済みデータから開く画面）の下部にある「Obsidianで仕上げ」から「Obsidianで操作ノートを開く」をクリックします。既存の処理済みデータも同じボタンから作業版を作成できます。既存データでは現在のアプリ保存版を出発点とし、過去のWhisper原文を復元することはありません。
3. Obsidianで研究用Vaultを開きます。既定の場所は `runtime/data/obsidian/ResearchVault`、入口は `00-ホーム.md` です。1つ上の `obsidian` フォルダーではなく `ResearchVault` 自体を保管庫に指定します。`MOJIOKOSI_DATA_DIR` を指定した場合は、そのデータフォルダー内の `obsidian/ResearchVault` になります。
4. 操作ノートから状態ノートを開き、「編集する会話」の各発話の引用本文を修正します。録音1件の全発話が1ノートに入り、発話ごとのファイルには分けません。時刻・話者の見出しと、引用の下の `^s-...` ブロックIDは保持します。
5. 操作ノート先頭のプロパティ欄で `provider` を `openai` / `google` / `lmstudio` のいずれかにします。「アウトラインを作成」だけにチェックを入れて保存します。
   同じノートの「AI仕上げに含める処理」で、自己紹介からの話者名特定・仕上げ後のアウトライン出力・Jevによる修正要否比較を選択できます。Jev比較は各発話を「修正が必要／修正不要」の二択で判定し、現行AIの変更有無と比較します。使用モデルは実行時のアプリ設定を使います。
6. 状態ノートに完了と表示されたら、リンク先の全体アウトラインを確認・編集します。議題は `## 見出し`、要点は `- 箇条書き` です。
7. 前のチェックを外して保存し、状態ノートが「次の操作を選べます」になるのを待ちます。「AI仕上げを実行」にチェックを入れて保存します。編集した会話と全体アウトラインを参照して再校正・ノイズ判定します。アウトラインが空の場合は先にAIで作成します。
8. 状態ノートから仕上げ結果を開き、折りたたみ欄の原文・修正理由・ノイズ候補を確認します。結果の引用本文は反映前に手動修正できます。ノイズ候補は自動削除しません。
9. 前のチェックを外して保存し、「次の操作を選べます」になったら「結果をアプリへ反映」をチェックします。確認済み本文、話者名、出力用アウトラインをアプリ・TXT・JSON・字幕等へ保存します。アプリ側の画面は再読み込みしてください。

Gurumojiを起動したまま操作します。チェック欄の変更は約2秒間隔で確認します。複数の操作を同時にチェックすると実行しません。処理中のチェックを外すと、AI呼び出しの区切りで中止します。Obsidianの追加プラグインは使用しません。

## ファイルとトークン

Obsidian公式の[ローカルMarkdownによる保存方式](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data)に合わせ、研究Vault内に直接保存します。保存先は `10-インタビュー/I001-録音名/` のようにインタビュー単位でまとめます。初回の全文・アウトライン・操作・状態・保存原文と概要を浅い位置に置き、生成版は同じインタビューの `履歴/仕上げ/` に残します。現在編集する版は概要・状態ノートのリンクから開きます。

全体・インタビュー別グラフ、一覧、画面配置の切り替えは[グラフの使い方](OBSIDIAN_GRAPH.md)を参照してください。ノートを読みやすくするため生成ノートの管理用プロパティは通常表示から隠し、操作ノートでは `provider` を表示します。全プロパティはObsidianのプロパティ表示やソースモードから確認できます。

- [プロパティ](https://help.obsidian.md/properties)：ノート先頭に録音名、作成・更新日時、タグ、別名、原文・操作ノートへのリンクを持たせます。入れ子にせず、標準のプロパティ欄で扱える形式にします。`tags` と `aliases` は自由に編集できます。`note_id` は移動先の識別に使うため保持します。
- [内部リンク・ブロック参照](https://help.obsidian.md/links)：会話・原文・アウトラインを内部リンクで結び、各発話にはブロックIDを付けます。研究メモから `[[会話ノートのパス#^s-6669727374]]` のように特定の発話を参照できます。ソースモードでIDを確認できます。
- [コールアウト](https://help.obsidian.md/callouts)：AIの修正理由と校正前の本文を折りたたみ欄に保存します。会話本文とは区別して読めます。

旧形式の作業ノートも引き続き読み込めます。旧形式では `text` ブロック内を編集してください。既存のノートを一括で書き換えることはありません。

録音ごとに、保存原文・会話全文・全体アウトライン・操作・状態のノートを用意します。AIが生成したアウトラインや仕上げ結果は版ごとの新しいノートに保存し、人が編集しているノートを上書きしません。過去版も残ります。

全文・アウトライン・操作ノートの本文やプロパティは、自動同期で書き換えません。タグは作成時点のまま残るため、現在編集する版は概要・状態ノートから開いてください。アプリの管理状態が失われ、保存先に作業ノートが残っている場合は上書きせず停止します。バックアップのDB・`obsidian_workbench`・研究Vaultが同じ時点のものか確認してください。

AIに送るのはノートから読み取った本文・短い識別子・話者ラベル・必要な文脈だけです。プロパティ、内部リンク、Markdownの見出し、区切り、操作欄、原文と結果の重複、修正理由の表示欄は送信しません。ノートごとのAPI呼び出しも行いません。長い会話だけを文字数で分割し、前後の発話と圧縮した全体アウトラインを添えます。ノートの保存数そのものによってAPIのトークン数が増える設計ではありません。

## 更新・中断

- チェックを入れたままでも同じ操作を再実行しません。再実行は一度チェックを外して保存し、状態を確認してから再チェックします。
- 元の会話や参照アウトラインが処理中・処理後に編集された場合は、古い結果の反映を止めます。最新の編集内容でAI仕上げを再実行してください。
- タグ・別名などプロパティだけの編集では、仕上げ結果を無効にしません。新形式のノートは処理していない間に同じVault内で移動・改名できます。Obsidianのリンク自動更新を有効にすると内部リンクも追従します。移動先で `note_id` が重複すると特定できないため処理を止めます。旧形式のノートは元の保存場所を保持してください。
- アプリ側で会話が更新された場合も反映を止めます。アプリの「Obsidianで仕上げ」から最新の作業版を作成できます。以前の作業ノートは残ります。
- アプリが中断した場合は、自動でAIを再呼び出しません。状態と保存結果を確認してからチェックを入れ直します。
- 作業状態・原文JSON・仕上げ結果JSONはデータフォルダーの `obsidian_workbench` に保存します。バックアップにはDB・`obsidian_workbench`・研究Vault・出力・必要なメディアを含めます。

この連携でアプリへ反映するのは、操作ノートに対応する仕上げ結果です。分析用の自動生成ノートや研究メモ全般をアプリへ取り込む機能とは別です。旧階層からの移行はバックアップ付きで実行し、保存先・内部リンク・DBのノート参照・仕上げ状態を更新します。
