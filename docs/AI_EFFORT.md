# AI仕上げのエフォート設定

「AI仕上げ」でAPIと処理を有効にすると、4つのカードで考える量を個別に設定できます。

- 全体アウトライン：参照用アウトラインの作成・圧縮と、仕上げ後の議題整理。
- おすすめ文章整形：Jevが要確認とした発話を、選択した参照範囲でLLMが確認・置換。
- 話者名の候補抽出：自己紹介からの氏名候補の抽出。
- 話者リンクの再確認：氏名と発話者の対応の確認。

おすすめ文章整形には「なし／小／中／高／MAX」があります。Jevは各発話について、意味不明な認識、音声ノイズの文字化、途切れ、欠落、重複、明白な誤認識の修正要否を判定します。修正候補だけをLLMへ渡し、LLMが問題なしと判断した発話は原文のまま残します。

- なし：Jev・LLMによる文章置換を実行しない。
- 小：対象発話だけを読み、原文をできる限り残して致命的で明白な誤りだけを最小修正する。
- 中：対象発話だけを1つの文章として処理し、意味不明・ノイズ・途切れ・明白な誤認識を修正する。
- 高：会話アウトラインと直前1発話を読む。文章になっていない、または途切れていて判断材料が足りないとLLMが返した場合だけ、さらに1つ前を追加して再実行し、最大10発話まで広げる。
- MAX：会話アウトラインと前後最大10発話を読み、会話の流れから強く予測できる文章への書き直しを許可する。文脈にない事実・結論・固有名詞の創作は禁止する。

小・中・高では、会話の流れから予測した全面的な書き直しを許可しません。おすすめで「Obsidianに保存して仕上げ」をOFFにしたアプリ内仕上げを選び、AIプロバイダーとTypeSafe APIキーが設定済みの場合にこの処理を実行します。Obsidian仕上げではWhisper原文を先に保存するため、このアプリ内文章整形は実行しません。

ほかのカードには「思考モード」のON／OFFと、ONのときのエフォート「低／中／高／ultra」があります。OFFでは推論を使わず、低からultraへ進むほどより長く考えます。処理時間・トークン使用量は内容とモデルで変わり、精度の向上を保証するものではありません。設定はブラウザーに保存され、Obsidianの作業ノートを作成・再度開く際にも引き継がれます。実行中の作業には途中の設定変更を反映しません。

アプリ内の仕上げでは現在の工程と回転アニメーションを表示します。Obsidianの仕上げも、対象の会話をアプリで開いていれば3秒ごとに状態を確認して表示します。アニメーションは待機中の表示で、残り時間の予測ではありません。OSの「動きを減らす」設定では回転と切り替えアニメーションを停止します。

手動の思考量指定は対応モデルで使用してください。LM Studioでは、文章整形以外のカードで非対応の選択肢を無効にします。文章整形の5段階はモデルの思考量だけでなく参照範囲も制御するため、すべて選択できます。

- OpenAI Responses API：OFFは`reasoning.effort: none`、ultraは`xhigh`として送信します。対応値はモデルに依存します。[公式モデル資料](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
- Gemini 2.5：`thinkingBudget`をOFF / 低 / 中 / 高 / ultra に対し 0 / 1024 / 8192 / 16384 / 24576 で設定します。Gemini 2.5 ProはOFFをサポートしないため、最小の1024に対応付けます。Gemini 3系もOFFを完全にはサポートしないため最小、ultraは高に対応付けます。[公式思考設定資料](https://ai.google.dev/gemini-api/docs/generate-content/thinking)
- LM Studio：`/api/v1/models`のモデル別対応値を確認して送信します。ON／OFFだけを持つQwen系ではON時にモデルの既定の思考量を使い、`minimal`は低、`xhigh`は高またはultraへ対応付けます。Gemma・Llama系のように思考量のAPI設定を公開しないモデルには、非対応の値を送らずモデル既定の動作を使います。[モデル対応値の公式資料](https://lmstudio.ai/docs/developer/rest/list)

旧い保存データの文章整形「自動」は「中」として扱い、ほかの処理の「自動」は引き続きモデルの既定値として扱います。エフォートを変更しても発話ID、時刻、話者の対応付けは変更しません。
