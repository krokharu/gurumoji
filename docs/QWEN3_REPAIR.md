# Qwen3-8Bの修復と実機再検証

2026-09-14、Qwen3-8BでAI仕上げ全工程が通ることを確認しました。アプリの使用モデルは`qwen/qwen3-8b`に戻し、LM Studioでロード済みです。

## 特定した原因

保存されていた`Qwen3-8B-Q4_K_M.gguf`のSHA-256が、[配布元](https://huggingface.co/lmstudio-community/Qwen3-8B-GGUF/tree/07ebe812301319d9947477e3a94ab8aa587bb3af)と不一致でした。

- 配布元・交換後：`a7676d257b10f3ce23aedba45e64ba61a5aa295f0009d87c5627f6c026a8f35f`
- 交換前：`756f0ee0101a872da4e61373a8cfd97879649a1ecbd3b174516651f6761fe3ba`
- ファイルサイズ：5,027,783,968バイト。
- 不正な領域：ファイルオフセット1,566,875,648から8,192バイト。
- 対象：`blk.5.ffn_up.weight`というモデル重み。
- 旧ファイルではこの領域がすべて`FF`。配布元との実際の不一致は8,137バイトで、残り55バイトは配布元も`FF`でした。他の領域は一致しました。

同じ推論処理・同じサーバーでモデルファイルを交換すると成功したため、この重みの破損が生成異常の主因と判断しました。以前のGPU相性やJSON制約の問題という仮説を、この結果で訂正します。ファイルが破損した時点や、ダウンロード・保存などどの段階で破損したかは未特定です。

## 修復内容

1. 配布元のコミットを固定してGGUFを再取得。
2. サイズとSHA-256が配布元と一致することを確認。
3. 元ファイルを同じフォルダーの`Qwen3-8B-Q4_K_M.gguf.backup-756f0ee0101a`へ退避。
4. 検証済みファイルに交換してロード。
5. アプリのローカル使用モデルをQwen3-8Bに設定。

再利用可能な検証・修復処理を`scripts/repair_qwen_download.py`に実装しました。ダウンロードのハッシュが不一致なら元ファイルを置換せず、置換に失敗した場合も元ファイルへ戻します。通常の検証は書き換えを行わず、`--repair`を指定した場合だけ修復します。修復前は対象モデルをLM Studioからアンロードしてください。

```powershell
python scripts/repair_qwen_download.py C:/Users/kurok/.lmstudio/models/lmstudio-community/Qwen3-8B-GGUF/Qwen3-8B-Q4_K_M.gguf
```
