# 分析手法の登録票

手法の定義をプログラム資料側で版管理し、研究用Vaultには利用した定義の版を保存する。外部ツールによる分析と手作業の分析にも同じ票を使う。

| 項目 | 記入ルール |
| --- | --- |
| `method_id` | 英小文字・数字・アンダースコア。名称変更でも維持 |
| `method_version` | 計算法・前処理・出力契約の変更で更新 |
| 表示名・目的 | 解こうとする問いと結果の読み方 |
| `execution_kind` | `builtin`／`external`／`manual` |
| 実装状態 | `planned`／`available`／`deprecated`。登録できることと計算できることを区別 |
| 入力単位・必須データ | 会話／話者／発話／形態素等、必須列・ID・入力schema |
| 対象・除外 | 条件、対象集合の作成法、欠測・1話者・空データの扱い |
| パラメーター | 型・既定値・範囲・計算への影響 |
| 計算・実施手順 | 式または質的分析の工程、解析器・モデル・環境・seed |
| 結果schema | 必須成果物、JSON schema、CSV列・単位・行キー、図の形式 |
| 根拠規則 | 必須の発話参照／対象集合／表の行キー、支持・反証の区別 |
| 更新判定 | fingerprintに含める入力・条件・環境 |
| 保存分類 | DB台帳、固定CSV／JSON、Markdownの役割 |
| 限界 | 言えること、言えないこと、確認を要する条件 |
| 出典 | 手法の一次資料、実装元、確認日 |
| 検証 | 架空データ、期待結果、失敗条件、確認者 |

## 手法を登録する際の確認

- [ ] 同じ入力・条件・手法版を識別できる。
- [ ] 結果の行と入力を照合できる。
- [ ] 空・欠測・実行不可・失敗を区別する。
- [ ] 全件データを保存し、画面のプレビューから結果を作らない。
- [ ] 見解には出所と根拠がある。
- [ ] 既存のコード・メモ・別手法の結果を上書きしない。
- [ ] 原文・実行条件・結果ファイルへのリンクを確認した。
