# 逐語録の分析準備

## 操作

「分析」→「設定・手動分析」→「文字起こしを分析用データに整える」。本文・話者・区切りの修正は既存の文字起こし編集画面で行い、保存後に分析画面で対象を再読み込みする。

1. 研究目的・研究質問・質問票・比較属性は既存の会話プロフィール／分析設定へ記入する。準備欄には根拠資料名とページ・行等を記録する。ない資料は推測しない。
2. 実参加人数は名簿等の根拠がある場合だけ記入する。発言した人数ではない。話者名は匿名IDを使い、実名対応表は分析データとは別に管理する。
3. 発言ごとに本文状態（未確認／逐語録確認・音声未照合／音声照合済み／聞き取り不明）、発言区切り、話者確認、役割を記録する。音声・動画が存在しない場合の音声照合済みは拒否する。照合を実際に行ったかは研究者の申告であり機械認証ではない。
4. 順序は保存逐語録の配列に分析用付番する。時刻が欠損する編集では0秒を根拠に並べ替えない。`time_unknown` は互換編集処理が内部に0秒を持っていても、準備表で欠損として出力するための印。
5. 分割・結合時は、保持された過去の発言IDをカンマ区切りで指定する。自動推測しない。部分引用の文字オフセット管理は未実装。今回の準備表の単位は発言全体。
6. 「確認途中として保存」、または全発言の本文と区切りを確認した後に「版を確定」。後者でも話者不明なら相互作用の準備完了とはしない。
7. CSVと「原本・全入力版・確認履歴 JSON」を取得する。JSONには過去の本文・プロフィールも含むため共有前に個人情報を確認する。メディアは含めない。外部送信・AI実行は起こさない。

## 正本と追加テーブル

現在の編集対象は従来どおり `library_items`。原音声・動画の保存先、会話ID、既存発言ID、ResearchVaultは変えない。

| テーブル／項目 | 内容 |
| --- | --- |
| `library_items.original_segments_json` | 取込時の本文。新規Whisper処理ではAIによる本文修正より前の発話スナップショットを保存。生のモデル出力全フィールドではない |
| `transcript_versions` | 現在の発話配列・話者プロフィール・表示名・会話プロフィールの不変スナップショット。会話ID＋連番、source_hash、来歴、日時を保持 |
| `transcript_preparations` | 最新の確認記録とrevision。確認対象source_hash・研究者確認状態・分析根拠hash |
| `transcript_preparation_events` | 確認記録の全変更履歴。過去分を件数制限で削除しない |

発話・プロフィールの保存と入力版の記録は同じSQLiteトランザクション。確認保存は `BEGIN IMMEDIATE` と確認revision・source_hashの一致を必要とする。GET・CSV出力では履歴を増やさない。失敗時は同時にロールバックする。

元から空のレコードに後で発言を追加しても、過去の取込原本を捏造しない。新しい入力版に本文を記録し、対応原本なしとする。既存レコードの初回保存では現時点の版を `legacy_current_baseline` 等として固定し、過去の原本や編集履歴を復元したとは扱わない。

## 確認状態と分析根拠

内容の準備は「本文が非空」「本文確認済み」「区切り確認済み」。相互作用の準備はこれに加えて話者・役割・順序の確認を必要とする。手法の必要データが十分、妥当性が検証済み、とは意味しない。

本文、話者、順序、プロフィールが変わればsource_hashが変わり、確認状態は保守的に全件再確認となる。コード・相互作用の根拠も要再確認とする。確認記録の変更でも分析根拠は再確認対象になり得る。単なる分析保存では解除せず、研究者の明示的な再確認操作で現在の版へ結び直す。過去の確認記録と根拠hashは履歴に残る。

削除した発言を参照する既存リンクは `missing_target` として保持する。存在しない発言への新規リンクは拒否する。レポートは現在の分析対象版の本文を引用し、根拠が古いコード・相互作用は結果として出さない。取込時本文を修正後のコードの根拠へ勝手に差し替えない。

## 出力

### 画面の可視化（2026-09-14追加）

「分析」→「設定・手動分析」の保存済み記録を表示する。編集途中のコード・リンクは保存後に反映する。

- コード件数の棒は0～最大件数の共通尺度。10件と100件は1:10の長さ。0件は長さ0。話者ラベル数とグループ数を併記し、支持人数や重要性の割合とは表現しない。
- 話者×コード表はPC・モバイル共通。色の尺度は表全体の最大件数で統一し、件数ボタンから根拠発言を開く。ここで表示する発言集合は連続した会話ではなく、該当コードの抜粋。
- 相互作用タイムラインは保存したリンクだけを応答発言の順で表示。参照先→応答発言を示し、関係種別で絞り込む。矢印は因果関係ではなく、縦の間隔は経過時間ではない。自動で同意・意見変更を判定しない。
- 各リンクから両端とその間の全発言を発言順に開く。集計除外の発言も文脈として残して区別する。40発言ずつ追加できる。リンクは30件ずつ追加表示し、表示件数と全件数を明示する。
- 本文は改行・空白を保ちHTMLとして解釈しない。内容コード・カテゴリー・テーマと、相互作用の解釈メモを別に表示。本文確認状態、話者・役割・順序の未確認も表示する。時刻のある発言は元の発言・音声画面へ移動できる。
- 根拠が古いリンクや参照先削除には現在の本文を結び付けず、IDと要再確認表示を残す。古いコードのマトリクスも現在の本文を根拠として開かない。

図の画像ダウンロード、テーマ間の理論関係図、反例の専用分類、VisualizationVaultからの図ファイル生成は今回の範囲外。CSVと既存の版付き保存契約は変更しない。

テスト：`tests/test_qualitative_visualization.py`（PC／モバイルの実ブラウザーで尺度、ゼロ値、比較表、関係フィルター、91発言の連続文脈、除外発言、XSS防止、古い根拠、削除先、追加表示、空データを検証）。

### API・データ出力

- `PUT /api/library/<id>/preparation`：確認記録の保存。必須 `revision`, `source_hash`、発言IDごとの `records`、任意 `confirm`, `review_analysis`。
- `GET /api/library/<id>/analysis`：`manual.preparation` に準備状態、発言表、入力版一覧。
- `GET /api/library/<id>/analysis/export.csv?dataset=prepared_turns`：UTF-8 BOM、1発言1行。時刻・ID等の欠損は空欄。原本文と分析対象本文、版、前後ID、確認状態を分離。
- `GET /api/library/<id>/preparation/export.json`：原本、全入力版、確認履歴、列一覧・文字コード・行数・行データのhashを持つmanifest。CSVは数式注入対策の接頭辞を付ける場合があるため、厳密な文字列の交換はJSONを使う。manifestのrows_sha256はJSON行データの正規化hashでありCSVファイルのbyte hashではない。
- 分析CSVにも入力版・source_hash・要再確認フラグ。Excelに「逐語録の分析準備」シート。固定した分析成果物にも準備表と準備状態を収録。

InputVaultへは版・hash・確認状態・件数だけを記録し、確認メモや発言本文を複製しない。分析の入力識別値は準備revisionも含み、変更後は保存分析をstale扱いにする。通常のVault更新でAI再実行はしない。

## 導入・バックアップ・互換性

起動時に3テーブルを追加するだけで、既存本文・IDの一括移行はしない。導入前のバックアップはアプリ停止後のDBと必要メディア・既存Vault、またはSQLite backup APIによる整合コピーを使用する。稼働中DBの単純コピーは避ける。

旧コードへ戻しても既存列・保存先は同じで、追加テーブルは残してよい。ただし旧コードによる編集は新しい履歴を記録しない。再導入時はhash不一致を再確認対象とし、その期間の編集履歴を復元したとは扱わない。JSONは監査用の出力であり、自動復元／履歴版への巻き戻しUIは今回実装しない。

関連テスト：`tests/test_transcript_preparation.py`。欠損、確定条件、競合、原本保全、全版保持、根拠の陳腐化、参照先削除、CSV、トランザクション、PC／モバイルブラウザーを検証する。
