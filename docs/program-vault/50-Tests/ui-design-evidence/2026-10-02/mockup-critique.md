# Gurumoji 静止モックアップの独立批評

2026-10-02 UTC / v2 初回レビュー＋修正後10図の再確認 / 提案・未採用・未実装  
対象ソースHEAD: `ddc23abe0d747a1e6cfd6d3bc262ce226f4756b0`  
対象: `prototypes/v2/rendered/` の比較PNG 8図と修正後に加わった補助状態2図。初回8図・修正後10図を `view_image` で実画素確認した。本文の座標・寸法・MC指摘は初回レビュー版に対するもの。修正後の判定は冒頭の要約と末尾を参照する。

## 結論

**段階導入はAを第一候補とし、Bのdesktop根拠paneは独立した仮説として残す。** Aは今回の静止状態では測定→確認→採用の現在地と主張→引用の所属を追いやすい。B desktopは同時対照の余地がある。B mobile初回の主張欠落は修正された。修正版でも研究者メモは別状態にあるため、画面の短さだけで「照合しやすい案」とは評価できない。

両案の大きな前進は、**計算済み0と欠測、平均の分母、採用と実行、分析時12版と現在13版、AI下書きと研究者メモ**を文章で分けたこと。quietな緑・紙色と既存構造を保つ方針にも異論はない。色替えや装飾の追加より、次の3点が先である。

1. 編集できる定義と右側の試行結果が、いつの同じ組合せなのかを短く可視化する
2. mobileの根拠にも、検討対象の主張と未確認状態を残す
3. 対象集合・欠測時の次操作・測定の限界を、採用前に読める位置に置く

**修正後の要約:** MC-02〜06の可視情報不足は修正版で補われた。MC-01は試行bindingと変更後の失効図で設計を補強したが、実際の状態遷移・server保証は未実装／未検証。MC-07は低優先の実装評価事項として残す。詳細は末尾「修正版の再確認」。

これは専門家による静止表示レビューであり、利用者の好み、作業速度、完遂率、誤り発見率を測った結論ではない。

## 優先して直す具体点

以下の「高・中・低」は**この設計案を補強する優先度**であり、現行アプリのDG/P1/P2欠陥分類とは別。確信度は画素上の観察と、それに基づく読解リスクを分けて示す。

### MC-01 高: 試行がどの定義・入力に対応するかを通常表示で確かめにくい

- **箇所:** `b-measurement-desktop.png` 左「定義を編集」x≈52–458/y≈277–900と、右「試行結果」x≈518/y≈276以降。A desktopおよび両mobileの試行見出しにも定義版は出ない
- **観察:** 見えるのは「新しい定義・未採用」「先頭4発話を試しました」とheaderの「現在の入力12版」。Bでは編集可能に見えるfieldと採用対象が同じ画面にある。右の結果が左の現在の値に対応するという視覚的な期待を作る
- **リスク:** 左を変えた後も同じ右側を見てよいと誤解し得る。今回の一致fixtureで古い試行を表示している証拠ではなく、重要な不一致状態が未表現という指摘
- **代案:** 試行見出し直下に「試行した定義1版・入力12版／現在の定義と一致」の短いbinding表示。詳細にID/hashを置く。編集後は「定義を変更しました。試行し直してください」を結果の先頭へ出し、旧試行を消すか履歴表示へ退避し、確認チェックと採用を失効させる
- **注意:** 現行APIは個票・固定入力・定義版の追加契約が必要。ラベルを描くだけで安全になったとは扱わない。`draft-DESIGN.md` §5と監査DG-02-T1〜T3に結び付ける
- **確信度:** 観察 高／誤解リスク 中〜高

### MC-02 高: B mobileの根拠から、照合すべき主張が消えている

- **箇所:** `b-evidence-390.png` y≈297–411。「←結果へ戻る：待ち時間」「AI下書きの根拠・1発話」の直下に「選択中の根拠」
- **観察:** 他の3根拠図にある「待ち時間への改善要望がある可能性」「AI下書き・未確認」「引用は一部…全体の合意は…判断できません」が表示されない。topic名だけでは原文の主張を再構成できない
- **リスク:** 引用がどの主張を支えるのか、限定を保ったまま評価できない。記憶と往復に依存する。AI下書きというラベルはあるが、未確認という状態はない
- **代案:** 戻り口の下に小さな主張anchorを残す。「AI下書き・未確認」＋主張全文（このfixtureなら1〜2行）＋「引用1発話。全体の合意は判断できません」。研究者メモは展開式でもよい。sticky化は別の遮蔽／focus検査が必要なので、まず通常flowで置く
- **比較条件:** この必要情報を揃えた後でAのinlineとBの別状態を比較する。現行の画像高さ差178pxは効率差の証明にならない
- **確信度:** 観察 高／誤解・記憶負担のリスク 高

### MC-03 中: 母集団・除外・先頭Nの関係を1行で結べていない

- **箇所:** 全測定図header。desktop y≈154、mobile y≈205。「対象4発話 / 除外1発話」
- **観察:** 全5発話であることと、除外後の先頭4件であることが通常表示にない。試行paneは「先頭4発話」だけを示す
- **リスク:** 「4件のうち1件除外」なのか「4件に加えて1件除外」なのかを推測する必要がある。平均の分母3は別に明示されており、ここを欠測の分母不備と混同しない
- **代案:** header「全5発話・除外1発話」、試行説明「除外後の先頭4発話を試しました」。又は「全5 → 除外1 → 試行4」と短い文で接続する。除外理由は詳細へ。欠測1は試行4の内数だと保つ
- **確信度:** 観察 高／誤解リスク 中

### MC-04 中: 欠測時の「入力を確認」が次操作か状態か判別しにくい

- **箇所:** `a-measurement-desktop.png` S004 x≈765/y≈670、B desktop x≈882/y≈632、A mobile x≈108/y≈950、B mobile x≈108/y≈934
- **観察:** amber色の通常textとして状態欄／値の隣に置かれ、linkの下線やbuttonの形がない。他の操作は枠付きなので見分けがつきにくい
- **リスク:** 欠測の理由を読めても直す入口が分からない。逆に状態の説明を押せると誤認する可能性もある。実際に非クリックだったという検査結果ではない
- **代案:** 状態は「欠測：時刻不明」と記し、別に下線付き「S004の入力を確認」又は小さいoutline buttonを置く。試行時の固定入力確認と現在の発話編集を分ける。現在入力を直したら旧レビューは失効し、再試行が必要と示す
- **実装条件:** row全体だけをclick可能にせず、名前のあるlink/buttonを用意する。欠測は採用不可と自動で決めず、測定の許容条件に従う
- **確信度:** 観察 高／操作探索リスク 中〜高

### MC-05 中: mobileでは測定の限界が採用前の可視要約から落ちる

- **箇所:** `a-measurement-390.png` y≈328–433、`b-measurement-390.png` y≈357–417。desktopにある「重要性や関与の強さは表しません」がない
- **観察:** mobileは規則・数値・尺度・統計の短い列だけ。Aには直下の定義詳細入口があるが、Bの詳細入口は採用より下のy≈1260。閉じた詳細の中身はこの画像では読めない
- **リスク:** 秒数を研究上の重要性や参加の質に読み替えないという、この課題に固有の注意が狭幅だけ弱くなる。field名の英語enumを減らしたのは良いが、限界まで省かない
- **代案:** titleの下か平均の前に「話した秒数を測ります。重要性や関与の強さは示しません」を短く残す。型・尺度・手法など専門詳細を必要に応じて展開へ移す方が、このfixtureの判断に必要な説明を守れる
- **確信度:** 観察 高／誤解リスク 中

### MC-06 中: 引用を特定する発話IDが通常表示にない

- **箇所:** 全根拠図の「選択中の根拠」直下。A desktop y≈637、B desktop y≈333、A mobile y≈658、B mobile y≈436
- **観察:** 「話者B・01:00–01:02」は表示されるが、fixtureのS002はなく、E-002やfull run IDは閉じた詳細に依存する。詳細内容は今回の静止図では未確認
- **リスク:** 同じ話者、時刻の重複や編集があると識別しにくい。来歴そのものが失われたとは断定しない
- **代案:** 直下を「S002・話者B・01:00–01:02」とする。full run/hash/evidence IDは詳細に置いてよい。前後文脈も同じ分析時入力12版から来ていることを詳細又は短いラベルで保証する
- **確信度:** 観察 高／追跡リスク 中

### MC-07 低: 無効状態とmobileの現在地を、色以外でもさらに明瞭にする

- **箇所:** 全測定図の未チェックと淡緑「この定義を採用」。全mobile図の最上部nav「文字起こし 結果一覧 分析 話者」
- **観察:** 採用buttonは未チェック時に淡緑だが緑の境界があり、選択tabの淡緑にも近い。音声buttonは理由が直下にあって分かりやすい。mobileの最上部navにはdesktopの「分析・可視化」の太字／緑の現在地がない
- **代案:** checkboxの補助文「確認すると採用できます」を設け、disabledを役割・状態として実装する。mobile main navも現在地を太字・下線・現在ラベル等で保ち、読み上げ上のcurrentも設定する。警告色の増設や全buttonの大型化は不要
- **確信度:** 観察 高／混乱リスク 中以下。実コントラスト・AT不合格の主張ではない

## 保持したい点と、過剰修正を避ける点

- **数値:** 60/2/0を有効3として平均20.7秒と表示する計算はfixtureと一致。S003は「0秒」「計算済みゼロ」、S004は「欠測」「時刻不明」。平均に0を含め、欠測を含めない文章もある。この区別をlegendだけへ戻さない
- **科学的な限界:** 主張は「可能性」と限定され、引用1件から重要性や全体合意を判断しないと説明される。単なるAI免責badgeより作業に即している。mobile Bにも引き継ぐ
- **採用:** チェック→採用button→「全件実行は始まりません」の並びは明瞭。実行開始を同じbuttonへ合体させない。新しい定義・未採用の表示を、採用済み旧版が破壊されないという実装保証へ読み替えない
- **版差:** 保存結果入力12版／現在入力13版、引用本文の変更warning、現在発話への別入口、音声無効理由を色だけに頼らず示す。このfixtureの理由を「音声がありません」へ置き換えない
- **階層:** desktopの見出し・summary・個票・次操作は追える。過剰に大きいdecorative heroや新ブランドは不要。quiet greenを現在地・操作・数値に一貫して使い、warningを文字と淡いamberで区別する方向を維持
- **legibility:** 今回の短い日本語では明白な欠け・重なり・frame外へのはみ出しは見えなかった。これは長い名前、100行、200%/400%拡大、実フォントの可読性を保証しない。13px補助文字をすべてWCAG違反とする根拠もない
- **密度:** 4個票がmobileで各82pxのcardになるため約360pxを使う。ID/時刻と値/状態の2行は理解しやすい。まず可変高・余白調整を比較し、表を全面に詰めたり必須文を消したりしない。高さだけの最適化はしない

## 選好は分解した仮説として扱う

| 仮説 | この静止図から支持できること | まだ判断できないこと |
|---|---|---|
| Aの段階レビューを最初に導入 | 現在地2、定義要約、確認・採用の順序が表示される。既存3モードとdetailsを維持する | 誤測定発見、学習時間、実装費用の実測 |
| Bのdesktop根拠paneを比較候補に残す | claimとquoteを同時に見られる。fixtureではwarningが近い | 長文・多引用・200%での読みやすさ、focus、pane閉鎖時の選択保持 |
| Bの4タスクnavを独立評価 | labelが研究者の仕事に近い可能性がある | 既存利用者が旧3モードより見つけやすいか。このfixture1課題では判断不能 |
| mobileでは文脈を短く保持する | Aは上下移動、Bは現在主張欠落という異なる負担がある | task成功や往復数の優劣。Bへclaim anchorを足してから同条件比較が必要 |

M（定義と試行の配置）、E（根拠inline/pane）、N（nav再編）を一度に変えないという `comparison.md` の方針を支持する。今回はA/Bの人気投票や合計点にはしない。

## 操作可能な試作で必須になる確認

以下は**要求と試験計画**であり、PNGで確認した結果ではない。

1. **定義の編集・再試行:** Bの左fieldを変える／Aで定義へ戻ると、右の試行binding、確認check、採用可能状態がどう変わるか。遅れて返った旧試行を現在の結果へ採用しない。試行連打の多重送信も確認
2. **採用と実行:** 未チェック時は採用できない。checkedでもserverのレビューbindingを満たすかは別。採用の成功／不明／競合を区別し、全件実行の対象・採用版・処理内容・送信先・保存先は次の実行準備で確認できる
3. **既採用の保護:** fixtureの旧`dur_base`と新`dur_review`を分離し、取消・試行失敗・通信断で旧採用版を維持する。画面上の「新しい定義」だけで合格にしない
4. **根拠を開いて戻る:** 同じrun、result、filter、選択引用、scrollへ戻る。Aのdetailsは起点へfocus。B desktopはpaneの非modal/modalモデルを決め、閉じた後に起点へfocus。B mobileの戻るは前の結果状態を復元し、再計算を始めない
5. **current sourceへの移動:** 保存引用12版と現在13版を混ぜない。現在の発話を開いて戻っても保存引用は固定。音声の無効理由をkeyboard/ATでも取得できる。別fixtureで同版・音声ありの通常再生→戻るも試す
6. **読み順・役割:** 表はheader/rowの対応、mobile cardは発話IDと値/理由の関連を持つ。tabsは適切なkeyboard操作と選択状態、disclosureはexpanded状態、checkboxは関連labelを持つ。status更新でページ全体を読み上げ直さない
7. **長文・狭幅:** 320 CSS px、200%/400%相当、長い日本語の定義・話者・引用、複数根拠、0件/全欠測/試行失敗、未知のlegacy来歴を確認。tableの二次元性で周囲の操作の横overflowを正当化しない

実装前に全状態の美しい画面を作る必要はないが、少なくとも「定義編集後・試行失効」「採用応答不明」「根拠版不明」の3状態を短いstoryboard又は状態表で補い、誤った成功を描かないことを確認する。
