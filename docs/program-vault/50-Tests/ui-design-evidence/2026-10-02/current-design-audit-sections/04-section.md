# Gurumoji 現行デザイン監査と実装可能な改善計画：4. 段階的な情報構造案

親索引・状態・確認版：[[50-Tests/ui-design-evidence/2026-10-02/current-design-audit]]。必要な本文だけを取得する。

## 4. 段階的な情報構造案

ADR-118の既存方針を採用しつつ、最初から全画面を差し替えない。

### 第1段階: 入口と用語の整合

- 上部4入口、作成3ステップ、データ作業4タブは維持
- 分析の主ボタンを実態に即した「基礎分析を実行」で統一。現在JSが表示時に「分析を実行」へ戻すため、ラベルを共通化
- テーマ分析・AI見解・分類の入口は適切なページに可視で置き、送信前確認と中止を同じ部品へ寄せる
- 「手動実行」は「測定を定義して実行」、「手動分析」は「研究者の確認・コード付け」など目的を分離。正式語彙は利用者の理解で検証して確定
- データ一覧／分析の補助ナビは上部と同じ意味を繰り返さず、対象コンテキストと戻り先へ整理

### 第2段階: 分析内の作業主語へ移行

| 主入口案 | 現行機能をどこから移すか | 初期実装の境界 |
|---|---|---|
| 結果を見る | 自動分析、手法別、概要〜統計 | 手法はfilter、主題は副ナビ。計算を起動せず閲覧 |
| 比較する | 下部比較パネル、比較履歴 | 既存同一質問/異条件探索の注意と版固定を保つ |
| 分析を組む | 共通実行dialog、定義、準備、コード/研究者確認への入口 | 既存APIを再利用しつつDG-02-T1〜3の版・試行契約は追加が必要。外部送信や新しい尺度採用は明示 |
| データ・出力 | 出力・検証、run履歴、各成果物、Vault状態 | 現在のプレビューと固定runを区別 |

全結果を新旧レイアウトへ二重描画せず、既存panel builderを再利用する。現在desktop/mobileの両contentを再構築しているので、値・選択・イベント・focusの回帰を確認し、技術刷新を導線改善の前提にしない。

## 5. 視覚体系: 維持するものと整えるもの

### 5.1 方向性

Gurumojiは、根拠を読む時間の長い研究用ワークスペースとして整える。濃緑は選択と主要操作、紙色は背景、白は作業面。既存の色の骨格を残し、装飾の光沢やカード数を増やすより、対象・内容・操作の優先順をはっきりさせる。

旧1440pxの根拠画面では、結果文と引用本文・話者・時刻・音声操作の近接は有用。旧結果編集画面でも、選択した発話の境界が明瞭。この良さを残してコンテキスト帯と操作密度を整える。現行修正版の視覚品質を旧画像だけで評点化しない。

### 5.2 トークンの提案

| 用途 | 現行 | 提案・条件 |
|---|---|---|
| 基本本文 | `--ink #18211d` | 維持 |
| 背景/作業面 | `#f4f5f0 / #fffef9` | 維持。階層は背景濃度・境界・余白の少数ルールで表す |
| 主要操作 | `#1c6b50` | 維持。白上6.425:1の指定色対 |
| 補助文 | `#68736e`、analysisのみ`#526159` | 役割tokenへ。小さく薄い文字を増やさない |
| 警告文字 | `--orange #e87941`の流用 | orange装飾とwarning-textを分離。文字は濃色に |
| focus | `rgba(28,107,80,.35)` | 不透明の識別しやすい色と3px枠を候補。各背景で検証 |
| タイプ階層 | root`.7rem`、各画面override多数 | title / section / body / label / caption / monoの役割を定義 |
| 余白 | 5/7/9/11/13等が多い | 4/8/12/16/24/32を基準候補に。既存表示の調整値まで機械的に置換しない |
| 角丸/影 | 7〜22px、画面と部品で多数 | panel、control、pillの3系統へ。選択・hoverを影だけで示さない |

fontは既存日本語system stackを継承。本文16px相当、操作label14〜15px相当、補助13px相当を候補に試す。これは製品の読みやすさの方針であり、「WCAGが16pxを要求する」という主張ではない。

指定色の計算は[specified-color-contrast.json](../specified-color-contrast.json)に保存。独立反証でcascadeを追跡し、drop-zoneの通常背景は後続media queryのwhite、文字比率は3.128:1と補正した。基底gradientとの2.892〜3.029:1は現行画面比率として使わない。登録話者概要の未保存orangeは実gradient端点上2.627〜2.759:1。一方、analysis sidebarの未保存は濃色overrideで5.992:1あり、維持する反例。半透明保存バーやhover/selectedを含むcomputed styleは別途必要。既存mutedのcard上4.875:1を、淡い文字と同じ扱いにしない。

### 5.3 密度とレスポンシブ

- desktopの資料照合は本文・音声/動画・根拠の優先度で幅を配分。常時サイドバーを増やさない
- 959px以下の既存切替を当面維持。320pxでは横ナビの選択名、主操作、入力エラーを確実に読めるようにする
- 表は研究用途上の二次元性を維持し、横スクロールと同等のダウンロードを用意。全列をカードへ変換することを既定にしない
- 固定保存バーは未保存保護として残す。viewport・ソフトキーボード・拡大でfocusや編集中本文を完全に隠さない
- 多数発話の性能改善は別計測。見た目を軽くするために根拠や件数を黙って間引かない
