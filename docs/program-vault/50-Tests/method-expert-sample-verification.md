# 手法の専門家定義のサンプル検証（2026-09-16）

対象：17人の専門家定義（[[50-Analysis-Methods/10-Experts/00-Index]]）と、`src/gurumoji/method_experts.py` によるアプリへの組み込み（[[40-Design/decisions]] のADR-115）。

## 「サンプル検証済み」の意味と、確かめていないこと

架空のサンプル逐語録をアプリの実際の経路（分析データの生成 → 専門家の選択 → 適用条件の判定 → 分析方針の手順・分析レポート・保存記録・AI下書きの制約）に通し、適する条件と適さない条件の両方で、専門家定義どおりに判定・表示されることを確かめた、という意味で使う。

確かめていないこと：

- 実データでの動作。実在の逐語録や個人情報は使っていない。
- 実際のLLMの出力。AIの呼び出しはテスト用の偽の応答に置き換え、外部へ送信していない。生成文の妥当性は検証していない。
- 多言語E5による埋め込みの計算と、音声感情モデルの推論。この環境には sentence-transformers と s3prl が入っていないため、保存形式に合わせた架空の結果（Transformerテーマ分析の結果、発話ごとの感情ラベル）で、専門家の判定だけを確かめた。
- 判定と手順の方法論的な妥当性。専門家定義が各手法を正しく表しているかは、文献ノートの確認範囲に依存する。方法論に詳しい人のレビューは受けていない。
- ブラウザー上の表示。分析方針パネルの専門家の確認は、既存のUIテストが成功することだけを確かめ、表示内容は目視していない。2026-09-16に追加した「手法別」タブ（ADR-116）は、実ブラウザーの自動テスト（`tests/test_analysis_method_view.py`）で一覧・判定・専門家・結果パネルの表示を確認したが、人の目視はしていない。

## 環境

- Windows 11、プロジェクトの `.venv`（Python 3.12）、ブランチ `agent/expand-analysis-ai-workflows` の未コミットの作業ツリー
- GiNZA・SudachiPy・SciPy は導入済み。sentence-transformers・s3prl は未導入
- データベースとVaultの出力先は一時フォルダー。`runtime/data` は使わず、一時フォルダーは実行後に削除した

## サンプル

すべて架空。架空の家計簿アプリを1週間使った感想を話す、司会1人・参加者3人のグループインタビュー（24発話）をもとに、条件を変えた。

| サンプル | 内容 | 主に確かめた条件 |
| --- | --- | --- |
| fit | 24発話、時刻あり、準備記録で本文・区切り・話者・順序を確認済み、研究目的・質問項目・比較グループあり、全発話に感情ラベル | 適する条件 |
| no_question | 研究目的と研究質問がなく、準備記録も未確認 | 研究質問を必要とする手法 |
| one_speaker | 参加者1人の8発話 | 話者数・発話数を必要とする手法 |
| no_times | 時刻がなく、順序も未確認 | 時間構造と相互作用 |
| long | 3人・450発話 | 少量のデータ向けの手法の上限 |
| sparse_emotion | 感情ラベルが24発話中2発話だけ | 感情推定のカバー率 |
| fit_second | fit と同じ比較グループの2件目 | 会話間比較 |

## 結果

### 主手法として選ぶ専門家（方法論）

| 専門家 | 適する条件（fit） | 適さない条件 | AI見解 |
| --- | --- | --- | --- |
| 質的内容分析 | 満たす | no_question：研究質問がない → 分析を始めない | fit：段階IDと文献IDつきで保存。no_question：生成しない（409） |
| テーマ分析 | 満たす | no_question：分析を始めない | fit：保存。登録外の文献IDを返すと再試行後に失敗し、前回の見解を保持。no_question：409 |
| フレームワーク法 | 満たす | one_speaker：話者が2人未満 → 分析を始めない | fit：保存。one_speaker：409 |
| SCAT | 満たす | long：450発話 → 要確認（上限の目安300） | fit：保存。要確認では止めない |
| M-GTA | 満たす | 研究質問を空にする：研究目的だけでは分析テーマにならない → 分析を始めない | fit：保存。研究質問なし：409 |
| KJ法 | 満たす | long：450発話 → 要確認（上限の目安400） | 主手法にすると常に生成しない（409） |
| 計量テキスト分析 | 満たす（GiNZA） | one_speaker：発話20未満・話者2人未満・簡易解析 → 要確認 | 主手法にすると常に生成しない（409） |
| フォーカスグループの相互作用分析 | 満たす | no_times：順序が未確認 → 分析を始めない。one_speaker：参加者2人未満 → 分析を始めない | fit：保存。no_times：409 |

8手法とも、分析方針の手順が主の専門家の段階と担当に置き換わり、分析レポート（Markdown）に「手法の専門家による確認」の節と主の専門家の見出しが出た。分析レポートの文献IDと、分析を始めない条件の行は、テーマ分析と相互作用分析で確かめた。

### 結果を保存する手法の専門家（計算・前処理・比較）

| 専門家 | 適する条件 | 適さない条件 |
| --- | --- | --- |
| 参加バランス | fit：満たす | one_speaker：話者2人未満 → 分析を始めない。no_times：順序未確認・時刻なし → 要確認 |
| 会話の時間構造 | fit：満たす | no_times：有効な時刻が50%未満 → 分析を始めない。one_speaker：話者2人未満 → 分析を始めない |
| 記述統計 | fit：満たす（GiNZA） | 簡易解析 → 要確認。no_times：有効な時刻が90%未満 → 要確認 |
| 群間比較 | fit：期待度数5未満のセルが多い → 要確認 | one_speaker：群が1つ → 分析を始めない |
| 相関 | fit：満たす（GiNZA） | one_speaker：発話10未満 → 要確認 |
| 埋め込みによるテーマ探索 | 架空の保存結果（シルエット係数0.32）：満たす | 0.05 → 要確認。入力が変わった後の結果 → 分析を始めない。未実行 → 判定を付けない |
| 音声感情推定 | fit（全発話にラベル）：満たす | sparse_emotion（カバー率8%）→ 要確認。no_times：順序未確認 → 要確認 |
| 日本語テキストの前処理 | fit：GiNZAで満たす（形態素・係り受け） | 簡易解析 → 要確認。係り受けが使えない場合は結果がなく、判定も付けない |
| 会話間比較 | fit と fit_second：満たす | 1会話だけ（コードで直接判定）→ 分析を始めない |

保存記録では、結果を出した手法だけに担当専門家の判定が付き、未実行のTransformerテーマ分析と、専門家を置かないローカル見解・手動コード・AI見解には付かなかった。`algorithms.experts` には知識hashが残った。ResearchVaultの手法ノートの「限界と追加確認」には、担当専門家、判定、研究者が確認する項目の件数、文献IDが出た（示してはいけない結論も同じ節に書く）。

## 確認項目ごとの結果

| 確認項目 | 結果 |
| --- | --- |
| 正しい専門家が使われるか | 8手法それぞれで、主の専門家が「研究者が選択」として読み込まれた。補助の専門家は、分析方針が補助に挙げた手法のものだけ |
| 手法固有の手順に従うか | 分析方針の手順が、主の専門家の段階と担当（研究者・コード・AI下書き）に一致した。AI下書きは、許可された段階と、その段階の文献IDだけを使った |
| 根拠をたどれるか | 分析レポートと保存記録に、専門家ID・定義の版・知識hash・文献IDが残った。文献IDから文献ノートへ、文献ノートから確認範囲と査読状態へたどれる |
| 適さないデータを無条件に分析しないか | 分析を始めない条件では、AI見解を生成前に409で止めた。計算系の結果は従来どおり計算・保存し、判定を付けた |
| 文献の不足を示すか | 知識ベースの写しから文献ノートを消すと、分析レポートに「見つからない文献ノート」が出て、その文献だけを根拠とするAIの段階が外れた |
| 捏造しないか | 登録外の文献IDは保存されなかった。研究者が確認する項目を、アプリは確認済みと表示しなかった。未実行の手法には判定を付けなかった。専門家どうしの合議や独立したレビューは行っていないと、分析レポートに明記した |
| ノートの更新が反映されるか | 知識ベースの写しで手順ノートを変えると、保存済みのAI見解が「更新が必要」になり、次の保存は新しい記録になった。変更前は、同じ入力の保存が同じ記録を返した |
| 関係のない専門家を読み込まないか | 読み込みの記録で、本文を読んだ専門家フォルダーは分析方針の専門家だけだった。他の専門家はプロパティだけを読んだ |
| 既存の機能を壊していないか | 下記の全テストが成功した |

## 実行したテスト

- `tests/test_method_expert_samples.py`（8件、成功）：上の結果のうち、簡易解析で再現できるもの。
- `tests/test_method_experts.py`（23件、成功）：定義の検証、文献の解決、専門家の選択、知識hash、AI下書きの制約、API。
- 全テスト：プロジェクトの `.venv` のPythonで `python -m unittest discover -s tests`（2026-09-16の最終実行で445件、すべて成功）。システムのPythonで実行すると scikit-learn などが無く、Transformer分析のテストが失敗する。
- GiNZAを使う「満たす」の結果（計量テキスト分析・記述統計・相関・前処理）は、同じサンプルを実際のGiNZAで通した一回限りの実行で確かめた。実行に使った作業用スクリプトはリポジトリに含めていない。

再実行：リポジトリルートで環境変数 `PYTHONPATH=src` を設定し、`python -m unittest discover -s tests -p "test_method_expert*.py"` を実行する。
