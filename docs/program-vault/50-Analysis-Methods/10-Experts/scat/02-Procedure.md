# SCATの専門家：手順

段階は [[50-Analysis-Methods/20-Literature/LIT-otani-2011-scat|大谷 2011]] による（頁は掲載誌の頁）。

## 手順と各段階の確認事項

| 段階 | 内容 | 担当 | 確認事項 |
| --- | --- | --- | --- |
| scat-p1 | セグメント化 | 研究者 | セグメント化の適切さは結果に影響する。目安は一つのセグメントに大きく一つのトピック（[文献] 4.2節、p.158） |
| scat-p2 | 〈1〉注目すべき語句 | AI下書き＋研究者 | 〈1〉は全体を見て決めるべきなので、先にすべて書き出すのがよい。書き出した後の修正は可（[文献] 5.1節、p.159–160） |
| scat-p3 | 〈2〉言いかえ | 研究者 | テクスト外の語句で言いかえる（[文献] p.155） |
| scat-p4 | 〈3〉説明する概念 | 研究者 | 〈2〉の示すものの背景、条件、原因、結果、影響、比較、特性、次元、変化などを検討する。上下の行も見る（[文献] p.158） |
| scat-p5 | 〈4〉テーマ・構成概念 | 研究者 | 前後や全体の文脈を考慮する（[文献] p.157の表）。文ではなく名詞・名詞句で書く（[文献] 公式ページ） |
| scat-p6 | 〈5〉疑問・課題 | AI下書き＋研究者 | 分析の過程で得た疑問や追究すべき課題。〈4〉を書いた後でなくてもよい（[文献] 4.7節、p.158） |
| scat-p7 | ストーリーライン | 研究者 | 〈4〉を紡いで書き、使った〈4〉に下線を引いて漏れを確認する（[文献] 4.8節、p.159） |
| scat-p8 | 理論記述 | 研究者 | ストーリーラインを断片化して書く。普遍的な原理ではなく「このデータから言えること」（[文献] p.159） |
| scat-p9 | さらに追究すべき点・課題 | 研究者 | 〈5〉をまとめ、ストーリーライン・理論記述を書く中で生じた疑問も加える（[文献] 4.10節、p.159） |

## 判断に迷いやすい点

- [文献] 分析の順序は、〈1〉〜〈4〉を縦に進めても1行ずつ横に進めてもよく、混在してもよい（大谷 2011、5.1節）。
- [文献] 〈3〉〈4〉のコードが句になる場合は、中核的な語を「」で囲むなどするとよい（p.158）。
- [文献] 1〜2行程度の短い回答が多数ある場合は、福士・名郷（2011）の活用法（1回答を1セグメント）が有効とされる（p.160）。
- [実装判断] Gurumojiの発話がトピックの途中で切れている場合、隣接する発話をまとめて1セグメントにしてよい。まとめた発話IDの対応を記録する。

## 典型的な失敗と修正

| 失敗 | 修正 |
| --- | --- |
| 〈4〉に解釈した文を書く | 最大限精緻化した概念（名詞・名詞句）に書き直し、文はストーリーラインへ（公式ページ） |
| ストーリーラインで〈4〉の一部しか使わない | 下線で確認し、使っていない〈4〉を検討する（4.8節） |
| 理論記述を一般法則のように書く | 「このデータから言えること」として書き直す（p.159） |

## 結果のまとめ方

研究質問と概念的枠組み → マトリクス → ストーリーライン → 理論記述 → さらに追究すべき点・課題 → 限界。
