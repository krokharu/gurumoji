# M-GTAの専門家：判断基準と品質確認

## 判断基準

- [文献] コーディングの基本は、データを解釈してコードに置き換えることと、コードから元のデータへたどれるようにしておくことの2点で、どのタイプのGTAでも共通する（木下 2007、p.4）。
- [文献] 解釈した意味は定義として短文にしておくことで、解釈の密度を一貫して維持できる（木下 2007、p.7）。
- [文献] 飽和化は、新たに重要な概念が生成されなくなり、理論的サンプリングで確認すべき問題点がなくなったときに判断する（木下 2007、p.8）。
- [文献] M-GTAは限定された範囲で一般化しうる知識の生成を目的とし、その一般化は分析焦点者を介した条件設定で成り立つ（研究会のページ）。

## アプリが判定する項目と人が確認する項目

M-GTAの品質は、概念の生成と比較の吟味によるため、コードで判定する品質項目は置かない（[実装判断]）。`mgta-q1`〜`mgta-q5` はすべて研究者が確認する項目。適用条件では、研究質問（分析テーマとして登録）の有無だけをコードで判定する。

## ほかの手法との違い

[整理] 質的内容分析やコーディングの信頼性型テーマ分析のように複数のコーダーの一致を品質の条件にするのではなく、ワークシートでの定義とヴァリエーションの対応、反対例の検討、理論的メモの記録を品質の拠り所にする。
