# M-GTAの専門家：手順

段階は [[50-Analysis-Methods/20-Literature/LIT-kinoshita-2007-mgta|木下 2007]]（頁は掲載誌の頁）と [[50-Analysis-Methods/20-Literature/RES-mgta-society-official|M-GTA研究会のページ]] による。

## 手順と各段階の確認事項

| 段階 | 内容 | 担当 | 確認事項 |
| --- | --- | --- | --- |
| mgta-p1 | 分析テーマと分析焦点者 | 研究者 | 研究テーマを設定した後に分析テーマを設定する（[文献] 5節、p.4–5）。「〜のプロセス」を入れて動態的プロセスを捉える形にする（[文献] 研究会のページ） |
| mgta-p2 | 全体を読み着目する | 研究者 | 面接記録なら最初に1人分の全体に目を通す（[文献] p.6）。切片化せず、分析テーマと分析焦点者を視点に着目する（[文献] 6節、p.5、研究会のページ） |
| mgta-p3 | 概念の生成 | 研究者 | 着目した部分の意味を幾通りか検討し、定義として採用するものを決め、概念表現を考える（[文献] p.6） |
| mgta-p4 | 分析ワークシート | AI下書き＋研究者 | 1概念1ワークシート。概念名、定義（短文）、ヴァリエーション（具体例）、理論的メモの欄（[文献] 8節、p.7） |
| mgta-p5 | 反対例・類似例と比較 | AI下書き＋研究者 | 反対例や類似例も記入し、複数の概念のワークシートを同時並行で進める（[文献] p.7） |
| mgta-p6 | 理論的メモ | 研究者 | 定義にならなかった解釈案、疑問、アイデアを記入する（[文献] p.6–7） |
| mgta-p7 | カテゴリーの生成 | 研究者 | 概念と概念の関係から分析結果をまとめる（[文献] p.4） |
| mgta-p8 | 理論的サンプリングと飽和化 | 研究者 | 新たに重要な概念が生成されず、理論的サンプリングで確認すべき問題点がなくなったときに飽和化と判断。データの範囲の調整も含める（[文献] p.8） |
| mgta-p9 | 結果図とストーリーライン | 研究者 | 論文執筆の前に、概念とカテゴリーだけで簡潔に文章化する（[文献] p.9） |

## 判断に迷いやすい点

- [文献] 分析結果がすぐに出てきそうな場合は、分析テーマがまだ練られていないと考えて再検討する（研究会のページ）。
- [文献] 分析テーマと分析焦点者の調整から、二つ目の論文につながる別の分析テーマが設定できる場合もある（研究会のページ）。
- [実装判断] Gurumojiでは、概念をコードブックのコード（ラベル＝概念名、説明＝定義）、ヴァリエーションをそのコードを付けた発話、理論的メモを分析メモで記録する。

## 典型的な失敗と修正

| 失敗 | 修正 |
| --- | --- |
| 発話を細かく切り分け、語句ごとにコードを付ける | 分析テーマと分析焦点者に照らして意味のまとまりに着目し直す（切片化しない） |
| 定義を書かずに概念名だけを付ける | 解釈した意味を短文の定義にする（p.7） |
| 反対例を探さない | ワークシートに反対例を記入し、定義を見直す |
| 人数や頻度で結果を示す | 概念と概念の関係でまとめる（p.4） |

## 結果のまとめ方

研究テーマ・分析テーマ・分析焦点者 → 概念の一覧（定義とヴァリエーション） → カテゴリー → 結果図 → ストーリーライン → 理論的メモと飽和化の判断 → 限界。
