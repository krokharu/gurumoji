# フレームワーク法の専門家：手順

段階は [[50-Analysis-Methods/20-Literature/LIT-gale-2013-framework|Gale et al. 2013]] の「Procedure for analysis」による。

## 手順と各段階の確認事項

| 段階 | 内容 | 担当 | 確認事項 |
| --- | --- | --- | --- |
| fw-p1 | 書き起こし | 研究者 | 質の良い録音と、可能なら逐語の書き起こし（[文献] Stage 1） |
| fw-p2 | 面接に慣れ親しむ | 研究者 | 分析者と面接者が異なる場合に特に重要。余白に分析的なメモ（[文献] Stage 2） |
| fw-p3 | コーディング | AI下書き＋研究者 | 1行ずつ読み、重要と解釈した箇所にコード。帰納的な研究では多くの観点からコード化（open coding）（[文献] Stage 3） |
| fw-p4 | 作業用の分析枠組み | 研究者 | 最初の数件の後、研究者が集まってラベルを比べ、コードの組に合意し、カテゴリーにまとめて明確に定義する。数回の改訂がありうる（[文献] Stage 4） |
| fw-p5 | 枠組みの適用 | 研究者 | 以後の逐語録にインデックスを付ける。質的データ分析ソフトはデータを整理する道具で、分析はしない（[文献] Stage 5） |
| fw-p6 | 行列へのチャート化 | AI下書き＋研究者 | 表計算で行列を作り、逐語録ごとにカテゴリー別の要約を記入する（[文献] Stage 6） |
| fw-p7 | 解釈 | 研究者 | 印象や考えを記録し、分析メモを書いてチームで議論する（[文献] Stage 7） |

## 判断に迷いやすい点

- [文献] 慣れれば1時間分の逐語録につき平均で約半日かかり、初期はさらに長くかかる（Gale et al. 2013、Stage 6）。作業量をデータの量から見積もる。
- [整理] ケースの単位（話者、属性、グループ、会話）を先に決める。Goldsmith（2021、要旨）は分析単位を複数の観点から検討する重要性を示す。
- [実装判断] Gurumojiの「話者×コード（発言件数）」の表は、インデックス付けの結果の確認に使える。セルの要約（チャート化）は研究者が分析メモや外部の表で行う。

## 典型的な失敗と修正

| 失敗 | 修正 |
| --- | --- |
| 共通のトピックがないデータを行列にまとめようとする | 手法の選択に戻る（テーマ分析、語りの分析など） |
| 枠組みを最初から固定し、改訂の記録を残さない | fw-p4に戻り、変更理由をコードブックの変更履歴に残す |
| セルの件数で結論を書く | 要約と元の発話で解釈する。数値化しない（[文献] Discussion） |

## 結果のまとめ方

研究質問とケースの定義 → 分析枠組み → 行列（要約と発話ID） → ケース間の共通点と違いの解釈 → 分析メモ → 限界。
