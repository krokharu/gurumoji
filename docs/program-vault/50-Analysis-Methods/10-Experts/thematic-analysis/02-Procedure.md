# テーマ分析の専門家：手順

段階IDは実行定義（[[50-Analysis-Methods/10-Experts/thematic-analysis/01-Expert]]）と一致させる。フェーズの名前は [[50-Analysis-Methods/20-Literature/LIT-oka-2022-reflexive-ta-ja|岡ほか 2022]] の訳語による。

## 分析の前に決めること

[文献] Braun & Clarke（2006、PDF p.6–9）は、分析の前に次を検討し、分析の過程で内省的に吟味するとする。

- 何をテーマとみなすか（研究質問に関してデータの重要な何かを捉え、一定のパターンを持つ意味を表すもの）
- データ全体の豊かな記述か、特定の側面の詳しい説明か
- 帰納的（ボトムアップ）か、理論的（トップダウン）か
- 意味的水準か、潜在的水準か
- 本質主義・実在論か、構築主義か

## 手順と各段階の確認事項

| 段階 | 内容 | 担当 | 確認事項 |
| --- | --- | --- | --- |
| ta-p1 | データに精通する | 研究者 | コーディングの前にデータセット全体を少なくとも1回読む。書き起こしは聞こえたとおりにし、言い淀みなどを取り除かない（[文献] 岡ほか 2022、p.149） |
| ta-p2 | コーディング | AI下書き＋研究者 | 研究質問に関わる特徴にコードを付ける（[文献] Braun & Clarke 2006のTable 1、岡ほか 2022） |
| ta-p3 | 初期テーマの生成 | AI下書き＋研究者 | 潜在的なテーマと関連するコード化データをすべて抽出したら終える。名称は2018年に「テーマの検索」から変更された（[文献] 岡ほか 2022、p.152） |
| ta-p4 | テーマの開発とレビュー | 研究者 | 開発中のテーマを、コード化したデータとデータセット全体に照らして確認・再検討する（[文献] 岡ほか 2022、p.152） |
| ta-p5 | テーマの磨き上げ、定義と命名 | 研究者 | 各テーマを詳しく分析して定義し、名前を付ける（[文献] 岡ほか 2022、p.152） |
| ta-p6 | 報告書の作成 | 研究者 | 主要なテーマに沿って、分析のストーリーとデータを織り合わせる（[文献] 岡ほか 2022、p.153） |

## 判断に迷いやすい点

- [文献] テーマの数に公式の規定はないが、一般に8000語の英語論文で2〜6個のテーマを報告している（岡ほか 2022、p.152）。数を目標にしない（[整理]）。
- [文献] 再帰的TAでは、評定者間の信頼スコアを出すための研究チームは必須ではなく、質を保つためにも望ましくないとされる（岡ほか 2022、p.147）。複数の研究者で分析する場合も、一致率ではなく解釈の吟味として位置づける（[整理]）。
- [整理] AIの初期コード・テーマの候補は、研究者の読み込み（ta-p1）の代わりにならない。候補は、研究者が見落とした箇所を確かめる材料として使う。

## 典型的な失敗と修正

[文献] Braun & Clarke（2006、PDF p.18–19）と岡ほか（2022、p.154–156）が挙げる落とし穴に対応させる。

| 失敗 | 修正 |
| --- | --- |
| 抜粋を並べるだけ、内容を言い換えるだけで分析していない | テーマごとに、データが何を意味するかの解釈を書く |
| インタビューガイドの質問をそのままテーマにしている | 質問への回答の集まりではなく、データセットを横断する意味のパターンに戻って検討する |
| テーマが機能していない（重なりが多い、一貫しない、例が少ない） | テーマの開発とレビュー（ta-p4）に戻り、統合・分割・破棄を行う |
| データと主張が一致しない | 抽出したデータがテーマを裏付けているかを繰り返し確認する |
| 理論や研究質問とTAの形が一致しない | 分析前の判断と採用したTAの形を見直す |

## 結果のまとめ方

1. 研究質問、分析前の判断、採用したTAの形
2. テーマの一覧（定義と名前）
3. テーマごとの分析の語りと、データの抜粋（発話ID）
4. テーマ間の関係
5. 品質確認の記録（[[50-Analysis-Methods/10-Experts/thematic-analysis/03-Quality]]）と限界
