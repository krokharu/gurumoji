# 大谷（2011）：SCAT: Steps for Coding and Theorization

## 研究目的

量的研究者を主な読者に想定して、明示的な手続きで着手しやすく、小規模データにも適用できる質的データ分析手法SCATを、新しい分析例を使って解説する（p.155）。

## 対象データと研究条件

分析例として、良く切れる包丁を初めて使ったときの経験を調理師に尋ねた面接の逐語を使う（p.156–157の表）。

## 分析手順の要約

- セグメント化したテクストをマトリクスに書き込む。セグメント化の適切さは分析結果に影響し、目安は一つのセグメントに大きく一つのトピックが入るようにすること（4.2節、p.158）。
- 各セグメントに次の順でコードを付ける（p.155、p.157–158）。
  - 〈1〉テクスト中の注目すべき語句
  - 〈2〉それを言いかえるテクスト外の語句
  - 〈3〉それを説明するようなテクスト外の概念。〈2〉の示すものの背景、条件、原因、結果、影響、比較、特性、次元、変化などを検討して付ける
  - 〈4〉前後や全体の文脈を考慮して浮き上がるテーマ・構成概念
  - 〈5〉分析の過程で得た疑問・課題。〈4〉を書いた後でなくてもよい（4.7節）
- 〈3〉〈4〉のコードが句になる場合は、中核的な語を「」で囲むなどするとよい（p.158）。
- 〈4〉のテーマ・構成概念を紡いでストーリーラインを書く。ストーリーラインで使った〈4〉のコードには下線を引き、漏れがないことを確認するよう勧める（4.8節、p.159）。
- 〈1〉〜〈4〉のコーディングはデータの部分に着目した「脱文脈化」であり、〈4〉からストーリーラインを紡ぐ作業は「再文脈化」だとする（p.159）。
- ストーリーラインを断片化して理論記述を行う。ここでの理論は普遍的な原理ではなく「このデータから言えること」だとする（p.159）。
- 〈5〉をまとめ、ストーリーラインや理論記述を書く中で生じた疑問も加えて「さらに追究すべき点・課題」を書く（4.10節、p.159）。
- データから研究を発展させて論文化する際は、分析の根拠となる「概念的枠組み」が必要だとする（p.158、4.10節）。
- 分析の順序は、〈1〉から〈4〉を縦方向に進めても1行ずつ横方向に進めてもよい。ただし〈1〉は全体を見て先にすべて書き出すのがよいとする（書き出した後の修正は可）（5.1節、p.159–160）。
- 1〜2行程度の短い回答が多数ある場合は、一つの回答を一つのセグメントとみなす福士・名郷（2011）の活用法が有効とする（p.160）。

## 主要な知見

SCATは、一つだけのケースのデータやアンケートの自由記述など、比較的小規模の質的データの分析にも有効で、明示的・定式的な手続きを持つため初学者も着手しやすいとする（p.155）。

## 適用上の注意と限界

- 著者は対比として、グラウンデッド・セオリーは大量のデータ採取と長い研究期間を要し、ごく小規模のデータや既に採取したデータには適用できないと述べる（p.155）。
- すぐれた分析には、関連文献を参照しながら分析を見直すことが必要で、示した例はその最初の段階だとする（p.158）。
- 連載記事であり、査読の有無は確認していない。

## 専門家の判断・手順に反映する内容

- [[50-Analysis-Methods/10-Experts/scat/01-Expert|SCATの専門家]]：〈1〉〜〈5〉、ストーリーライン、理論記述、さらに追究すべき点・課題を手順の段階IDとして定義する。
- 品質確認：ストーリーラインで〈4〉のコードがすべて使われたか（下線による確認）、セグメントが一つのトピック単位か、概念的枠組みと文献の参照があるか。
- 禁止事項：理論記述を普遍的な法則として示さない。
- 適用条件：小規模データでも使えるが、セグメント化と各段階のコーディングは分析者の作業であり、AIや自動処理で置き換えたものをSCATの実施とは表示しない（[実装判断]）。
