# AIが担う範囲と禁止事項

専門家定義は、LLMを再学習させるものではない。保存した専門家定義と知識ノートを実行時に読み込み、手順・判断基準・禁止事項に沿って処理と説明を制御する仕組みである。人格の分離とモデルの分離は別であり、同じモデルでも、読み込む定義・入力・出力・実行状態を専門家ごとに分ける。

## 実行時の読み込み

1. 分析設定の「主となる分析手法」と、既存の分析方針（`build_focus_group_analysis_plan`）が補助として挙げた手法から、専門家を選ぶ。全専門家を毎回読み込まない。
2. 選んだ専門家の `01-Expert.md` の実行定義を読み、適用条件をコードで判定する。
3. AIを使う操作（AI見解の生成）では、選んだ主の専門家の短い指示文（`ai_assist.brief`）だけをプロンプトに入れる。知識ノート全体・文献本文・他の専門家の定義は入れない。
4. AIの出力には、手順の段階ID（`method_step`）と方法論の根拠ID（`basis_ids`）を必須にする。どちらも専門家定義に登録されたIDだけを許可し、サーバーで検証する。存在しない文献IDは保存しない。文献ノートが見つからない文献IDは根拠として許可せず、AI下書きの段階の根拠がすべて見つからない場合は生成しない。

実装：`src/gurumoji/method_experts.py`、`analysis_insights.create_ai_insights`。

## AIに任せてよいこと・いけないこと

| してよい | してはいけない |
| --- | --- |
| 専門家定義で `actor: ai_draft` とした段階の候補を、発話IDを付けて出す | 研究者の段階（例：テーマの確定、概念の生成、KJ法のグループ編成）を実施済みとして出す |
| 候補ごとに、該当する手順の段階と方法論の根拠IDを示す | 元データにない発言・話者・時刻・数値を作る |
| 反例・少数意見・確認すべき点を候補として挙げる | 頻度を重要性や支持人数として述べる、有意差や信頼性係数を推定で書く |
| 文献と専門家定義の範囲で手順を説明する | 文献IDを作る、文献に書かれていない手順を文献の記述として書く |

AIの出力は研究者のコード・注釈・メモへ自動で反映しない（[[40-Design/method-rules]] の `qualitative_coding`・`ai_insights`）。

## 手法ごとのAI補助の可否

可否と許可する段階の正本は、各専門家の `01-Expert.md` の `ai_assist`。ここには要約だけを置く。

| 専門家 | AI補助 | 理由の要約 |
| --- | --- | --- |
| 質的内容分析 | 限定（カテゴリー候補） | カテゴリー定義・適用規則の確定は研究者 |
| テーマ分析 | 限定（初期コード・パターン候補） | 再帰的テーマ分析では研究者の主観的な関与が分析の中心 |
| フレームワーク法 | 限定（行列セルの要約候補） | 枠組みの作成と解釈は研究者 |
| SCAT | 限定（<1>の注目語句と<5>の疑問の候補） | <4>の構成概念、ストーリーライン、理論記述は分析者 |
| M-GTA | 限定（概念候補と反対例の確認点） | 概念生成は分析テーマと分析焦点者に沿った研究者の解釈 |
| KJ法 | 使わない | ボトムアップのグループ編成を、類似度による自動分類で置き換えない |
| フォーカスグループの相互作用分析 | 限定（相互作用の候補となる発話の組） | 応答の意味の確定は研究者 |
| 計算系の専門家 | 使わない | 計算はコードで行い、説明は定義から決定的に作る |

## トークンと送信先

- AIの呼び出しは、利用者が明示的に押すボタン（AI見解の生成）からだけ行う。統計の計算・保存・Vault出力ではAIを呼ばない（[[40-Design/decisions]] のADR-111）。
- プロバイダーとモデルは既存のAI設定（OpenAI、Google Gemini、LM Studio）に従う。専門家化のために、より高コストなモデルや外部APIへ切り替えない。
- 実行時にWeb検索はしない。文献の調査は開発時の作業として行い、結果を文献ノートに保存する。

## LLMによる注釈の評価についての文献

- [文献] ツイートとニュース記事の4つのサンプル（n = 6,183）で、関連性・立場・話題・フレームの判定について、ChatGPTのゼロショットの正確さがクラウドワーカーを平均で約25ポイント上回ったと報告した研究がある（[[50-Analysis-Methods/20-Literature/LIT-gilardi-2023-llm-annotation|Gilardi et al. 2023]]、要旨確認）。日本語のグループインタビューの分析や解釈を検証したものではない。
- [実装判断] したがってAIの出力は候補・下書きとして扱い、研究者の確認を必須にする。
