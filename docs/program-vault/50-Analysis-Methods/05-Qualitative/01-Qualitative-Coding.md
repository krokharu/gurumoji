# 手動コード・重要引用（`qualitative_coding`）

## 実装契約

コードブックはID、ラベル、定義、含める例、除外する例、カテゴリー、テーマ、色を持つ。研究者は発話ごとに複数コード、発話のきっかけ（自発／働きかけ）、相互作用タグ、対象発話への根拠リンク、重要引用、メモ、除外を保存できる。出力は分析方針・データ確認、全発話と分析結果の対応表、コード一覧、コードブック変更履歴、コード済み発話、話者×コード行列、相互作用集計、根拠発話リンク、重要引用、研究質問・役割・コードブック等の`context_checks`である。編集で発話IDが失われた注釈は孤立データとして保持し、静かに消さない。

## オーケストレーターの判断

- 新しいコード、定義変更、統合・分割、再コーディングは人の承認が必要。コード名だけで既存注釈を自動移行しない。
- 各解釈に支持発話だけでなく、反例・未コード・除外・孤立注釈の状況を返す。
- コーディング単位、研究者、日付、コードブック版、変更理由、二重コーディングの有無、合意手順を保存する。コード頻度をテーマの重要度と読まない。

## 言えないこと

コードは分析者が定義したレンズであり、発話に唯一の正解ラベルがあることを意味しない。相互作用タグも会話の意味を自動確定しない。

## 査読文献

- [Braun & Clarke (2006)](https://doi.org/10.1191/1478088706qp063oa) はテーマ分析を柔軟な質的手法として説明し、データへの精通、初期コード、テーマ候補、見直し、定義、報告という反復的な工程を示す。
- この実装はテーマ分析を自動実行しない。コードブック、原文、反例、研究者メモを保存できるようにする土台である。

## 専門家定義との関係

手動コードは手法ではなく、質的分析の各専門家（質的内容分析、テーマ分析、フレームワーク法、SCAT、M-GTA、KJ法、相互作用分析）が共通に使う記録の道具のため、専用の専門家を置かない（[[50-Analysis-Methods/10-Experts/00-Index]]）。
