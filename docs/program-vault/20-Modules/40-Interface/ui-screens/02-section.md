# Web UIの画面構成と既存機能の対応：画面とURL

親索引・状態・確認版：[[20-Modules/40-Interface/ui-screens/00-Index]]。必要な本文だけを取得する。

## 画面とURL

上部バーの4入口（動画・音声を文字起こし／文字起こし結果／分析・可視化／話者管理）で画面を切り替える。結果領域には互換の補助ナビ「データ一覧／分析・可視化」も残る。画面ごとにハッシュを持ち、再読み込み・ブラウザーの戻る・ブックマークで同じ画面に戻る。

| 画面 | URL | 役割 |
| --- | --- | --- |
| 動画・音声を文字起こし | `#/new` | 3ステップ（ファイル → 設定 → 開始）と、処理中の進捗 |
| 文字起こし結果 | `#/data` | 一覧・検索・絞り込み、データグループの作成・割り当て・管理。カードを押すと作業画面を開く |
| データの作業画面 | `#/data/<id>` | 1件の確認・編集。見出しの下に「アウトライン（予定と結果）」、その下に4つのタブと保存バー |
| 分析・可視化 | `#/analysis`、`#/analysis/<id>` | 1件の分析。複数インタビューの比較は下部の折りたたみ |
| 分析の実行状況 | `#/analysis/<id>/run` | 統合した分析計画の段階、現在処理、進捗、ログ、中止。バックグラウンド移動時は分析チップから戻る |
| 話者管理 | `#/speakers` | 話者台帳・CSV・事前アンケート分析 |

旧URLも使える。`?view=new|library|speakers|analysis`、`?item=<id>`（分析）、`?section=`（分析の節）は初回表示で対応するハッシュへ置き換える。ObsidianのVaultに保存済みの `?view=analysis&item=…&segment=…` 形式の根拠リンクも従来どおり動く。

## 操作の流れ

1. **新規作成：** ファイルを選ぶ → 録音の種類を選ぶ → 「現在の設定」の要約を確認し、変えたい項目の「変更」だけを開く → 「内容を確認して開始する」で開始。詳細設定（認識・話者分離、単語登録、AI仕上げ、音声感情分析、出力形式）は初期状態で閉じている。
2. **処理中：** 新規作成画面にフォームの代わりに進捗を表示する。ほかの画面へ移ると、上部バーの処理状況チップだけが残る（押すと進捗へ戻る）。
3. **完了：** 新規作成画面を見ている場合は、そのデータの作業画面を開く。別の画面で作業している場合は開かず、チップを「文字起こしが完了 — 結果を開く」に変える。編集中のデータを置き換えない。
4. **確認・編集：** 作業画面の「発話の確認・編集」で音声を再生しながら修正し、下部の「編集内容を保存」で保存する。分析へは見出しの「分析・可視化 →」から進む。
5. **分析：** 「分析を実行」は発話量・会話時間構造の基礎pipeline。「手動実行」は4つの測定プリセット（文字数・発話時間・話者ID別度数・役割別度数）から、下書き保存→最大20件の固定試行→確認チェック→採用→全件実行の順で使う。簡単／詳細表示は自動／手動の実行方法とは独立し、表示切替では値や採用を変更しない。TransformerとAI見解は「内容・文脈検索」、発話分類は分類欄から個別実行する。実行中対象は表示中対象と分離し、完了応答で別データへ移動しない。根拠発話の音声は保存時と現在の本文・話者・有効時刻が一致する場合だけ再生する。

スマホ（959px以下）では、同じ3ステップを1ステップ1画面にし、下部の「戻る／次へ」で進む。デスクトップとスマホで別々のフォームや手順表示は持たない。
