# Web UIの画面構成と既存機能の対応

2026-09-16にWeb UIの構造を作り直した（作業ツリー、未コミット）。バックエンドのAPI・保存形式・分析処理は変えていない。判断の背景は [[40-Design/decisions#ADR-116 Web UIを画面単位のURLと3ステップの新規作成に作り直し、既存APIと要素IDを維持する]]、解消した問題は [[40-Design/ui-ux-issues]]。

2026-09-20の後続設計：多様な手法・実行結果を探す、比較する、追加分析へ渡すUI案を[[40-Design/core-handler-routing-reorganization-plan]]の図7に追加した。比較の保存履歴・成果物・Vault再試行（UX-33）は先行実装済みで、分析画面を「結果を見る／比較する／分析を組む／データ・出力」へ全面整理する部分は未実装（ADR-118）。以下は現行UIの説明として維持する。

2026-09-20に[[40-Design/analysis-execution-ux-plan]]のPhase 1〜2を実装した。分析実行の表示上の入口を「分析を実行」へ統合し、自動／手動の計画パネル、詳細設定、6段階の実行中画面、上部バーの分析チップ、バックグラウンド継続、中止を追加した。現段階は既存APIを画面側で順番に実行するため、永続pipelineとデータ待ちからの差分再開は後続Phase 3〜4である。

統計セクションは数値表だけでなく、記述統計の最小値・四分位・中央値・平均・最大値を示す分布図、カテゴリ別割合バー、統計検定の効果量バー、クロス集計の100%積み上げグラフを先に表示する。正確な値と前提条件を確認できるよう、従来の表は各グラフ直下の詳細表示に残す。

- **実装：** `src/gurumoji/templates/index.html`、`static/app.js`（`showView`、`routeHash`、`parseRouteHash`、`confirmLeave`、`setItemTab`、`openSettingsPanel`、`renderFlowSteps`、`updateJobChip`）、`static/analysis-execution.js`、`static/style.css`、`static/ai-effort.css`
- **検証：** `tests/test_ui_defaults.py`、`tests/test_browser_e2e.py`、`tests/test_content_browser.py`、`tests/test_machine_profile.py`

## 画面とURL

上部バーの3つのタブ（新規作成・処理済みデータ・話者管理）で画面を切り替える。処理済みデータ内では「データ一覧」と「分析・可視化」をサブタブで切り替える。画面ごとにハッシュを持ち、再読み込み・ブラウザーの戻る・ブックマークで同じ画面に戻る。

| 画面 | URL | 役割 |
| --- | --- | --- |
| 新規作成 | `#/new` | 3ステップ（ファイル → 設定 → 開始）と、処理中の進捗 |
| 処理済みデータ | `#/data` | 一覧・検索・絞り込み、データグループの作成・割り当て・管理。カードを押すと作業画面を開く |
| データの作業画面 | `#/data/<id>` | 1件の確認・編集。見出しの下に「アウトライン（予定と結果）」、その下に4つのタブと保存バー |
| 分析・可視化 | `#/analysis`、`#/analysis/<id>` | 1件の分析。複数インタビューの比較は下部の折りたたみ |
| 分析の実行状況 | `#/analysis/<id>/run` | 統合した分析計画の段階、現在処理、進捗、ログ、中止。バックグラウンド移動時は分析チップから戻る |
| 話者管理 | `#/speakers` | 話者台帳・CSV・事前アンケート分析 |

旧URLも使える。`?view=new|library|speakers|analysis`、`?item=<id>`（分析）、`?section=`（分析の節）は初回表示で対応するハッシュへ置き換える。ObsidianのVaultに保存済みの `?view=analysis&item=…&segment=…` 形式の根拠リンクも従来どおり動く。

## 操作の流れ

1. **新規作成：** ファイルを選ぶ → 録音の種類を選ぶ → 「現在の設定」の要約を確認し、変えたい項目の「変更」だけを開く → 「内容を確認して開始する」で開始。詳細設定（認識・話者分離、単語登録、AI仕上げ、音声感情分析、出力形式）は初期状態で閉じている。
2. **処理中：** 新規作成画面にフォームの代わりに進捗を表示する。ほかの画面へ移ると、上部バーの処理状況チップだけが残る（押すと進捗へ戻る）。
3. **完了：** 新規作成画面を見ている場合は、そのデータの作業画面を開く。別の画面で作業している場合は開かず、チップを「文字起こしが完了 — 結果を開く」に変える。編集中のデータを置き換えない。
4. **確認・編集：** 作業画面の「発話の確認・編集」で音声を再生しながら修正し、下部の「編集内容を保存」で保存する。分析へは見出しの「分析・可視化 →」から進む。
5. **分析：** 分析・可視化で対象を選び、「分析を実行」から自動実行または手動実行を選ぶ。詳細設定ではTransformer条件、AI実行先、Jev、既存結果の再利用を指定する。実行中は段階画面を表示し、別画面へ移動した場合は上部バーの分析チップから戻る。「文字起こしを開く」で同じデータの作業画面へ戻り、根拠発話の「音声で確認」→「見解・文脈検索に戻る」の往復は従来どおり。

スマホ（959px以下）では、同じ3ステップを1ステップ1画面にし、下部の「戻る／次へ」で進む。デスクトップとスマホで別々のフォームや手順表示は持たない。

## 既存機能の移動先

| 既存機能 | 旧画面の場所 | 新しい場所 |
| --- | --- | --- |
| APIトークンの状態、使用モデルの選択 | ヒーロー右側のトークンパネル、スマホは新規作成ヘッダー | 上部バーのトークン表示（1321px以上）と「接続と処理装置」ダイアログ |
| マシン診断、CPU/GPUの利用可否 | ヒーロー、認識設定のマシン診断、スマホヘッダーの3か所 | 「接続と処理装置」ボタンのCPU/GPU表示とダイアログ。自動設定の内容は「認識・話者分離」の先頭 |
| 会話モード（会議／グループインタビュー／雑談） | 新規作成01 | ステップ2「設定を確認する」の先頭 |
| ファイル選択、ドラッグ＆ドロップ、パス・保存先 | 新規作成02 | ステップ1。パス・保存先は折りたたみ |
| 認識モデル、言語、前処理、小声対策、詳細処理、処理装置、話者数、VAD | 新規作成03（詳細設定の一部は常時表示） | ステップ2の「認識・話者分離」パネル（閉じた状態） |
| 単語登録 | 新規作成03（常時表示） | ステップ2の「単語登録」パネル |
| AI仕上げ、Obsidianで仕上げ、思考モードとエフォート | 新規作成04（エフォートは常時表示） | ステップ2の「AI仕上げ」パネル。エフォートはその中の折りたたみ |
| 音声感情分析 | 新規作成05 | ステップ2の「音声感情分析」パネル |
| 出力形式（SRT、字幕付き動画） | 新規作成06 | ステップ2の「出力形式」パネル |
| 開始、設定要約 | 開始バー、左ナビの要約、スマホの確認一覧 | ステップ3「内容を確認して開始する」 |
| 進捗、トークン使用量、システム使用状況、処理ログ、中止 | どの画面でも表示される進捗カード | 新規作成画面の進捗カード。ほかの画面では上部バーのチップ |
| 処理済みデータ一覧 | 上部バー「処理済みデータ」 | 「処理済みデータ」内のサブタブ「データ一覧」 |
| 分析・可視化、比較 | 上部バー「分析・可視化」 | 「処理済みデータ」内のサブタブ「分析・可視化」 |
| データグループの作成・割り当て・グループ順表示 | なし（新規） | 「処理済みデータ」のグループ管理、カードのグループ選択、絞り込み・並べ替え |
| 発話の再生・編集・追加・削除、絞り込み | 1ページの結果画面の下部 | 作業画面「発話の確認・編集」。デスクトップはプレイヤーを左に固定 |
| 会話プロファイル、会話話者連携、話者名のAI再特定、会話話者CSV | 結果画面の中段 | 作業画面「会話・話者」 |
| 会議議事録・タスク、アウトライン、感情の要約、AIトークン使用量 | 結果画面の上段 | 作業画面「議事録・アウトライン」 |
| 予定した議題（質問ガイド）と、実際に話された内容の時間順一覧 | なし（新規） | 作業画面の見出し直下「アウトライン（予定と結果）」。折りたたみ可。要点は「議事録・アウトライン」タブ |
| ダウンロード、実行フォルダー、データの削除 | 結果画面の見出し、下部の危険操作エリア | 作業画面「ファイル・管理」 |
| 編集内容を保存、Obsidianで仕上げ | 固定バー（一覧へ戻る・分析と同居） | 作業画面下部の保存バー（2つだけ） |
| 一覧へ戻る、分析・可視化、話者管理への移動 | 関連画面ナビと固定バーの2か所 | 作業画面の見出し（「← 処理済みデータ」「分析・可視化 →」）と上部バー |
| 空のデータを追加、話者管理、事前アンケート分析 | 変更なし | 変更なし |

## 互換性として維持したもの

- APIの呼び出し、送信するフォーム項目名（`name` 属性）、保存・編集・分析のリビジョン確認は変更していない。
- `processed-data-hub`、`show-library-list-button`、`show-library-analysis-button`を処理済みデータ内のサブナビとして再導入した。従来の分析実行要素は既存スクリプトとの互換用に非表示で残し、表示上の実行入口は`analysis-execution.js`へ統合した。
- ブラウザー保存：`sessionStorage` の `gurumoji.activeJobId`、`gurumoji.pendingSubmission`、`gurumoji.bootSplashSeen`、`localStorage` の `gurumoji.ai-efforts` は同じキーで読む。
- 未保存の確認（文字起こし、話者管理、分析設定・準備記録）は、タブ・戻る操作・作業画面からの移動のすべてで `confirmLeave` を通る。

## 実装上の注意

- 実行中ジョブのID（`activeJobId`）と表示中のデータのID（`currentJobId`）を分けた。処理中に別のデータを開いて保存しても、ジョブの進捗・中止と混ざらない。
- スマホの固定バーが画面下に付くよう、`.app-main` の登場アニメーションは不透明度だけにしている。`transform` を使うと固定バーの基準がカードになる。
- 上部バーの高さは `--app-bar-height` で管理し、分析の固定ナビ・スクロール位置はこの値から計算する。
