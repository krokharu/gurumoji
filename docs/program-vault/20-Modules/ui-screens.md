# Web UIの画面構成と既存機能の対応

2026-09-16にWeb UIの画面構造を作り直し、当時の版`2f13f98`に収録した。画面は同じAPI・保存形式を使う。2026-09-25にはHTMLを`templates/views/`の画面別テンプレートへ分けた。判断の背景は [[40-Design/decisions#ADR-116 Web UIを画面単位のURLと3ステップの新規作成に作り直し、既存APIと要素IDを維持する]]、解消した問題は [[40-Design/ui-ux-issues]]。

2026-09-20の後続設計：多様な手法・実行結果を探す、比較する、追加分析へ渡すUI案を[[40-Design/core-handler-routing-reorganization-plan]]の図7に追加した。比較の保存履歴・成果物・Vault再試行（UX-33）は先行実装済みで、分析画面を「結果を見る／比較する／分析を組む／データ・出力」へ全面整理する部分は未実装（ADR-118）。以下は現行UIの説明として維持する。

**導入履歴（2026-09-20）:** [[40-Design/analysis-execution-ux-plan]]のPhase 1〜2で、自動／手動の計画パネル、当時の6段階実行画面、分析チップ、バックグラウンド継続、中止を追加した。当時のブラウザー逐次実行の説明は、以下の現行M0〜M7実装とは区別する。

**現行コードの照合（2026-10-02、HEAD `ddc23abe`／直近実装 `59ebd24`）:** `analysis_core.py`と`analysis_pipeline.py`はM0〜M7の要求・段階・状態をサーバー側で永続化し、`static/analysis-execution.js`はpipelineの作成・状態取得・中止・再試行APIへ接続する。分析内の表示モードは「自動分析／設定・手動分析／手法別」。初回範囲は参加・会話時間構造の記述集計、手動測定、固定JSON/CSV/ZIPなどで、47成果物・全LLM役割・推測統計・静止画像・SAV等の提供を意味しない。詳しい導入範囲は[[40-Design/analysis-milestone-visualization-design]]の第18.7節と現行`CAPABILITIES`を照合する。基礎pipelineとTransformer・AI見解等の個別分析、外部AIを使う計画相談は別の入口・能力として扱う。

この照合はコードと既存の隔離検証に基づく。現行版の実画面・AT受入を済ませた意味ではない。手動定義の版整合や個別分析入口の不整合は[[40-Design/ui-design-implementation-plan]]のW01/W02と証拠表を参照し、永続化の存在だけから版保証・操作可能性を合格にしない。

統計セクションは数値表だけでなく、記述統計の最小値・四分位・中央値・平均・最大値を示す分布図、カテゴリ別割合バー、統計検定の効果量バー、クロス集計の100%積み上げグラフを先に表示する。正確な値と前提条件を確認できるよう、従来の表は各グラフ直下の詳細表示に残す。

2026-09-22に[[40-Design/video-ui-redesign-plan]]（UX-35〜UX-42）を実装した。動画確認画面（`#/data/<id>`）の動画プレビュー幅を380〜480pxに拡大、動画枠の配色をライトカードに統一、発話リストを通常時コンパクト（チャット風タイムライン）・選択時フル展開に変更、再生中のハイライトと自動追従トグルを追加した。新規処理中画面（`#/new`）の進捗表示から計器・ログをアコーディオンに格納し、視覚的ノイズを削減した。

- **実装：** `src/gurumoji/templates/views/result.html`・`views/create.html`（処理中カード）、`static/app.js`（`renderMedia`、`syncMediaPlayback`、`renderSegments`、`playSegment`）、`static/style.css`（`.transcript-layout`、`.media-review`、`.segment`、`.progress-details-accordion`）
- **検証：** `tests/test_ui_defaults.py`、`tests/test_session_outline.py`、`tests/test_meeting_minutes.py`、`tests/test_speaker_registry.py`、`tests/test_transcript_formatting.py`、`tests/test_launcher.py`、`tests/test_application_lifecycle.py`


## 画面とURL

上部バーの4入口（動画・音声を文字起こし／文字起こし結果／分析・可視化／話者管理）で画面を切り替える。結果領域には互換の補助ナビ「データ一覧／分析・可視化」も残る。画面ごとにハッシュを持ち、再読み込み・ブラウザーの戻る・ブックマークで同じ画面に戻る。

| 画面 | URL | 役割 |
| --- | --- | --- |
| 動画・音声を文字起こし | `#/new` | 3ステップ（ファイル → 設定 → 開始）と、処理中の進捗 |
| 文字起こし結果 | `#/data` | 一覧・検索・絞り込み、データグループの作成・割り当て・管理。カードを押すと作業画面を開く |
| データの作業画面 | `#/data/<id>` | 1件の確認・編集。見出しの下に「アウトライン（予定と結果）」、その下に4つのタブと保存バー |
| 分析・可視化 | `#/analysis`、`#/analysis/<id>` | 1件の分析。複数インタビューの比較は下部の折りたたみ |
| 分析の実行状況 | `#/analysis/<id>/run` | 統合した分析計画の段階、現在処理、進捗、ログ、中止。バックグラウンド移動時は分析チップから戻る |
| 話者管理 | `#/speakers` | 話者台帳・CSV・事前アンケート分析 |

旧URLも使える。`?view=new|library|speakers|analysis`、`?item=<id>`（分析）、`?section=`（分析の節）は初回表示で対応するハッシュへ置き換える。ObsidianのVaultに保存済みの `?view=analysis&item=…&segment=…` 形式の根拠リンクも従来どおり動く。

## 操作の流れ

1. **新規作成：** ファイルを選ぶ → 録音の種類を選ぶ → 「現在の設定」の要約を確認し、変えたい項目の「変更」だけを開く → 「内容を確認して開始する」で開始。詳細設定（認識・話者分離、単語登録、AI仕上げ、音声感情分析、出力形式）は初期状態で閉じている。
2. **処理中：** 新規作成画面にフォームの代わりに進捗を表示する。ほかの画面へ移ると、上部バーの処理状況チップだけが残る（押すと進捗へ戻る）。
3. **完了：** 新規作成画面を見ている場合は、そのデータの作業画面を開く。別の画面で作業している場合は開かず、チップを「文字起こしが完了 — 結果を開く」に変える。編集中のデータを置き換えない。
4. **確認・編集：** 作業画面の「発話の確認・編集」で音声を再生しながら修正し、下部の「編集内容を保存」で保存する。分析へは見出しの「分析・可視化 →」から進む。
5. **分析：** 「分析を実行」は発話量・会話時間構造の基礎pipeline。「手動実行」は4つの測定プリセット（文字数・発話時間・話者ID別度数・役割別度数）から、下書き保存→最大20件の固定試行→確認チェック→採用→全件実行の順で使う。簡単／詳細表示は自動／手動の実行方法とは独立し、表示切替では値や採用を変更しない。TransformerとAI見解は「内容・文脈検索」、発話分類は分類欄から個別実行する。実行中対象は表示中対象と分離し、完了応答で別データへ移動しない。根拠発話の音声は保存時と現在の本文・話者・有効時刻が一致する場合だけ再生する。

スマホ（959px以下）では、同じ3ステップを1ステップ1画面にし、下部の「戻る／次へ」で進む。デスクトップとスマホで別々のフォームや手順表示は持たない。

## 互換性として維持したもの

- APIの呼び出し、送信するフォーム項目名（`name` 属性）、保存・編集・分析のリビジョン確認は変更していない。
- `processed-data-hub`、`show-library-list-button`、`show-library-analysis-button`は処理済みデータ内の補助ナビ。基礎pipelineは`analysis-execution.js`、個別Transformer／AI見解は`analysis-content.js`、発話分類は`analysis-method-view.js`。個別入口は可視化し、aria-hiddenの旧再集計buttonだけ非表示を維持する。
- ブラウザー保存：`sessionStorage` の `gurumoji.activeJobId`、`gurumoji.pendingSubmission`、`gurumoji.bootSplashSeen`、`localStorage` の `gurumoji.ai-efforts` は同じキーで読む。
- 未保存の確認（文字起こし、話者管理、分析設定・準備記録）は、タブ・戻る操作・作業画面からの移動のすべてで `confirmLeave` を通る。

## 実装上の注意

- 実行中ジョブのID（`activeJobId`）と表示中のデータのID（`currentJobId`）を分けた。処理中に別のデータを開いて保存しても、ジョブの進捗・中止と混ざらない。
- スマホの固定バーが画面下に付くよう、`.app-main` の登場アニメーションは不透明度だけにしている。`transform` を使うと固定バーの基準がカードになる。
- 上部バーの高さは `--app-bar-height` で管理し、分析の固定ナビ・スクロール位置はこの値から計算する。


## 2026-10-03 分析UIの安全境界（V1/V2実装、V3以降は未受入）

- 実装checkpoint: `d3694b8`（基点`b02275b`、backend契約`9768b80`）。失われた旧ソースの復元ではなく新規修正。
- 分類・検索・相談・開始・取消・poll・再試行はitem/data/navigation/入力revision/編集世代とrequest所有者を照合。同itemの検索語・送信先・Transformer条件は保持するが、古い結果・loading・errorは新contextへ持ち込まない。
- 試行表は返された固定行をそのまま表示し、現在の本文・音声時刻を補完しない。採用には完全な`expected_trial`、全件実行には採用版mapと試行input hashを送る。採用版の編集は別IDの下書き。応答不明の採用はGET確認より前に再PUTしない。
- 4保存先はResearch/Input/Orchestrator/Visualization。非空API targetsは従来の3target集合で、Researchを含む4writerの実行証拠を別に表示する。legacyの証拠欠落は不明。package欠落・不整合／blocked recoveryでは再計算や不可用なretryを案内しない。
- `tests/test_analysis_ui_safety.py`はNode合成DOM・遅延fetch試験と実backendの4preset計算を束ねる。実データ、外部AI、モデル推論、ブラウザー、音声再生は使わない。固定checkpointの詳細証拠はクラウド作業領域`artifacts/eight-hour-20261003/analysis-ui`、独立確認は同`ui-review`。
- V3実画面・pointer/keyboard、AT、利用者理解・見た目の評価はブラウザー制約で未実施。非表示解除と合成DOM成功を通常操作のUI受入に読み替えない。


## 保存済み自律分析の履歴・スライド（2026-10-04追加）

分析画面と自律分析dialogの「分析の履歴と根拠」が専用read-only viewerを開く。会話内run、初期/最新/過去のラベル版、時系列フィルター、保存結果・Core判断・採否・固定原文を同じ文脈で表示する。`static/analysis-history.js/.css`、`templates/views/analysis-history.html`、`services/analysis_history.py`が担当する。

「スライド」は別の明示保存操作を持つ。設計確認→VisualizationVaultへの設計/prompt保存→固定版プレビュー→編集可能PPTXの順。閲覧では保存・AI呼出しを行わない。`services/analysis_slides.py`、`analysis_slide_templates.py`、`web/analysis_slides_routes.py`へ接続する。詳しい境界は[[40-Design/analysis-history-viewer]]。
