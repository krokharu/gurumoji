# Gurumoji UI設計指針：3 守る実装契約

親索引・状態・確認版：[[40-Design/30-Interface/ui-design-contract/00-Index]]。必要な本文だけを取得する。

## 3 守る実装契約

1. 既存API、ID、フォーム名、URL、revision確認、保存経路を再利用する。React/Tailwind移行、全画面生成、別状態ストアはこの計画の前提にしない
2. 実行中対象と編集中対象を分離する。処理完了で別の編集中データを置き換えない。未保存確認、競合draft退避、削除Undo、CSVのpreview→適用→通常保存を保つ
3. 発話ID・生成時本文・話者・時刻・入力revision/hash・run IDを保持する。古い結果に現在の来歴を補わず、不明は不明とする。古い引用を現在音声へ黙って接続しない
4. 欠測、未実行、失敗、計算済みゼロを分ける。図・表・出力の対象集合、分母、除外理由を一致させる。観測話者数と実参加人数を混同しない
5. AI下書き、研究者編集、研究者確認を分ける。実行成功・schema合格を科学的妥当性や研究者の採用に置き換えない。頻度・感情・発話量から重要性・合意・内面を自動断定しない
6. 閲覧・検索・比較結果を開く操作は、新しい推論や外部送信を暗黙に始めない。基礎pipeline、計画相談、個別分析の能力と送信先を別々に説明する。AI見解は発話・話者名／役割・研究質問だけでなくコードと重要フラグ、設定時には専門家の短い説明・手順情報も送る。計画相談には入力した目的文を送るため、そこへ貼った本文まで「送らない」と保証しない
7. 研究者所有ノートの本文・タグ・別名を再生成しない。生成ノートは既存の履歴保護経路を通す。SQLは追加のみ。保存形式・移行変更はバックアップ／dry run／復旧を設計してから行う

根拠: [AGENTS.md](../../../../../AGENTS.md)、[詳細開発規則](../../50-Governance/ai-development-rules.md)、DG-01/02/06、UX:S01/UX:S15/UX:S17/UX:S20。文献の一般知見と既存契約は別の根拠として使う。

## 4 情報構造と主要フロー

上部4入口と `#/new`、`#/data`、`#/data/<id>`、`#/analysis/<id>`、`#/speakers`、既存の根拠queryリンクを保つ。新規作成はファイル→設定→開始、1データは発話編集／会話・話者／議事録・アウトライン／ファイル・管理を維持する。

分析内は当面、現在の各結果部品をそのまま使い、正しい実行入口・現在地・版を補う。次にADR-118の「結果を見る／比較する／分析を組む／データ・出力」を小さい単位で評価する。手法は結果の分類、手動コードは解釈作業として扱い、手動測定と同じ意味の「手動」へまとめない。旧入口は移行中の戻り口として残し、同じ結果を二重描画しない。

| 研究者の仕事 | 常に見える文脈 | 完了の意味 |
|---|---|---|
| 原音を確認して直す | 対象・未保存・選択発話・再生位置 | 指定版の保存成功。人の確認状態は別 |
| 結果から根拠へ往復 | run／入力版・選択引用・前後文脈 | 同じ結果・filter・位置・focusへ戻れる |
| 測定を定義する | 入力列・規則・型・尺度・出力単位・対象 | 試行値を見て明示採用した定義版が固定される |
| 分析を待ち回復する | 対象・工程・状態・最後の取得時点 | 計算／保存／Vault書出しそれぞれの結果が分かる |
| 比較して出力する | 比較集合・条件・分母・親run | 表示と同じ固定結果・来歴を持つ出力 |

根拠: DG-05/06、[ADR-118](../../50-Governance/decisions/00-Index.md)、UX:K01/UX:K02/UX:K05/UX:K09/UX:K13。優れた情報構造であるとの実証は今後行う。
