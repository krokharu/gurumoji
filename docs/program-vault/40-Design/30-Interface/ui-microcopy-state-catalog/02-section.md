# Gurumoji 日本語UI文言と状態の仕様案：3 状態ごとの短い文と許可操作

親索引・状態・確認版：[[40-Design/30-Interface/ui-microcopy-state-catalog/00-Index]]。必要な本文だけを取得する。

## 3 状態ごとの短い文と許可操作

以下は表示adapterの提案。UI上の語彙であり、backendに新しい状態を保存する要求ではない。`ready`は全体実行statusにはなく、開始前の確認と個別工程で扱われる。実行の可否は実際の検証結果・API応答に従う。

| 状態と確認条件 | 見出し・補助文の例 | 許される操作と停止条件 |
|---|---|---|
| 開始前の確認中 | 「開始条件を確認しています」 | 設定の閲覧・閉じる。開始可と表示しない |
| ready相当 | 「開始できます」＋残るモデル読込条件があれば隣接表示 | 対象・未保存・必要設定・確認項目が揃った場合だけ開始。推論成功は保証しない |
| accepted | 「開始待ち」 | `cancel`がある場合だけ「中止を依頼」。受付済みを計算開始済みにしない |
| running | 「分析中」＋「処理：{工程名}」 | `cancel`がある場合だけ中止。画面を離れる操作は処理中止と分ける |
| waiting | 「分析が待機しています」＋取得した理由 | `retry_publication`なら「Vaultへの保存を再試行」、`retry_failed`なら「失敗した処理を再試行」。両方なければ「設定を見直す」等、実際にできることだけ。待機理由不明ならそのまま示す |
| failed | 「分析が停止しました」＋「{確認できた原因}」 | 現行は許可操作が空なので同じ実行の再開を約束しない。設定確認は可。別の分析開始は対象・条件の再確認を伴う。確認できた保存物への読取入口は保持 |
| 中止要求の送信中 | 「中止を依頼しています」 | 重複送信を防ぐ。送信済み・受付済み・中止済みと言わない |
| cancelling | 「中止の完了を待っています」 | 再中止ボタンは無効。サーバーのterminal応答まで完了表示をしない。現行`active`は取消可能性から計算されるため、`active=false`を停止証拠にしない |
| cancelled | 「分析を中止しました」 | 保存済みを確認できた結果だけ開く。「すべて元に戻しました」は不可 |
| completed | 「分析が完了しました」 | 表示対象run・計算・本体保存・選択Vaultの状態を別に明示。「結果を見る」が現在データを開く間は固定runを開くと約束しない |
| 編集の保存中 | 「変更を保存しています」 | 二重送信を防ぐ。保存中に追加した編集は別の未保存状態として保持 |
| save conflict | 「別の更新があるため保存できません」 | 現行の退避機能がある画面では「未保存内容をダウンロード」→「最新の内容を開く」。無断上書き、退避前の自動再読込は禁止 |
| stale | 「保存後にデータが更新されています」 | 保存時の結果を保持。再分析は別操作。差分がないか確認できなければこの状態に決めつけない |
| unknown | 「最新の状態を確認できません」＋「最後の確認 {時刻}：{状態}」 | 前回状態は過去のものと明記。再取得の副作用を確認してから再取得。成功・失敗・中止を推測しない |
| missing | 「値なし」または「欠測：{確認できた理由}」 | 計算対象・理由・根拠が取れるときだけ確認先を示す。測定できなかった値を0にしない |
| zero | 「0秒」など数値と単位、必要なら「集計に含む」 | 有効な入力から算出した0だけ。平均の分母へ含めるかはその計算法に従う |
| inaccessible run/artifact | 「保存済み結果を開けません」＋取得できた理由 | 同じ結果の再取得、確認できる別ファイル、履歴へ戻る。現在値への自動置換・再計算・新規実行は禁止。404だけで削除やアクセス権不足と断定しない |

根拠コード: `analysis_core.py:19–30,42–76`、`analysis_pipeline.py:752–812,823–845`、`analysis-execution.js:302–327,393–476,524–539,602–636`。工程の完了割合は`analysis_pipeline.py:792–812`の成功終端数に基づく。処理時間の割合ではなく、対象外工程も成功終端へ含む。出すなら「工程の完了 {p}%」とし、残り時間へ換算しない。
