# Gurumoji 日本語UI文言と状態の仕様案

2026-10-02 UTC / 設計案・未実装  
対象HEAD: `88f5e3eea245166ee68ed4dc6c3f99c31e149228`、branch: `dot/cloud-cpu-setup`。確認開始時のアプリGitはclean。対象は現行template/JavaScript/backendと、統合済みDESIGN・Software VaultのW01〜W08。アプリソース、runtime、研究データ、既存試作は変更していない。

## 1 結論

**動詞が示す処理と、確認できた状態を一致させる。** 「手動」はコード付与と測定設定へ分け、「公開」は実際のVault保存へ改める。見出し、ボタン、完了通知は同じ実行状態から決める一方、計算・本体保存・Vault保存・研究者確認・通信の状態は別々に示す。

先に直すのは、failedを実行中と呼ぶ表示、再試行しないボタンの「再試行」、採用と実行を一度に進める「開始」、閲覧端末を示す「このPC」。見た目だけの書換えでは解決しない箇所を以下で明示した。25件は文言の対象箇所数であり、新規不具合数や改善効果の測定数ではない。

### 今回確認した重要な条件

- 現行のfailedに対する`allowed_actions`は空。画面の「失敗した処理を再試行」は実際には設定画面を開く場合がある。waitingでも理由と許可操作を読まなければ「再開できます」と約束できない
- 現行の手動測定は「開始」でdraft保存→試行→adopted保存→全件実行へ進む。明示採用やレビュー待ちは未実装。文言だけを「試す」に変えてはいけない
- 中止要求を送信中、要求を受け付けた状態、処理の中止完了は別。通信失敗は処理停止や未保存の証拠にならない
- 本体の固定ファイルを上書きしない契約・読取時hash照合はある。しかし定義の履歴不変性、実行時の採用版固定、試行の人による確認記録を保証する契約は未整備
- 個別AI見解などの実行入口はCSSで隠れている。案内文を変えるだけで「実行できます」とすることはできない
- 送信説明と保存先説明にも範囲の不足がある。AI見解のpayloadには役割・コード・重要フラグ等も入り、pipelineのVault保存は3先の管理表に加えてResearchVaultも扱う。文言を短くする際にこの内容を落とさない

参照: [設計入口](../../../../../DESIGN.md)、[設計契約](../ui-design-contract/00-Index.md) §3〜7、[実装計画](../ui-design-implementation-plan/00-Index.md) W01〜W08。

## 2 共通語彙

| 用語 | 利用者へ示す意味 | 避ける使い方 |
|---|---|---|
| 設定・コード付け | 分析設定、研究者が付けるコード、関連する記録を編集する場所 | 測定規則を選ぶ操作まで「手動」で一括する |
| 測定を設定 | 入力と計算規則を指定する。説明文を書くだけでは規則にならない | 「独自分析」「自由に測定」など、自然文から任意の計算を作るように見せる |
| 少数の発話で試す | 対象から定めた順序・件数を測定する | 代表性を検証していない試行を「サンプルで検証済み」とする |
| この定義を採用 | 使う測定内容を明示的に選び、採用状態を保存する | 計算開始、研究の妥当性確認、試行レビューの永続保証と同義にする |
| 全件で実行 | 表示した除外条件を適用した対象全体に実行する | 除外を含む元の全発話へ実行するように見せる |
| 算出済み | 値を計算できた | 値や解釈の正しさ、人の確認まで保証する「有効」「検証済み」 |
| 欠測 | 対象だったが値がない。理由を取得できれば添える | 0、未実行、対象外を一つの「なし」にする |
| 対象外 | 指定した条件によって集計から外した | 欠測と同数にまとめる |
| 保存済み結果 | 特定の実行で保存された入力・条件・結果 | 現在データを再集計した画面に「保存済み」と表示する |
| 現在のデータと差分あり | 保存時と現在の入力・分析条件が異なることを照合できた | 結果を消すべきだと読める「無効」、不明時の「最新版」 |
| 確認記録なし | 対象の確認記録がないことを確かめた | 人が一度も読んでいないと断定する「未確認」。読取失敗は「確認記録を確認できません」と分ける |
| Vaultに保存 | 設定された保存先へ書き出す | 「公開」「端末に保存」「全Vaultに同期」 |
| ダウンロード | 閲覧中の端末へファイルを取得する | Gurumoji実行環境への保存と同義にする |
| 接続先 | 選択した処理サービス・LLMの実際の宛先 | 遠隔ブラウザーから見た「このPC」「ローカル」の無条件使用 |

「版」は短い通常表示、「ID・hash・出力列・技術情報」は詳細へ置く。詳細を折りたたんでも、対象、単位、対象数、欠測数、保存先、実行するかどうかは主操作の近くに残す。既存の専門用語は詳細で保持するが、`pipeline`、`永続ゲート`、`binding`、`committed`を通常UIの説明へ移植しない。
