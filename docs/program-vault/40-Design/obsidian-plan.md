# Obsidian保存・分析登録の実装計画

2026-09-13更新：組み込み手法の固定保存・AI仕上げの変更記録・Vault生成は実装済みです。現行API・テーブル・登録契約は [[30-Data/analysis-storage-v1]] を参照してください。この文書は差分取り込み・外部手法等の後続計画も含みます。

会話の見解から根拠をたどり、異なる分析手法の結果と研究者の解釈を蓄積できる構成にする。保存先は「最新版を管理するDB」「再現・外部利用に使うCSV／JSON」「読む・つなぐ・考察するObsidian」に分ける。各データの正本は [[storage-policy]] で明示する。

## 到達する状態

- 会話ページから、文字起こしの対象版、話者、分析結果、根拠、研究メモへ移動できる。
- 分析手法ごとに、条件を変えた結果と過去の成功結果を保存できる。
- 表・グラフの元数値と、見解を生成した時点の原文を取り出せる。
- 未実装の手法も、外部ツールで作成したCSV／JSONと登録票から収録できる。
- Obsidianを閉じていてもアプリは通常どおり動作する。
- 研究データ用Vaultとプログラム資料用Vaultを独立して開ける。

## 既定方針

| 項目 | 提案する既定動作 |
| --- | --- |
| Vault数 | 研究用とプログラム資料用の2つ。入れ子にしない |
| 研究用の保存先 | `<MOJIOKOSI_DATA_DIR>/obsidian/ResearchVault`。現在の `data/obsidian/ResearchVault` に構成・登録ガイド・テンプレートを作成済み。保存先変更UIは今後実装 |
| プログラム資料 | リポジトリの `docs/program-vault`。今回、この計画と現状解説を作成済み |
| 自動書き出し | 初回に対象会話を選び登録した後、確定保存・分析成功に応じて更新キューへ追加 |
| 重い再分析・AI再生成 | Vault同期では実行しない。入力変更時は「更新が必要」にする |
| 過去結果 | 成功した登録結果を版付きで保持。同一入力・同一手法・同一条件は再利用 |
| 全発話のノート化 | 1発話1ファイルは既定にしない。版付き文字起こしページ内のブロックを根拠に使う |
| 語のノート化 | 頻出語を全件自動作成しない。研究者が保存した語・概念だけ独立ノートにする |
| 外部プラグイン | 必須にしない。Markdown・プロパティ・リンクで成立させる |
| Obsidian編集の取り込み | 確定：研究メモ・解釈・コード案を差分確認後に取り込む。本文・話者の編集はアプリで行う |
| 配布・バックアップ | Vault、結果ファイル、DBバックアップ、メディアの対象を分けて選べる |

ObsidianではVaultごとにリンクが解決されるため、両Vaultは独立したルートとする。[Obsidian公式：Vaultの保存方式](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data)

## 研究用Vaultの構成案

```text
ResearchVault/
  00-Home.md
  10-Projects/             研究目的・研究質問・対象会話への索引
  20-Conversations/        会話ごとの入口・最新版へのリンク
  25-Sources/              入力スナップショット別の発話ページ
  30-Speakers/             話者ID単位の表示用プロフィール
  40-Analyses/             会話ID/分析実行ID/ の結果ノート
  45-Methods/              分析手法の定義と版
  50-Codes/                アプリで確定したコードの表示用ノート
  60-ResearchNotes/        人が編集するメモ・解釈・コード案
  70-Concepts/             研究者が整理した概念・テーマ・関連付け
  80-Attachments/          閲覧用の図。音声の複製は選択時だけ
  90-Templates/            登録テンプレート
  95-Indexes/              手法別・話者別・更新待ち・要確認の索引
```

物理配置の詳細は [[storage-policy]]、命名・リンクは [[sync-contract]] に定める。研究用Vaultの中にSQLiteや秘密設定を置かない。

## 現在の準備状況

研究用の `data/obsidian/ResearchVault` と、プログラム資料用の `docs/program-vault` を独立したVaultとして作成済み。研究用には索引、16手法の登録ガイド、共通規約、記入用テンプレートを配置した。自動同期・差分取り込み・実データ移行は、以下の実装段階で行う。

## 実装段階

| 段階 | 実装内容 | この段階の完了条件 |
| --- | --- | --- |
| 0：契約と試行 | 設定、ID、schema、対象・除外ルール、既存DBバックアップ、書き出しプレビュー | 実データを変更せずファイル数・容量・対象を確認できる |
| 1：分析の固定保存 | 入力スナップショット、実行台帳、成果物manifest、全件JSON／CSV、最新結果ポインター | 同じ結果を再取得でき、異なる条件の結果を別々に保持できる |
| 2：研究用Vault | 会話・発話・手法・分析・コード・索引を生成、引用リンク、アプリへ戻るリンク、更新キュー | APIキーなしで1会話の見解から根拠・詳細結果までたどれる |
| 3：人の記録との連携 | 研究メモ・コード案の検出、構文検証、差分表示、選択取り込み、競合検出 | Obsidian上の追記を失わず、承認した案だけアプリへ反映できる |
| 4：手法の拡張 | 手法登録schema、アダプター、外部CSV／JSON結果の検証・登録 | サンプルの外部分析を、実行エンジンの追加なしで収録できる |
| 5：プログラム資料 | 現状資料を機能・API・保存契約・設計判断・テストへ拡充し、更新チェックを導入 | 機能→コード→テスト→設計判断のリンクを検証できる |
| 6：移行・運用 | 既存会話の選択一括登録、失敗再開、可搬パッケージ、復元、容量確認 | 既存出力・編集保存の回帰テストと移行／復元試験が通る |

段階5は研究データの同期に依存せず進められる。新しい統計手法の計算実装そのものは、段階4の「保存・登録対応」と区別して個別に計画する。

## アプリ側で追加する操作

1. 設定画面の「Obsidian保存」で研究用Vaultの場所を設定し、フォルダーの状態を確認する。
2. ライブラリで会話を選び「Obsidianに登録」。初回は含む情報、除外対象、予定ファイルと容量を表示する。
3. 分析画面に「今回の結果を保存」「過去の結果」「Obsidianで開く」「同期状態」を追加する。
4. KWICに「検索を研究ノートとして保存」を追加し、全一致結果と検索条件を固定保存する。
5. Obsidian側で人が作成したノートは「変更を確認」から読み込み、取り込む項目を選択する。
6. 「他の分析結果を登録」から手法・会話・入力版・CSV／JSONを指定する。

Obsidianを開く操作はURIを使う。引用の音声確認はGurumojiの会話・発話・入力版を指定したリンクで行う。アプリが稼働していない端末では原文と保存済み結果を読める状態を保つ。[Obsidian公式：URI](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)

## 主な実装先

既存 `app.py` にはAPIと保存後の通知を追加する。新しい責務は、提案する `analysis_store.py`（版・成果物）、`analysis_method_registry.py`（手法定義）、`obsidian_export.py`（描画）、`obsidian_sync.py`（書き込み・取り込み）へ分ける。現在の分析計算とExcel出力を再利用する。

## 受け入れ条件

- 会話、発話、話者、コードのIDを維持し、同名話者・同名会話でも混ざらない。
- 同じ入力を繰り返し登録しても重複せず、変更後は旧結果の引用が旧原文へ解決される。
- 形態素・係り受け・CSVはプレビュー上限に依存しない。1話者・空データ・除外発話・簡易解析も状態を明示する。
- 同じ文字列が複数回現れるKWICは、発話IDと文字位置で区別する。
- 各手法が [[method-rules]] の条件・結果・根拠・限界を保存する。
- 途中中止、ディスク容量不足、ファイルロック、アプリ再起動で成功済み結果と人のメモが失われない。
- Obsidianでの移動・改名・削除・重複ID・同時編集を検出し、勝手に上書き・復活させない。
- 生成中の本文・話者情報・条件・注釈変更を検出し、古い結果を最新として公開しない。
- Obsidian上の取り込みは許可した項目だけに限定し、元のノートを保持する。
- 研究用Vault、プログラム資料、配布パッケージに含める情報をそれぞれ検証できる。
- PCで保存・取り込み・音声確認、スマホでノート閲覧・内部リンク・対応するアプリURLを確認する。端末間の転送方法は別設定とする。
- 既存の分析・編集保存・出力・再取込・AI見解・ブラウザーテストを通す。

初期負荷試験は、1会話1万発話、保存済み会話100件、形態素100万行を目安に、ファイル数・容量・生成時間・メモリー使用量を記録する。時間の合否基準は実装開始時に測定する基準PCとデータ量で確定し、現時点では性能を保証しない。

## 確定した取り込み範囲と初回設定

2026-09-13の利用者の指定により、Obsidianから取り込む内容は研究メモ・解釈・コード案とし、差分確認後に選択した項目だけを反映する方式で確定した。文字起こし本文・話者情報はアプリの既存編集機能で更新する。元のMarkdownを保持し、取り込み時には入力版と最新revisionを照合する。

保存先は初回設定で指定する。既存Vaultを使う場合も、登録対象と書き出し先を設定してから同期を開始する。
