# GurumojiのUI設計をAIに依頼するための調査と実践テンプレート：8 アクセシビリティと日本語の受入条件

親索引・状態・確認版：[[40-Design/ui-design-research/2026-10-02/prompt-research]]。必要な本文だけを取得する。

## 8 アクセシビリティと日本語の受入条件

次はプロンプトに必要に応じて添える確認項目。すべてのWCAG適合条件を網羅する監査ではない。

### 8.1 標準に由来する条件

- 通常文字のコントラストは4.5:1、大きい文字は3:1がAAの基準。操作部品・重要な図形は該当する非テキストコントラスト条件を確認する
- 色だけで保存状態、AI提案、話者、エラーの意味を伝えない
- キーボードで操作でき、focusが見え、固定要素で完全に覆われない
- 対象の大きさはWCAG 2.2 AAの24×24 CSS pxまたは該当例外を確認する。44×44をすべてのAA要件として説明しない
- 390 pxで表示できるだけではreflow適合の確認にならない。320 CSS px相当も確認し、意味上2次元配置が必要な表等の例外は個別に扱う
- エラーや状態変化を理解できる名前、説明、必要なプログラム上の関係を持たせる

[W1](https://www.w3.org/TR/WCAG22/)、[W2](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)

自動アクセシビリティ検査は有用だが、全違反を検出できない。通常画面だけでなく、ダイアログ、エラー、開いたメニュー等の状態も検査対象にする。最後に手動のキーボード操作・読み上げ・拡大確認を残す。[P2](https://playwright.dev/docs/accessibility-testing)

### 8.2 Gurumoji向けの追加仮説と確認ケース

以下は本製品向けの実務提案で、WCAGの数値要件そのものではない。

- 日本語IMEの変換確定Enterで、意図せず保存や実行が起きない
- 短文だけでなく、長い発話、長い話者名、英数字・URL混在、欠測、該当なしを使う
- 発話・時刻・話者・版の関係が、狭い画面でも読み違えにくい
- 未保存の内容がある場合、画面移動と復帰の挙動が予測できる
- 保存中の再操作や連打で二重処理に見えない
- 長時間分析では実際に取得できる状態を表示し、推測の進捗率を作らない
- メッセージは「保存できませんでした。入力内容はこの画面に残っています」のように、実際に保証できる復旧情報だけを書く
- 元のデータが欠けた引用、音声のない結果、失敗したrunでも作業を再開できる
- 表をカードへ変換する場合は、比較軸と行の関係が失われていないか確認する
- reduced motion時に意味が失われず、演出が内容の読解や再生操作を妨げない

## 9 効果を比較するための小さな実験計画

この節は**未実施の計画**。ベンダーの宣伝文句より、自分のアプリでの再現性を確認するために使う。

### 9.1 比較する条件

|条件|与えるもの|検証する仮説|
|---|---|---|
|A|短い対象タスクのみ|現在の基準|
|B|A＋既存設計の役割・制約|文脈で一般的なUIへの逸脱が減るか|
|C|B＋版が分かる参照画像と注釈|視覚的な読み違いが減るか|
|D|C＋操作状態と受入ケース＋描画反復|完成したフローの割合が上がるか|

比較の初期値は、同じ1フローで各条件3回程度。これは統計的に確定できるサンプル数という意味ではなく、ばらつきと致命的な失敗を観察するための小規模試行である。費用上限を設定し、必要な契約やデータ送信許可が揃ってから実施する。

### 9.2 公平にする条件

- 同じモデルの正確なID、同じ推論設定、同じツール、同じ素材とベースcommitを使う
- 1回目の見た目と、同じ反復予算の後の結果を両方記録する
- 生成時間だけでなく、確認・修正時間、失敗、追加作業を数える
- 良い1回だけを選ばず、失敗も残す
- 採点時は条件名を隠し、可能なら複数人で確認する
- 模擬データだけを用い、実会話や研究対象者の情報を送信しない

### 9.3 判定基準の例

重大な契約違反やデータ誤表示は、美観点で相殺しない。まず必須条件を合否で判定し、その後に比較指標を見る。

必須条件:
- 現行API・URL・保存契約の破壊なし
- 合成データで指定フローが完了する
- 未実行を成功と表示しない
- キーボードによる主要フローが通る
- 指定画面幅で内容や主操作が欠けない

比較指標:
- 初回で理解できる状態表示
- 根拠から結果へ戻る際の文脈保持
- 長文の読みやすさと情報密度
- 既存画面との一貫性
- 必須条件を満たすまでの人の修正時間

評価者が付ける1〜5点は観察の整理に過ぎない。利用者の実際のタスク成功率や満足度を測った値として扱わない。
