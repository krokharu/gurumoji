### 互換性・残っている制約

- 比較保存APIは、集計応答の`input_fingerprints`を必須にした。欠落は400、現在の本文・分析条件・準備・話者台帳との版不一致は409。開きっぱなしの旧画面は再読み込みし、再集計して保存する。
- 人のノートに付けたタグは作成時点のまま保持する。古い全文を自動で`graph/history`へ付け替えない。現在の作業版は概要・状態ノートで確認する。テーマノート内に従来生成した関連欄は自動削除しない。
- 排他的作成には同一ファイルシステムのハードリンクを使う。非対応の保存先では上書きへ切り替えず、エラーで停止する。生成ノート一般のhash確認と置換の間の競合（OBS-04）は別課題として残る。
- 準備の更新待ち伝播は今後の変更から有効。すでに誤った状態で保存された過去履歴の一括補正、実Vaultの移行・削除は実施していない。
- 次のプログラム課題は、生成Vaultの失敗通知（OBS-18）と比較履歴・再試行（UX-33）、watcherの停止表示（OBS-09）。一覧性能（PERF-01）は計測後に扱う。

## A. 現在のアプリの目的

ローカルPCで会議やグループインタビューを文字起こし・話者分離する。研究者が確認した逐語録を正本として保存し、根拠となる発話にたどれる分析結果を固定保存して、Obsidianで読み・考察する研究ワークベンチである（詳細は [[10-Architecture/system-map]]）。

## B. 主要機能

Coreは次の5つ。それ以外は [[20-Modules/feature-inventory]] で Supporting／Optional に分類した。

1. 文字起こしと話者分離
2. 逐語録の確認・編集保存
3. 処理済みデータの一覧
4. 分析・可視化
5. 分析結果の固定保存

## 目標とする層構造（書き換えずに寄せる）

| 層 | 責務 | 寄せ先（既存） |
| --- | --- | --- |
| Core | 会話・発話・版・確認状態のルールと、正本の保存 | `app.py` の保存・編集トランザクション、`transcript_preparation.py` |
| Service | 文字起こしパイプライン、分析、AI仕上げ、議事録、比較 | `research_analysis`、`analysis_insights`、`transformer_analysis`、`ai_finishing`、（`app.py` から移す関数） |
| Data | SQLite台帳、固定成果物、出力ファイル | `analysis_store`（成果物）、`app.py` のDB関数 |
| External Integration | Obsidian（全Vault）、AI HTTP、FFmpeg、モデル | `vault_registry`・`obsidian_layout`・`obsidian_finishing`（Obsidian）、`ai_http_worker` |
| UI | 表示と入力。API呼び出しは `apiFetch` だけ | `static/*.js`、`templates/index.html` |

ルール：上の層は下の層を呼ぶが、逆方向には呼ばない。Obsidian層は正本（DB・成果物）を読むだけで、DBを変更するのは Core の保存関数を通す場合（仕上げの反映）だけにする。
