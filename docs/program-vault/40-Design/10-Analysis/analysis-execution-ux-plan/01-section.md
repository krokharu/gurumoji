# 分析実行UX統合・段階分析設計

## 実装状態

2026-09-21の後続設計：[[40-Design/10-Analysis/analysis-milestone-visualization-design/00-Index|analysis-milestone-visualization-design]]で、M0〜M7の厳密な段階ゲート、段階内並列、手入力のラベル・測定・尺度とカラム・手法選択、47成果物の処理・UI対応、統計ソフト/画像出力を具体化した。新規開発ではこちらの利用者指定を優先する。本ノートの実装済み範囲と現行説明は維持し、後続案の「段階内は逐次でもよい」「手動は既存手法の選択だけ」という範囲を拡張する。

- Phase 1〜2：実装済み（2026-09-20）。既存APIを再利用した統合実行パネル、自動／手動、詳細設定、6段階の実行中画面、分析チップ、バックグラウンド継続、中止、同一入力の結果再利用を追加。
- Phase 3〜5：未実装。永続pipeline、データ待ち解除後の差分再分析、ADR-118の4作業単位への全面統合は版付きの後続変更とする。

## 1. 目的

分析画面に分散している「再集計」「AIで見解を作成」「テーマ分析を実行」「発話分類を実行」などの入口を、利用者から見て一つの実行フローへまとめる。

ただし、すべてを無条件に一括実行することはしない。ローカルで安全に繰り返せる処理、外部送信や料金を伴う処理、研究者の設定・確認が必要な処理を区別し、次を実現する。

1. 主な実行入口を「分析を実行」の一つにする。
2. 「自動実行」と「手動実行」を、実装方式ではなく利用者の操作目的として分ける。
3. 詳細設定は実行パネル内に集約し、通常は推奨値だけを見せる。
4. 実行中は専用画面で、現在の処理、全体の段階、待機理由、進捗を表示する。
5. 先行処理の結果や追加データが必要な分析は、依存段階として待機させる。
6. 失敗・取消・再起動後も、完了済みの段階を失わず、必要な段階だけ再試行できるようにする。

本設計は [[40-Design/10-Analysis/core-handler-routing-reorganization-plan/02-topics/10-section#図7：多様な分析を探す・読む・比較するUI|分析ワークスペース案]] と ADR-118 を具体化する。保存状態・実行状態・結果状態を一つの状態値へ潰さない原則、固定済み成果物を上書きしない原則は維持する。

## 2. 現状と問題

現行画面では、分析対象を読み込むだけで作られる集計と、利用者が明示実行する処理が同じ長い画面に混在している。

| 現在の入口 | 実際の役割 | 問題 |
| --- | --- | --- |
| `再集計` | 現在の分析データを再取得 | 再実行なのか再読込なのか分かりにくい |
| `AIで見解を作成／再生成` | 外部またはローカルLLMによる下書き生成 | 料金・送信範囲を含むのに、他の分析と同じ画面内に単独配置される |
| `テーマ分析を実行／作り直す／割り当てる` | Transformer分析のモード別実行 | 同じ処理の入口がモードにより別名になる |
| `テンプレート＋Jev＋Transformerで判定` | 発話分類候補の一括生成 | 事前に必要な結果と外部送信の関係が見えにくい |
| `設定とコードを保存` | 手動設定保存と自動集計更新 | 保存と分析実行の境界が利用者に伝わりにくい |

一方、文脈検索、意味検索、結果のCSV取得、Obsidianへの保存は「分析計画の実行」ではない。これらまで統合ボタンへ入れると、検索・閲覧・公開と計算の境界が再び曖昧になるため、各結果内の操作として残す。
