# 分析実行UX統合・段階分析設計

## 実装状態

2026-09-21の後続設計：[[analysis-milestone-visualization-design]]で、M0〜M7の厳密な段階ゲート、段階内並列、手入力のラベル・測定・尺度とカラム・手法選択、47成果物の処理・UI対応、統計ソフト/画像出力を具体化した。新規開発ではこちらの利用者指定を優先する。本ノートの実装済み範囲と現行説明は維持し、後続案の「段階内は逐次でもよい」「手動は既存手法の選択だけ」という範囲を拡張する。

- Phase 1〜2：実装済み（2026-09-20）。既存APIを再利用した統合実行パネル、自動／手動、詳細設定、6段階の実行中画面、分析チップ、バックグラウンド継続、中止、同一入力の結果再利用を追加。
- Phase 3〜5：未実装。永続pipeline、データ待ち解除後の差分再分析、ADR-118の4作業単位への全面統合は版付きの後続変更とする。

## 1. 目的

分析画面に分散している「再集計」「AIで見解を作成」「テーマ分析を実行」「発話分類を実行」などの入口を、利用者から見て一つの実行フローへまとめる。

ただし、すべてを無条件に一括実行することはしない。ローカルで安全に繰り返せる処理、外部送信や料金を伴う処理、研究者の設定・確認が必要な処理を区別し、次を実現する。

1. 主な実行入口を「分析を実行」の一つにする。
2. 「自動実行」と「手動実行」を、実装方式ではなく利用者の操作目的として分ける。
3. 詳細設定は実行パネル内に集約し、通常は推奨値だけを見せる。
4. 実行中は専用画面で、現在の処理、全体の段階、待機理由、進捗を表示する。
5. 先行処理の結果や追加データが必要な分析は、依存段階として待機させる。
6. 失敗・取消・再起動後も、完了済みの段階を失わず、必要な段階だけ再試行できるようにする。

本設計は [[core-handler-routing-reorganization-plan#図7：多様な分析を探す・読む・比較するUI|分析ワークスペース案]] と ADR-118 を具体化する。保存状態・実行状態・結果状態を一つの状態値へ潰さない原則、固定済み成果物を上書きしない原則は維持する。

## 2. 現状と問題

現行画面では、分析対象を読み込むだけで作られる集計と、利用者が明示実行する処理が同じ長い画面に混在している。

| 現在の入口 | 実際の役割 | 問題 |
| --- | --- | --- |
| `再集計` | 現在の分析データを再取得 | 再実行なのか再読込なのか分かりにくい |
| `AIで見解を作成／再生成` | 外部またはローカルLLMによる下書き生成 | 料金・送信範囲を含むのに、他の分析と同じ画面内に単独配置される |
| `テーマ分析を実行／作り直す／割り当てる` | Transformer分析のモード別実行 | 同じ処理の入口がモードにより別名になる |
| `テンプレート＋Jev＋Transformerで判定` | 発話分類候補の一括生成 | 事前に必要な結果と外部送信の関係が見えにくい |
| `設定とコードを保存` | 手動設定保存と自動集計更新 | 保存と分析実行の境界が利用者に伝わりにくい |

一方、文脈検索、意味検索、結果のCSV取得、Obsidianへの保存は「分析計画の実行」ではない。これらまで統合ボタンへ入れると、検索・閲覧・公開と計算の境界が再び曖昧になるため、各結果内の操作として残す。

## 3. UXの基本方針

### 3.1 一つの入口、二つの実行方法

分析画面の主操作は次の二つだけにする。

- 主ボタン：`分析を実行`
- 補助操作：`詳細設定`

`分析を実行`を押すと実行パネルを開き、最初に実行方法を選ぶ。

| 実行方法 | 利用者の意図 | 既定の挙動 |
| --- | --- | --- |
| 自動実行 | 推奨される順序で必要な分析を進めたい | 入力を検査し、安全なローカル処理から開始。依存データが揃えば次段階へ進む |
| 手動実行 | 手法、範囲、モデル、条件、再実行箇所を選びたい | 選択した処理と必須依存だけを計画し、実行前に差分を確認する |

「自動実行」は無確認の外部送信を意味しない。クラウドAI、Jev、料金が発生し得る処理は既定でオフにし、送信対象、provider、モデル、上限を確認して有効にした場合だけ計画へ入れる。既存の「文字起こし」「AIで数値化」「統計を実行」を費用上分ける ADR-111 の意図を維持する。

### 3.2 結果カードから直接実行しない

結果カード上の複数の実行ボタンは段階的に廃止する。カードのメニューに `この分析を再実行` を置く場合も、直ちにAPIを呼ばず、対象手法が選択された共通実行パネルを開く。

検索、根拠確認、表示切替、ダウンロードは実行ではないため、各カード内に残す。

### 3.3 通常設定と詳細設定

通常表示では次だけを見せる。

- 分析対象と本文版
- 自動／手動
- 実行予定の段階と件数
- ローカル／外部送信の区別
- 推定時間、推定使用量、上限。不明な場合は `不明`
- 実行できない項目と、その理由

`詳細設定`では次を段階別に編集できるようにする。

- 対象範囲、除外話者、除外発話、分析単位
- 手法と手法固有パラメーター
- Transformerのテーマ数、最小発話数、手動テーマ
- AI／Jevの利用有無、provider、model、送信方針、token・回数上限
- 完了済み結果を再利用するか、新しいrunとして再分析するか
- 成果物とVault公開の有無

設定変更が結果の意味・単位・尺度を変える場合は新しい計画版とする。実行開始後の計画へ画面上の設定変更を混入させない。

## 4. 画面構成

### 4.1 分析画面のヘッダー

```text
┌ 分析・可視化 ──────────────────────────────────────┐
│ 対象: インタビューA  本文12版  分析設定4版          │
│ 状態: 基礎分析 完了 / 追加分析 2件更新待ち          │
│                                      [詳細設定] [分析を実行] │
└────────────────────────────────────────────────────┘
```

実行中は主ボタンを `実行状況を見る` に変える。別画面へ移動した場合は上部バーに `分析中 2/5` のチップを残し、押すと実行中画面へ戻す。

### 4.2 実行パネル

```text
┌ 分析を実行 ────────────────────────────────────────┐
│ (●) 自動実行   ( ) 手動実行                         │
│                                                      │
│ 実行予定                                              │
│ ✓ 入力と設定を確認                                    │
│ 1 基礎集計・言語解析               ローカル           │
│ 2 Transformerテーマ分析            ローカル           │
│ 3 発話分類                         外部送信 OFF        │
│ 4 AI見解                           外部送信 OFF        │
│                                                      │
│ 推定時間: 約8分 / 外部送信: なし / 推定料金: 0円      │
│ [詳細設定を開く]                    [キャンセル] [開始] │
└──────────────────────────────────────────────────────┘
```

手動実行では段階・手法をチェック式で選ぶ。ただし、依存する先行段階は自動で追加し、`必要なため追加`と表示する。依存を外したい場合は、利用可能な保存済みrunを選ぶか、後続処理を外す。

### 4.3 実行中画面

実行開始後は専用の実行中画面へ遷移する。目標URLは `#/analysis/<item-id>/runs/<pipeline-request-id>` とし、具体構文はルーター実装時に既存URL互換を確認して確定する。

```text
┌ 分析を実行しています                    全体 42% ┐
│ インタビューA / 自動実行 / 開始 10:32            │
├──────────────────────────────────────────────────┤
│  ○──●──○──○──○                                   │
│ 準備  基礎  テーマ  分類  見解                    │
│        ╰─ 言葉の区切りと係り受けを解析中          │
│                                                   │
│       ◌ 形態素を解析しています                    │
│       12,430 / 28,100トークン相当                 │
│                                                   │
│ 次: 統計集計 → Transformerテーマ分析              │
│ [詳細ログ] [バックグラウンドで続ける] [中止]      │
└──────────────────────────────────────────────────┘
```

表示項目は次のとおり。

- 全体進捗：完了した段階の重みと現在段階の進捗。重みが不明な処理では段階数を使い、偽の秒単位予測を出さない。
- 現在の処理：利用者の言葉で表示し、関数名や生のモデル応答を出さない。
- 段階一覧：`完了／実行中／待機／確認待ち／失敗／取消／実行不可`をアイコンと文字で併記する。
- 待機理由：`テーマ分析の結果を待っています`、`研究者によるテーマ定義が2件必要です`など、次の行動が分かる文にする。
- 使用量：外部AIの要求回数・token、実行時間。費用換算できない場合は数値を推測しない。
- 詳細ログ：初期状態は閉じる。時刻、段階、再試行、警告を表示し、秘密情報や本文全体は含めない。

アニメーションは、現在の段階カード内で円弧または点が穏やかに移動する一種類に統一する。正常完了した項目は動かさない。`prefers-reduced-motion: reduce`ではアニメーションを停止し、状態文と進捗バーだけで同じ情報を伝える。

### 4.4 完了・部分完了画面

完了後は `結果を見る`を主操作にする。すべてを成功扱いにまとめず、次を分ける。

- 完了：選択した段階が保存まで完了
- 一部完了：独立した段階は完了したが、一部が失敗または実行不可
- 確認待ち：データや研究者判断を追加すれば続行可能
- 中断：アプリ終了等で実行継続を確認できない

一部完了では完了済み結果を表示し、`失敗した段階だけ再試行`、`設定を変更して新しく実行`、`ここまでの結果を見る`を提示する。

## 5. 分析の段階

段階番号は利用者に順序を伝えるための表示であり、すべての分析が必ず直列になることを意味しない。独立した処理は同じ段階内で並行実行できるが、初期実装では競合と負荷を避けるため逐次実行でもよい。

| 段階 | 名称 | 主な処理 | 完了条件 | 次へ進めない例 |
| --- | --- | --- | --- | --- |
| 0 | 準備・入力確認 | 本文版、発話ID、話者、除外、分析設定、モデル利用可否を固定 | 固定した計画と入力fingerprintを保存 | 未保存の編集、空本文、設定不足、本文版競合 |
| 1 | 基礎分析 | 発話量、時間推移、語彙、形態素、係り受け、記述統計、ローカル見解 | 手法ごとの結果状態と警告を保存 | 解析器が利用不可、必要件数不足 |
| 2 | 構造化・特徴抽出 | Transformerテーマ、意味ベクトル、選択されたAI数値化・分類用の特徴 | 後続が参照できる固定artifactと行IDを保存 | モデル未取得、テーマ定義不足、外部送信未許可 |
| 3 | 依存分析 | 発話分類、クロス集計、群比較、親結果を入力にする追加分析 | 親run・artifact・hashとの依存を記録して保存 | 親段階失敗、尺度・キー不一致、必要列不足 |
| 4 | 解釈支援・検証 | AI見解、反例・少数意見、手法前提、根拠照合、研究者の確認待ち | 主張と根拠ID、限界、確認状態を保存 | 研究質問不足、専門家ゲート不適合、根拠不成立 |
| 5 | 確定・公開 | 固定JSON／表、閲覧用出力、Vault公開 | AnalysisStoreへの確定後に段階完了 | 保存失敗、Vault競合。Vault失敗は分析計算の失敗と分ける |

### 5.1 データ待ちと再分析

後からデータが揃う処理は、失敗ではなく `確認待ち`または`待機`にする。

例：

- 事前アンケートが未取込 → 群比較は待機。基礎分析は完了として保持。
- Transformer結果が未完了 → それを使う発話分類だけ待機。
- 手動テーマが1件 → 手動割当は確認待ち。自動テーマ分析は選択可能。
- 研究質問が空欄 → AI見解は確認待ち。ローカル集計は実行可能。
- 本文・話者・設定が更新 → 過去runは保持したまま `更新が必要`とし、新しい計画で必要段階を再分析。

待機解除時に全分析をやり直さず、固定済み親結果の再利用条件を検証したうえで、その段階以降だけを新しい試行として実行する。現在版へ黙って差し替えない。

## 6. 実行状態と結果状態

画面では分かりやすくまとめて見せるが、内部では次を別軸で保持する。

| 軸 | 例 | 正本・扱い |
| --- | --- | --- |
| 計画要求 | `draft / accepted / running / completed / cancelled` | 提案済み `analysis_pipeline_requests` |
| 段階の試行 | `waiting / ready / running / completed / failed / cancelled / interrupted / blocked` | 提案済み `analysis_step_attempts` |
| 分析結果 | `not_run / completed / empty / unavailable / fallback / partial / stale` | 手法結果と固定run |
| 保存・公開 | 保存中、保存済み、Vault競合、再公開待ち | AnalysisStore、保留パッケージ、Vault状態 |

`completed`は結果runの保存確定後とする。Vault公開失敗、結果の`partial`、現在版から見た`stale`を、段階実行の失敗と混同しない。

## 7. 自動実行の規則

自動実行の既定計画は次の順で作る。

1. 入力・設定の未保存と版競合を確認する。
2. 完了済みで現行入力に一致する結果は再利用候補にする。
3. ローカル・決定的・無料の基礎分析を選ぶ。
4. ローカルモデルの準備状況を確認し、利用可能なら構造化処理を選ぶ。
5. 外部送信、費用、研究者判断を伴う処理は、事前に利用者が有効化したものだけ選ぶ。
6. 親結果、必要列、件数、尺度、手法前提が揃った後続だけ実行可能にする。
7. 新しい概念、尺度、コードブックの採用が必要なら、実行せず確認待ちにする。

自動実行の設定は、少なくとも次の3プリセットから始める。

- `ローカルのみ（推奨）`：段階0〜3のうち外部送信なしで実行可能なもの。
- `AI支援を含む`：許可したprovider・上限の範囲で段階4まで含める。
- `更新が必要な分析のみ`：現行入力で`stale`または未実行の段階だけを計画する。

常時監視による無操作の自動再実行は初期対象外とする。本文保存直後に高コスト処理が勝手に始まらないよう、最初は利用者が `分析を実行`を押した後の計画内だけを自動進行させる。

## 8. 手動実行の規則

手動実行では「手法名の一覧」だけでなく、目的から選べるようにする。

- 会話全体を把握する
- 発言のテーマを整理する
- 発話を分類・数値化する
- 話者や群を比較する
- AIで見解の下書きを作る
- 保存済み結果から追加分析する

目的を選ぶと候補手法を提示し、利用不可の手法も不足条件を添えて表示する。詳細設定では手法を直接選べる。選択結果は実行前の計画一覧に戻り、そこで対象・依存・外部送信を最終確認する。

## 9. API・保存への影響

### 9.1 初期段階で再利用するもの

- 現在の分析取得・保存API
- AI見解とTransformerの開始・状態取得・取消API
- 発話分類API
- 分析履歴・成果物・Vault再試行API
- `request_id`、`source_revision`、`analysis_revision`、fingerprintによる競合・重複防止
- 現在の`AnalysisStore`と固定成果物

### 9.2 段階実行で追加するもの

[[core-handler-routing-reorganization-plan#段階実行の状態と再開（FLOW-1〜2で追加）|既存の提案]]どおり、`analysis_pipeline_requests`と`analysis_step_attempts`を版付き拡張として追加する。既存の文字起こしジョブや`analysis_pending_packages`へ統合しない。

想定する操作APIは次のとおり。URLとpayloadは実装時に既存Routing規約へ合わせて確定する。

| 操作 | 目的 |
| --- | --- |
| 計画プレビュー | 自動／手動設定から、段階、依存、再利用、送信、見積り、実行不可理由を返す。副作用なし |
| 計画受付 | 固定計画と入力を保存し、同じ`request_id`の二重受付を防ぐ |
| 実行状態取得 | 計画、各段階、使用量、警告、結果runを返す。取得だけで再実行しない |
| 取消要求 | 未開始段階を取消し、実行中段階へ取消要求を伝える |
| 段階再試行 | 失敗・中断段階に新しい試行番号を作り、完了済み親結果を検証して再利用する |
| 明示再開 | 再起動後の`interrupted`を、入力・方針・残予算確認後に再開する |

## 10. 導入プラン

### Phase 0：実行分類と表示文言を固定

現行の操作を「計画実行」「検索・閲覧」「保存・公開」に分類し、統合対象を確定する。各既存APIについて、同期／非同期、取消可否、外部送信、料金、依存、保存タイミングを一覧化する。

完了条件：現在の実行入口がすべて分類され、統合後の移動先が決まっている。

### Phase 1：入口と実行パネルを統合

分析ヘッダーへ `分析を実行`と`詳細設定`を追加する。自動／手動、推奨計画、外部送信の確認を実装し、既存APIへ振り分ける。結果カードの旧ボタンは共通パネルを開く動作へ変える。

この段階では永続pipelineを新設せず、既存状態APIをまとめて見せる。同期APIは不確定進捗として表示する。

完了条件：分析を開始する主入口が一つになり、旧ボタンからも同じ確認画面へ到達する。

### Phase 2：実行中画面を作る

専用URL、段階ステッパー、現在処理、アニメーション、使用量、取消、バックグラウンド表示を追加する。AI見解とTransformerの既存進捗を同じ表示モデルへ変換し、同期処理は開始・完了・失敗を表示する。

完了条件：画面移動後も対象と実行状態を取り違えず、再読み込み時に既存の保存済み状態へ戻れる。

### Phase 3：段階実行を永続化

FLOW-1〜2の版付きDB拡張としてpipeline要求と段階試行を保存する。入力固定、依存DAG、二重受付防止、取消、`interrupted`、完了runとの結び直しを実装する。

完了条件：アプリ再起動、保存直後の停止、親失敗、独立枝の完了、取消競合をテストできる。

### Phase 4：データ待ちと差分再分析

必要列・親run・研究質問・手動テーマ・アンケート等のreadinessを段階ごとに評価し、待機理由と解除条件を表示する。データ追加後は全件再実行ではなく、影響された段階から新しい試行を作る。

完了条件：不足データがある処理だけ待機し、独立した分析結果を保持したまま続行できる。

### Phase 5：旧入口を廃止して分析ワークスペースへ統合

ADR-118の `結果を見る／比較する／分析を組む／データ・出力`へ接続する。新導線で既存結果、再実行、比較、保存、根拠確認に到達できることを確認してから、旧の `自動分析／設定・手動分析／手法別`切替と直接実行ボタンを外す。

完了条件：新旧を二重描画せず、既存URL・根拠リンク・保存履歴・成果物取得を維持する。

## 11. 受け入れ条件

### 操作

- 初見の利用者が、分析画面の主ボタン一つから自動実行を開始できる。
- 手動実行では対象、手法、詳細条件、外部送信、上限を実行前に確認できる。
- 結果カード内の再実行操作は、確認なしに処理を開始しない。
- 検索・表示・ダウンロードを分析の再実行と誤認しない。

### 進捗・状態

- 実行中画面だけで「現在何をしているか」「全体のどこか」「次は何か」が分かる。
- 待機・確認待ち・実行不可・失敗・取消・中断を区別する。
- 進捗率を算出できない処理は、偽の割合や残り時間を表示しない。
- motion低減設定でも同じ状態情報を読める。

### データ・再現性

- 実行開始後に画面の設定を変えても、受付済み計画の入力・設定は変わらない。
- 本文版・分析設定版・親artifactが変わったとき、旧結果を保持して`stale`を表示する。
- 失敗段階の再試行で、完了済みの独立段階を再計算しない。
- 保存再試行とVault再公開でAI・Transformerを再実行しない。
- クラウドAIとJevは、送信方針を明示確認しない限り自動計画へ入らない。

### 回帰確認

- AI見解、Transformer、発話分類、分析設定保存、比較、履歴、成果物、Vault再試行の既存操作が新導線から到達できる。
- 未保存の分析設定・準備記録を保護する。
- 連続実行、逆順応答、対象変更、別画面への移動で表示対象が入れ替わらない。
- スマートフォンでは段階一覧を縦表示し、横スクロールなしで主操作へ到達できる。

## 12. 初期実装の範囲

最初の実装単位は Phase 1〜2 とする。対象は単一インタビューの既存4処理（基礎再集計、Transformer、発話分類、AI見解）に限定し、共通実行パネルと実行中画面へ接続する。

永続pipeline、後続分析DAG、疑似人格の相談、常時監視による自動再実行、複数会話をまたぐ一括実行は同時に実装しない。Phase 1〜2で操作モデルを検証してから、Phase 3以降の保存契約を版付きで追加する。
