# 動画処理・確認画面 UI/UX 改善設計図

## 1. 背景と課題

利用者より「動画処理画面のUIが非常に見づらい」との指摘があり、調査の結果、以下の8つの課題（UX-35〜UX-42、詳細は [[40-Design/ui-ux-issues]]）が特定された。

1. **UX-35**: 動画プレビュー領域が横幅300〜380pxに固定され、スライド文字や表情が小さすぎて判読不能。
2. **UX-36**: 全体がライトテーマの中で動画コンテナのみ突如暗色（`#17201c`）で、視線移動時のコントラスト差による疲労が大きい。
3. **UX-37**: 発話（セグメント）1件ごとの縦幅が約250pxと巨大で、1画面に2〜3件しか入らず会話の文脈が見通せない。
4. **UX-38**: 上部のアウトライン・リザルト情報が巨大で、ファーストビューで動画プレイヤーとテキストが見切れる。
5. **UX-39**: 動画再生位置と発話リストのリアルタイム連動（自動追従・ハイライト）が弱く、現在位置を見失いやすい。
6. **UX-40**: 処理中画面（Progress Card）のアニメーション・システム計器・点滅ランプが過剰で視覚的ノイズが大きい。
7. **UX-41**: 設定項目が5つのアコーディオンに埋もれ、フォントサイズが極小（約11px）で漢字が潰れて可読性が低い。
8. **UX-42**: カードと背景の境界線・明度差が小さく、視覚的階層（ビジュアルヒエラルキー）が曖昧。

---

## 2. 改善方針と設計図

### 方針A: 動画確認・編集画面（`#/data/<id>`）の再設計（UX-35, 36, 37, 38, 39）

#### A-1. 動画プレビュー領域の拡大と配色統一（UX-35, UX-36）
- **レイアウト変更**:
  - `style.css` の `.transcript-layout` のカラム比率を見直し、動画サイドバーの幅を `minmax(380px, 520px)` または画面幅に応じた柔軟な比率に拡大する。
  - 横長（16:9）動画でも横幅450px以上・高さ約250px以上を確保し、プレゼンテーションのスライドや参加者の表情が明瞭に確認できるようにする。
- **配色統一**:
  - `.media-review` の `background: #17201c; color: white;` を廃止し、アプリの基調（`--card`, `--line`）に合わせたライトカードデザインに統一。
  - 映像プレイヤー本体（`<video>`）自体は黒背景を保ちつつ、コンテナやコントロール部のトーンを画面全体と調和させることで、目への刺激・コントラスト疲労を緩和する。

#### A-2. 発話リストの「チャット/字幕タイムライン化」（UX-37）
- **通常表示と編集モードの分離**:
  - **通常時**: 発話行（`.segment`）には「開始-終了時刻」「話者バッジ」「本文テキスト」のみをすっきりと表示する。
    - 1行の縦幅を約50〜70pxに圧縮し、1画面に **8〜12発話** が一覧できるようにする。
    - 会話全体の文脈や前後のやり取りが一目で把握できるようになり、校正効率が大幅に向上する。
  - **編集時（クリックまたはフォーカス時）**:
    - クリックされた発話のみスムーズに展開し、秒数入力・話者変更・感情選択・AIレビューなどの詳細入力欄を表示する。

#### A-3. 動画再生と発話のリアルタイム連動・オートスクロール（UX-39）
- **追従機能の強化**:
  - `mediaPlayer` の `timeupdate` イベントを監視し、現在の再生時刻に一致する発話に `.playing`（アクティブ強調スタイル）を付与する。
  - 再生に合わせて発話リストが自動でスムーズスクロールし、ユーザーが手動でスクロールせずとも常に再生中の発話が画面中央に保たれる「オートスクロール追従モード」（トグルでON/OFF可能）を導入する。

#### A-4. ファーストビューの適正化（UX-38）
- **上部メタ情報の整理**:
  - `<details id="session-outline">` は初期状態で閉じた状態（または1行のサマリーバー）とし、不要な縦幅占有を排除する。
  - 画面を開いた瞬間に「動画プレイヤー」と「発話リストの先頭」がファーストビューにきれいに収まる配置にする。

---

### 方針B: 新規文字起こし・処理中画面（`#/new`）の再設計（UX-40, 41, 42）

#### B-1. 処理中画面（Progress Card）のスマート化・視覚的ノイズ排除（UX-40）
- **メイン表示の厳選**:
  - 処理中画面の中央には「大きな進捗率（％）」「現在の処理ステージ名（例：話者を分離しています…）」「全体のプログレスバー」のみを美しく清潔に配置する。
- **計器類・ログの格納**:
  - 上下に激しく揺れる波形アニメーションや点滅ライトを抑え、CPU/GPU/メモリメーター、ディスクI/Oランプ、AIトークン詳細、詳細ログは「詳細システム情報を表示」アコーディオン内に格納する。
  - ユーザーが必要な時だけ展開して確認できるようにし、日常利用時の視覚的疲労・圧迫感をなくす。

#### B-2. タイポグラフィとコントラストの適正化（UX-41, UX-42）
- **文字サイズの引き上げ**:
  - 最小文字サイズ `--text-min` を `.7rem`（約11.2px）から `.8rem`（約12.8px）〜`.85rem`（約13.6px）へ引き上げ、設定画面の日本語テキスト・漢字の潰れを解消する。
- **カード輪郭の明瞭化**:
  - カード（`.workspace-card`, `.progress-card`, `.segment`）のボーダー色やドロップシャドウを調整し、背景との境界をはっきりさせて視覚的なメリハリ（ビジュアルヒエラルキー）を与える。

## 3. 実装計画と影響範囲

### 変更対象ファイル
- `src/gurumoji/templates/index.html`: アウトラインの初期開閉状態の変更、プログレスカードの詳細折りたたみ化
- `src/gurumoji/static/style.css`: レイアウト比率、配色、セグメントの通常/編集時スタイル、タイポグラフィ、コントラスト
- `src/gurumoji/static/app.js`: セグメントの展開/折りたたみロジック、`timeupdate`連動オートスクロール

### 互換性と安全性
- **要素IDの完全維持**: 既存の要素ID（`#media-player-host`, `#segment-editor`, `#progress-bar` 等）は一切変更せず、既存のテスト（`test_ui_defaults.py`, `test_browser_e2e.py` 等）を維持する。
- **API・DBの不変**: バックエンドAPIおよびデータベーススキーマは一切変更しない。

## 5. 追加改善記録（2026-09-22 UX-43〜45）

第1フェーズの改善後、「テキストがtextarea内に1行表示されるため文章として読みにくい」「視線移動が激しい」との追加フィードバックを受け、以下のさらなる改善（UX-43〜UX-45）を実施した。

- **UX-43 「読むモード」と「編集モード」の完全分離**: 通常時（折りたたみ時）は `textarea` を非表示にし、専用のプレビュー要素でテキスト全文を自然に折り返し表示するよう変更した。
- **UX-44 チャット風レイアウトの導入**: メタ情報（時間・話者名）とテキストを縦に並べるフレックスレイアウトに変更し、横方向への視線移動負担を減らした。
- **UX-45 再生中ハイライトの強化**: 再生中のセグメントの左端に太いオレンジ色のボーダーを表示し、「今どこを読んでいるか」を直感的に把握しやすくした。
- **起動エラーの修正**: 初期化処理において `requestedView` が未定義の状態で参照されることによるJavaScriptエラーを修正し、起動・ローディング画面の停止問題を解決した。
