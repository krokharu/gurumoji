CORE / HANDLER

全文を段階的に分析

Coreが次の問いを選び、Handlerが発注・保存・停止を管理します。全文を分割して読み取り、観察・主張・問いを記録します。

Core・会話解釈・独立検証・批判者に適用。Handlerはアプリの処理、数量・統計はPython集計です。

どこで止めるか

すべてのモードに適用する安全上限

無上限にできるのは時間と回数だけです。上限・利用者停止は批判レビューより優先。停止不能な呼出しの完了待ちや費用が残る場合があります。

完了後の保存先

正常終了した分析は、入力・全量台帳・初期版・結果を固定成果物としてアプリに保存します。

対象はInput／Orchestrator／Visualization／Researchの4つ一式です。Researchには保存時点の発話本文も複製します。生成ノートは既存の履歴保護経路で更新し、手動編集の履歴と削除済みノートの保護を維持します。研究者所有ノートの本文・タグ・別名は変更しません。停止・取消・失敗した分析は自動出力しません。

既定はOFFです。この選択は今回開始する実行だけに保存され、過去の実行の再開・再試行には追加されません。

新規実行では既定ONです。Orchestrator Vaultに状態・短い判断・データ参照を保存します。JSON・CSV・DBは正本に保持し、上の4 Vault出力とは別に管理します。

探索的なAI下書きです。実行成功・検証済みの表示は、研究上の結論の確定を意味しません。画面の描画・状態取得にAIは使いません。

    保存済み表から、局所集計 CODE

    現在の実行に固定された、利用許可のある保存表を選びます。選択肢の取得は計算しません。実行はアプリのローカルコード処理です。

    対象集合と計算の分母は結果で確認できます。欠測・未処理・不明・除外は、観測されたゼロと区別して保存されます。行の抽出は対象集合そのものの変更ではありません。

    保存した根拠をつなぎ、局所分析 CODE

    採用テーマの根拠、単位表、質的比較を選びます。複数会話では完全な発話表を2〜16件選び、確認後の送信時に対象集合を固定します。表示の取得は計算しません。入力・対象集合・依存する処理を確認してから、ローカルのコード処理を明示的に実行します。

    今回使う保存参照と役割

    計算の分母・欠測・未処理・不明・除外は保存結果で確認します。観測されたゼロとは別です。質的関係の提案と研究者の採否、同じ親根拠の再読と独立検証を区別します。

      会話内の話者と参加者の対応を研究者が記録する

      選択した固定対象の各会話・話者について、同じ人物として集約する参加者を明示します。複数会話でも同じ人物は研究者が明示してください。保存済み単位表の独立した確認記録として、この対応表そのものを保存します。既存のTA自由記述メモから対応を推測しません。訂正すると派生した入力が古くなるため、保存根拠を再取得して接続を確認してください。
